---
title: "Klanten"
description: "Maak de persoon of het bedrijf aan dat capabilities, accounts en transfers bezit."
---

Maak de klant aan voordat je een pay-in, uitbetaling of uitgegeven bankrekening bouwt. Capabilities, accounts en transfers zijn scoped aan die klant. Gebruik `externalId` als de stabiele mapping naar het bijbehorende record in jouw systeem.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Individuele klanten

Een individu vereist alleen `type`. Voeg profielvelden toe die je al kent en voeg er alleen meer toe wanneer de huidige capability of taak ze nodig heeft.

Maak de klant aan met [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Bewaar de geretourneerde `data.id` als `CUSTOMER_ID`. Zie [Individuele onboarding](/nl/knowledge-base/individual-onboarding/overview) voor beleidscontext.

## Zakelijke klanten

Een bedrijf vereist `business.legalName`. Maak het bedrijf aan met dezelfde operation:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Bewaar de geretourneerde `data.id` als `CUSTOMER_ID`. Zie [Zakelijke onboarding](/nl/knowledge-base/business-onboarding/overview) voor beleids- en documentcontext.

## Voeg zakelijke related parties toe

Voeg bestuurders, eigenaren en andere zakelijke deelnemers toe wanneer ze bekend of gevraagd zijn. Dit voorbeeld maakt een bestuurder aan met [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Bewaar de geretourneerde `data.id` als `RELATED_PARTY_ID`.

## Lees readiness uit capabilities

Een klant heeft geen verificatie- of readiness-status in de API. Lees de klant met [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) voor huidige profieldata en gebruik vervolgens capabilities en hun `openTaskIds` om te bepalen wat de klant vervolgens kan doen.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Ga vervolgens naar [Capabilities en tasks](/nl/integration/onboarding/capabilities-and-requirements) om de gewenste productuitkomst te ontdekken en te activeren.
