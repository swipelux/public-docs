Sandbox gebruikt dezelfde API-host als productie. Een sandbox API-key selecteert de testomgeving, waar helpers uitkomsten simuleren zonder echt geld te verplaatsen.

Houd de key op je backend. Sandbox-helpers vervangen geen productiecompliance of -onboarding.

Gebruik [Fouten en nieuwe pogingen](/nl/integration/errors) om te testen hoe je integratie omgaat met validatie-, state- en retryable platformfouten die sandbox-operations retourneren.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

## Test capability-readiness

Nadat je een capability hebt aangevraagd, stel je de sandbox-status in met [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"status":"ready"}'
```

Refetch de capability na gebruik van de helper. Behandel de huidige `status` en `openTaskIds` als het resultaat dat je product moet verwerken.

## Test een open taak

Maak een sandbox-taak met [`POST /v3/sandbox/tasks`](/api-reference/sandbox/post-v3-sandbox-tasks). Koppel deze aan de resource waarvan je de workflow test en gebruik `items` om te beschrijven wat de klant moet indienen. Deze handleiding toont capability- en transferworkflows; de API Reference definieert de customer-scope en het volledige requestschema.

Gebruik een `explanation`-item voor een tekstantwoord en een `document`-item voor een upload. Nieuwe `profile`-items vereisen ook `profilePointer`, een JSON Pointer naar het klantveld. Zie [Sandbox-taak aanmaken](/api-reference/sandbox/post-v3-sandbox-tasks) voor de overige itemtypen en velden.

Maak voor het transfervoorbeeld eerst een sandbox-transfer via een [pay-in](/nl/integration/receive-funds)- of [payout](/nl/integration/send-funds)-flow en exporteer daarna de geretourneerde `data.id`:

```bash
export TRANSFER_ID='tr_replace_with_your_transfer_id'
```

<Tabs>
  <Tab title="Capability + toelichting">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "capability",
    "customerId": "${CUSTOMER_ID}",
    "capabilityId": "${CAPABILITY_ID}"
  },
  "items": [
    {
      "type": "explanation",
      "request": "Explain the source of funds."
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="Transfer RFI + document">

Scope de taak op de transfer die wordt beoordeeld en vraag een document op met `constraints` die de geaccepteerde typen, formaten en leeftijd beperken.

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "transfer",
    "customerId": "${CUSTOMER_ID}",
    "transferId": "${TRANSFER_ID}"
  },
  "category": "transaction_rfi",
  "items": [
    {
      "type": "document",
      "request": "Upload a bank statement showing the source of funds for this transfer.",
      "constraints": {
        "acceptedDocumentTypes": ["bank_statement"],
        "acceptedFormats": ["pdf", "jpeg"],
        "maxAgeDays": 90
      }
    }
  ]
}
JSON
```

Het voorbeeld beperkt het geaccepteerde documenttype, de indeling en de ouderdom. Zie [Sandbox-taak aanmaken](/api-reference/sandbox/post-v3-sandbox-tasks) voor alle ondersteunde documentbeperkingen.

  </Tab>
</Tabs>

Bewaar `data.id` als `TASK_ID`, `data.revision` als `TASK_REVISION` en de huidige `data.requirements[0].id` als `REQUIREMENT_ID`. Laat het antwoord bij een aanroep van [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) overeenkomen met het item dat je hebt gemaakt:

<Tabs>
  <Tab title="Antwoord met toelichting">

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "text",
        "value": "Sandbox requirement completed."
      }
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="Documentantwoord">

Upload een passend bestand met [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents), bewaar de geretourneerde `data.id` als `DOCUMENT_ID` en dien deze in als documentantwoord:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-document-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "document",
        "documentIds": ["${DOCUMENT_ID}"]
      }
    }
  ]
}
JSON
```

  </Tab>
</Tabs>

Accepteer of weiger vervolgens de huidige submission met [`POST /v3/sandbox/tasks/{taskId}/review`](/api-reference/sandbox/post-v3-sandbox-tasks-by-task-id-review):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks/${TASK_ID}/review" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"outcome":"accepted"}'
```

Gebruik [Capabilities en tasks](/nl/integration/onboarding/capabilities-and-requirements) voor het productie-patroon voor taakvoltooiing.

## Financier een sandbox-wallet

Crediteer een uitgegeven wallet met [`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${ACCOUNT_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"amount":"250.00","currency":"USDC"}'
```

Bewaar de geretourneerde `data.id` als `TRANSFER_ID` wanneer je de gesimuleerde funding-transfer wilt inspecteren.

Het topup-id is een transfer-id. Haal het op via [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) of vraag het lijst-endpoint op via [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers) om je code-pad voor inbound-deposits te oefenen tegen sandbox-topups. De transfer-projectie is een voltooide inbound stablecoin-deposit met `origin: "inbound_deposit"`, `method: "stablecoin_transfers"` en `direction: "stablecoin_move"`, en wordt geretourneerd door de bijbehorende lijstfilters `accountId`, `origin`, `method` en `direction`.

## Voltooi of laat een transfer mislukken

Stel de uitkomst in met [`POST /v3/sandbox/transfers/{transferId}/state`](/api-reference/sandbox/post-v3-sandbox-transfers-by-transfer-id-state):

<Tabs>
  <Tab title="Voltooien">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"state":"completed"}'
```

  </Tab>
  <Tab title="Laten mislukken">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "state": "failed",
  "stateDetail": {
    "code": "sandbox_review",
    "message": "Sandbox transfer failed."
  }
}
JSON
```

  </Tab>
</Tabs>

Voer vervolgens een [pay-in](/nl/integration/receive-funds), [uitbetaling](/nl/integration/send-funds) of [uitgegeven bankrekening](/nl/integration/issue-bank-account)-flow uit in sandbox.
