For upgrading an existing integration from an earlier version, see [Migrate to v3](/api-reference/versioning/migrate-to-v3).

## 2026-08-17

**Version:** v3

### Added
- Published the v3 Problem Details catalog in the OpenAPI spec so integrators can map error responses directly from the schema. See [Errors](/integration/errors).
- Added `customerId` to v3 account webhook events, letting you correlate account activity to the owning customer without a follow-up read. See [Webhooks](/integration/webhooks).
- Full V3 individual profile field coverage in the merchant panel, so onboarding operators can review and edit every KYC field collected via the v3 API. See [Onboard customers](/integration/onboarding/customers).
- Published a v1/v2 → v3 developer migration guide. See [Migrate to v3](/api-reference/versioning/migrate-to-v3).

### Changed
- Customer and account country codes are now validated as assigned ISO 3166-1 alpha-2 values at write time. Reads tolerate legacy stored values so existing records keep resolving. See [Accounts](/integration/accounts).
- BlindPay USDC availability is now scoped by destination network, so quotes and transfers only offer USDC on the networks the destination actually supports.
- Every rail intake now requires the Swipelux Terms of Service, and ACH intake includes its ToS from the first step. Existing sessions stay resumable while provider review is open. See [Onboard customers](/integration/onboarding/customers).
- `Capability.ready` no longer implies an issued account. Wait for the account event (or read the account) before assuming it exists. See [Capabilities and requirements](/integration/onboarding/capabilities-and-requirements).
- HEIC uploads from iPhone are now accepted as identity and address documents.

### Fixed
- Re-executing a consumed quote now returns `409 quote_execution_consumed` instead of a generic error. See [Quotes and transfers](/integration/quotes-and-transfers).
- Transfer list reads and quote amount reads no longer 500 on large historical results.
- A contended KYC redirect now returns a conflict instead of a 404, so retries resolve cleanly. Hosted Align redirects no longer roll back partway through, and process-KYC links stay resumable while provider review is open.
- Related-party reads for individual customers no longer 404.
- External ACH account imports now surface the provider-reported cause when a rejection happens, so operators can act on the actual reason. See [Accounts](/integration/accounts).
- The standard-approval sweep no longer stalls on its own queue head, so onboarding decisions move through review without operator intervention.
- Sandbox Align customers are now provisioned end-to-end, and self-created transfers are no longer reported as conflicts in sandbox.
- KYB submissions with wallet-invalid fields are rejected before submit, and failed provider sync is no longer reported as success in the merchant panel.
- RFI (request-for-information) tasks in the merchant panel: submitted responses now show as complete, terms actions are tracked separately from other steps, duplicated document copy is removed, started KYC sessions stay pending until the applicant finishes, and stale RFI tasks no longer break the requirements view.
- Verification link rows in the merchant panel now show an **Open** action on every row, and every wallet-infrastructure task link renders in the requirements view.
