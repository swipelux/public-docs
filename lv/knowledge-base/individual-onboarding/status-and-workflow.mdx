## Verifikācijas statuss un darbplūsma

Uz politiku vērstais KYC ceļojums pāriet no informācijas vākšanas caur pārbaudi uz apstiprināšanas vai noraidīšanas lēmumu. Pašreizējie API resursi atklāj atsevišķus iespēju, pieteikumu, uzdevumu un iesniegumu dzīves ciklus.

<Warning>
  Politikas pārbaudes apzīmējumi un laika aplēses nenoteic API uzvedību.
  Neveidojiet stāvokļu mašīnu no zemāk esošajiem apzīmējumiem.
</Warning>

## Uz politiku vērstie pārbaudes jēdzieni

Šie uz politiku vērstie pārbaudes jēdzieni apraksta iesaistes ceļojumu. Tie nav pašreizējie API enum, webhook vērtības vai garantētas pārejas.

| Politikas apzīmējums | Nozīme |
| --- | --- |
| `not_started` | Klients eksistē, taču KYC darbs nav sācies |
| `incomplete` | KYC darbs ir sācies, taču trūkst nepieciešamās informācijas |
| `pending_verification` | Pārbaude gaida klienta pabeigšanu |
| `under_review` | Iesniegtā informācija vai dokumenti ir pārbaudē |
| `approved` | Politikas pārbaude apstiprināja klientu piemērojamām plūsmām |
| `rejected` | Politikas pārbaude noraidīja klientu |

Izmantojiet šos apzīmējumus tikai tad, kad apspriežat politikas ceļojumu. Nesūtiet tos kā pašreizējās statusa vērtības, ja vien pašreizēja ģenerēta shēma tieši neprasa to pašu vērtību savā kontekstā.

## Standarta KYC pārbaudes plūsma

1. Izveidojiet privātpersonas klientu.
2. Atklājiet un pieprasiet piemērotu iespēju.
3. Nolasiet pašreizējā uzdevuma detaļas.
4. Nosūtiet klientu uz pirmās puses mitinātu verifikācijas sesiju vai iesniedziet pilnas uzdevuma atbildes, ko pieprasa uzdevums.
5. Ļaujiet pārbaudei norisināties, kamēr pašreizējie resursi ziņo par savu pārbaudes stāvokli.
6. Atkārtoti ielādējiet pašreizējos resursus, lai noteiktu, vai nepieciešama papildu darbība vai iespēja ir gatava, ierobežota, noraidīta vai atcelta.

Politikas ceļojums to var raksturot kā nav sācies, gaida verifikāciju, pārbaudē un pēc tam apstiprināts vai noraidīts. Šie termini nedefinē API pāreju secību.

## Pastiprinātas KYC pārbaudes plūsma

1. Pabeidziet pašreiz pieprasīto standarta identitātes un dzīvīguma darbu.
2. Nolasiet jaunāko uzdevumu, kad pastiprināta pārbaude pieprasa papildu informāciju.
3. Sniedziet pieprasīto adreses apliecinājumu, līdzekļu apliecinājumu vai citus pierādījumus caur pašreizējo mitināto sesiju vai uzdevuma iesniegumu.
4. Augšupielādējiet dokumentus tikai tad, kad pašreizējais uzdevums to pieprasa.
5. Turpiniet uzraudzīt pašreizējos resursus manuālās pārbaudes laikā.
6. Apturiet vai turpiniet, pamatojoties uz pašreizējiem iespēju, pieteikumu, uzdevumu un iesniegumu stāvokļiem.

Atbilstības komanda var arī koordinēt pastiprinātu pārbaudi caur klienta reģistrēto e-pasta adresi.

## Biežākie noraidīšanas iemesli

| Iemesls | Risinājums |
| --- | --- |
| Dokuments nav lasāms | Sniedziet skaidru, augstas izšķirtspējas attēlu |
| Dokuments beidzies | Sniedziet derīgu, neizbeigušos identitātes dokumentu |
| Seja neatbilst | Pārliecinieties, ka pašbilde skaidri atbilst identitātes dokumenta fotogrāfijai |
| Nepilna informācija | Sniedziet katru vienumu, ko pieprasa pašreizējais uzdevums |
| Aizdomīga darbība | Sazinieties ar atbalstu manuālai pārbaudei |

## Verifikācijas laika grafiks

| Posms | Tipisks ilgums |
| --- | --- |
| Dokumentu augšupielāde | Uzreiz |
| Automatizētas pārbaudes | 1-3 minūtes |
| Standarta pārbaude | 1-24 stundas |
| Pastiprināta pārbaude | 1-3 darba dienas |

Šie ilgumi ir tipiskas politikas aplēses, nevis garantēta API uzvedība.

## Pašreizējās API stāvokļa vārdnīcas

Pašreizējie resursi izmanto atsevišķas slēgtas vārdnīcas:

- **Iespējas statuss:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Pieteikuma statuss:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Uzdevuma statuss:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Iesnieguma rezultāts:** `in_review`, `accepted`, `changes_requested`, `rejected`

Nesaplūdiniet šīs vārdnīcas vienā verifikācijas statusā.

## Notikumi un pašreizējais stāvoklis

Izmantojiet pašlaik dokumentētus [Webhook izsaukumus](/lv/integration/webhooks) kā izmaiņu paziņojumus, pēc tam atkārtoti ielādējiet pašreizējos klienta, iespējas, pieteikuma un uzdevuma resursus. Notikumi neaizstāj autoritatīvu resursu lasīšanu, un neviens uz politiku vērsts apzīmējums nenozīmē konkrētu notikumu.

Skatiet [Iespējas un uzdevumi](/lv/integration/onboarding/capabilities-and-requirements#complete-current-tasks) pašreizējam darbību ciklam.
