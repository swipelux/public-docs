## Privātpersonu iesaistes API darbplūsma

Izmantojiet šo karti, lai savienotu privātpersonu KYC politiku ar pašreizējo ģenerēto API atsauci. Katrā solī sekojiet pašreizējam resursam, nevis ieviesiet uz politiku vērstus apzīmējumus kā API stāvokļu mašīnu.

## Darbplūsmas karte

### 1. Izveidojiet privātpersonas klientu

Izveidojiet klientu ar [`POST /v3/customers`](/api-reference/customers/post-v3-customers). Saglabājiet atgriezto klienta ID un nolasiet pašreizējo resursu ar [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id).

### 2. Atklājiet un pieprasiet piemērotu iespēju

Nolasiet [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported). Izvēlieties variantu tikai tad, kad tā pašreizējā pieejamība un atbilstība atļauj pieprasījumu, pēc tam izmantojiet [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id).

### 3. Nolasiet pašreizējo iespēju un pieteikumus

Nolasiet [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id) un [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications). Sekojiet pašreizējiem atvērtajiem uzdevumu ID, nevis pieņemiet gatavību no agrākas atbildes.

### 4. Ielādējiet pašreizējā uzdevuma detaļas

Uzskaitiet klienta uzdevumus ar [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks). Ielādējiet autorizēto darbības laukumu ar [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task).

Uzdevuma detaļas var atklāt pirmās puses mitinātās sesijas URL un pašreizējās rīkojamās prasības. Izmantojiet tā pašreizējo versiju un statusu.

### 5. Pabeidziet mitinātās sesijas vai iesniedziet uzdevuma atbildes

Kad uzdevuma detaļas nodrošina mitinātu sesiju, atgriežat klientam tikai nepieciešamos sesijas datus un turiet API atslēgu savā aizmugursistēmā.

Kad uzdevums prasa atbildes, izveidojiet vienu pilnu nemainīgu mēģinājumu ar [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission). Nolasiet vienu pašreizējo iesniegumu un tā publisko rezultātu ar [`GET /v3/customers/{customerId}/tasks/{taskId}/submissions/{submissionId}`](/api-reference/task-submissions/get-customer-task-submission).

### 6. Augšupielādējiet dokumentus tikai, kad pieprasīts

Augšupielādējiet dokumentus tikai tad, kad pašreizējais uzdevums to pieprasa. Izmantojiet [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents), pēc tam ievietojiet atgriezto dokumenta ID atbilstošajā dokumenta atbildē.

### 7. Atkārtoti ielādējiet pašreizējos resursus

Pēc katra notikuma vai darbības atkārtoti ielādējiet pašreizējo klientu, iespēju, pieteikumus un uzdevumu. Izmantojiet to jaunākos stāvokļus, iemeslus, prasības un atvērtos uzdevumu ID, lai izvēlētos nākamo soli.

## Politikas un ieviešanas norādījumi

Vienkāršotā, standarta un pastiprinātā KYC ir politikas līmeņi. Tie neaizstāj pašreizējos iespēju, pieteikumu, uzdevumu, iesniegumu, prasību vai mitinātu sesiju stāvokļus.

Ieviešanas detaļām sekojiet [privātpersonu iesaistes ceļvedim](/lv/integration/onboarding/customers#individual-customers), [Iespējas un uzdevumi](/lv/integration/onboarding/capabilities-and-requirements#complete-current-tasks) un [Integrācijas dokumentu ceļvedim](/lv/integration/onboarding/capabilities-and-requirements#upload-documents).
