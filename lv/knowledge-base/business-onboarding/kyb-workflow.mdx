## KYB darbplūsma

KYB darbplūsma apvieno pašreizējos klienta, saistīto pušu, iespēju, uzdevumu, iesniegumu un dokumentu resursus ar uzņēmuma un tā īpašumtiesību politikas pārbaudi.

<Warning>
  KYB rezultāti un termiņi ir politikas aplēses. Tie negarantē API pārejas,
  apstiprināšanu vai pieejamību.
</Warning>

## Pašreizējā darbplūsmas secība

### 1. Izveidojiet uzņēmuma klientu

Izveidojiet uzņēmuma klientu ar [`POST /v3/customers`](/api-reference/customers/post-v3-customers). Nolasiet pašreizējo klientu ar [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id).

### 2. Uzturiet saistītās puses

Izmantojiet [`GET /v3/customers/{customerId}/related-parties`](/api-reference/customers/get-v3-customers-by-customer-id-related-parties), lai pārskatītu pašreizējās puses, [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties), lai izveidotu vienu, un [`PATCH /v3/customers/{customerId}/related-parties/{relatedPartyId}`](/api-reference/customers/patch-v3-customers-by-customer-id-related-parties-by-related-party-id), lai atjauninātu sniegtos faktus.

Uzturiet tiešos īpašniekus, mātes vienības, UBO, kontrolējošās personas, direktorus, amatpersonas un parakstītājus, ko pieprasa pašreizējie uzdevumi. Viņu lomas ir atsevišķas.

### 3. Atklājiet un pieprasiet piemērotu iespēju

Nolasiet [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported). Pieprasiet pieejamu vai beta iespēju tikai tad, kad klients ir atbilstošs, izmantojot [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id).

### 4. Nolasiet pašreizējos uzdevumus

Uzskaitiet pašreizējo darbu ar [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks). Ielādējiet katru rīkojamo uzdevumu ar [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task), pēc tam iegūstiet nākamo darbību no tā pašreizējās versijas, prasībām un sesijām.

### 5. Augšupielādējiet dokumentus, ko pieprasa pašreizējais uzdevums

Augšupielādējiet pieprasīto failu ar [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents). Pašreizējais uzdevums nosaka, vai dokuments ir nepieciešams, un var sašaurināt tā pieņemto veidu, skaitu vai formātu.

### 6. Iesniedziet pilnas uzdevuma atbildes

Iesniedziet vienu pilnu atbilžu kopu pašreizējai uzdevuma versijai ar [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission). Izmantojiet pašreizējos prasību ID un atsauciet augšupielādēto dokumentu ID tikai tur, kur uzdevums to prasa.

### 7. Uzraugiet pašreizējos resursus

Pēc katras darbības vai notikuma atkārtoti ielādējiet klientu ar [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id), iespēju ar [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id), tās pieteikumus ar [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications) un jebkurus pašreizējos uzdevumus.

Pilnai mehānikai skatiet [uzņēmumu iesaisti](/lv/integration/onboarding/customers#business-customers), [Iespējas un uzdevumi](/lv/integration/onboarding/capabilities-and-requirements#complete-current-tasks) un [Integrācijas dokumentu ceļvedi](/lv/integration/onboarding/capabilities-and-requirements#upload-documents).

## Pastiprinātas pārbaudes (EDD) iniciatori

EDD var būt nepieciešams:

- Augsta riska jurisdikcijām
- Augsta riska vertikālēm, tostarp spēlēm, tirdzniecībai un kripto biržām
- Sarežģītām īpašumtiesību struktūrām
- Sagaidāmajam mēneša apjomam, kas pārsniedz piemērojamās robežvērtības
- Darbībām, kas saistītas ar sankcionētām valstīm

## Politikas pārbaudes rezultāti

**Rezultāts:** KYB apstiprinājums, nosacīts apstiprinājums ar ierobežojumiem vai noraidījums.

Tie ir politikas pārbaudes rezultāti, nevis pašreizējās API statusa vērtības. Nosacītu politikas lēmumu var atspoguļot caur pašreizējiem resursiem, neveidojot statusu "conditional approval".

## Verifikācijas laika grafiks

| Posms | Tipisks ilgums |
| --- | --- |
| Dokumentu augšupielāde | Uzreiz |
| Sākotnējā pārbaude | 1-2 darba dienas |
| Standarta KYB | 2-5 darba dienas |
| EDD, ja aktivizēts | 5-10 darba dienas |

Šie ilgumi ir tipiskas politikas aplēses, nevis garantēta API uzvedība.

## Biežākie noraidīšanas iemesli

| Iemesls | Risinājums |
| --- | --- |
| Trūkstoši dokumenti | Sniedziet katru dokumenta veidu, ko pieprasa pašreizējais uzdevums |
| Neskaidri vai izplūduši dokumenti | Sniedziet augstākas kvalitātes skenējumus vai attēlus |
| Nesaskaņota informācija | Pārliecinieties, ka vienības nosaukums sakrīt visos iesniegtajos pierādījumos |
| Nepilna īpašumtiesību struktūra | Sniedziet pierādījumus, kas aptver 100% īpašumtiesību |
| Beigušies dokumenti | Sniedziet aktuālus, derīgus dokumentus |

## Politikas termini un API stāvokļi

Turiet politikas lēmumus atsevišķi no pašreizējiem resursu vārdnīcām:

- **Iespējas statuss:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Pieteikuma statuss:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Uzdevuma statuss:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Iesnieguma rezultāts:** `in_review`, `accepted`, `changes_requested`, `rejected`

Nolasiet jaunāko resursu, nevis pārveidojiet politikas rezultātu par API vērtību.
