---
title: "Smilšu kastes testēšana"
description: "Kontrolējiet iespējas, uzdevuma, maka un pārveduma rezultātus, veidojot savu integrāciju."
---

Smilšu kaste izmanto to pašu API resursdatoru kā produkcija. Smilšu kastes API atslēga izvēlas testa vidi, kur palīgi simulē rezultātus, nepārvietojot reālus līdzekļus.

Turiet atslēgu savā aizmugursistēmā. Smilšu kastes palīgi neaizstāj produkcijas atbilstību vai iesaisti.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

## Testējiet iespējas gatavību

Pēc iespējas pieprasīšanas iestatiet tās smilšu kastes statusu ar [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"status":"ready"}'
```

Pēc palīga izmantošanas atkārtoti ielādējiet iespēju. Uztveriet tās pašreizējo `status` un `openTaskIds` kā rezultātu, ko jūsu produktam jāapstrādā.

## Testējiet atvērtu uzdevumu

Izveidojiet smilšu kastes uzdevumu ar [`POST /v3/sandbox/tasks`](/api-reference/sandbox/post-v3-sandbox-tasks). Izvēlieties `scope.type`, kas atbilst resursam, kuru testējat, un pievienojiet vienu vai vairākus `items`, kas apraksta to, kas klientam jāiesniedz.

`scope.type` pieņem `customer`, `capability` vai `transfer`. `transfer` mērogam ir nepieciešams gan `customerId`, gan `transferId`. `capability` mērogam ir nepieciešams gan `customerId`, gan `capabilityId`. `customer` mērogam ir nepieciešams tikai `customerId`.

`items[].type` pieņem `document`, `profile`, `questionnaire`, `explanation` un `attestation`. Izmantojiet `document`, kad klientam ir jāaugšupielādē fails, `profile` konkrētam klienta profila laukam, `questionnaire` brīva teksta atbildei, `explanation` rakstiskam paskaidrojumam un `attestation`, kad klientam ir jāapstiprina teksts.

Iestatiet `category`, lai uzdevumu saskaņotu ar darbplūsmu. Darījuma informācijas pieprasījumam (Request For Information, RFI) izmantojiet `transaction_rfi` ar `transfer` mērogu.

<Tabs>
  <Tab title="Iespēja + paskaidrojums">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "capability",
    "customerId": "${CUSTOMER_ID}",
    "capabilityId": "${CAPABILITY_ID}"
  },
  "items": [
    {
      "type": "explanation",
      "request": "Explain the source of funds."
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="Pārveduma RFI + dokuments">

Ierobežojiet uzdevuma mērogu līdz pārbaudāmajam pārvedumam un pieprasiet dokumentu ar `constraints`, kas sašaurina pieņemtos tipus, formātus un vecumu.

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "transfer",
    "customerId": "${CUSTOMER_ID}",
    "transferId": "${TRANSFER_ID}"
  },
  "category": "transaction_rfi",
  "items": [
    {
      "type": "document",
      "request": "Upload a bank statement showing the source of funds for this transfer.",
      "constraints": {
        "acceptedDocumentTypes": ["bank_statement"],
        "acceptedFormats": ["pdf", "jpeg"],
        "maxAgeDays": 90
      }
    }
  ]
}
JSON
```

Dokumenta `constraints` pieņem `acceptedDocumentTypes`, `acceptedFormats`, `maxAgeDays`, `captureMethods` un `nameMatch`. Pilnu lauku katalogu skatiet [Izveidot smilšu kastes uzdevumu](/api-reference/sandbox/post-v3-sandbox-tasks).

  </Tab>
</Tabs>

Saglabājiet `data.id` kā `TASK_ID`, `data.revision` kā `TASK_REVISION` un pašreizējo `data.requirements[0].id` kā `REQUIREMENT_ID`. Iesniedziet atbildi caur [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "text",
        "value": "Sandbox requirement completed."
      }
    }
  ]
}
JSON
```

Pēc tam pieņemiet vai noraidiet pašreizējo iesniegumu ar [`POST /v3/sandbox/tasks/{taskId}/review`](/api-reference/sandbox/post-v3-sandbox-tasks-by-task-id-review):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks/${TASK_ID}/review" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"outcome":"accepted"}'
```

Izmantojiet [Iespējas un uzdevumi](/lv/integration/onboarding/capabilities-and-requirements) produkcijas uzdevumu pabeigšanas paraugam.

## Papildiniet smilšu kastes maku

Kreditējiet izsniegtu maku ar [`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${ACCOUNT_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"amount":"250.00","currency":"USDC"}'
```

Saglabājiet atgriezto `data.id` kā `TRANSFER_ID`, ja vēlaties pārbaudīt simulēto finansējuma pārvedumu.

Papildinājuma id ir pārveduma id. Iegūstiet to caur [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) vai uzskaitiet caur [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers), lai izmēģinātu savu ienākošās iemaksas koda ceļu ar smilšu kastes papildinājumiem. Pārveduma projekcija ir pabeigta ienākoša stabilās monētas iemaksa ar `origin: "inbound_deposit"`, `method: "stablecoin_transfers"` un `direction: "stablecoin_move"`, un to atgriež atbilstošie `accountId`, `origin`, `method` un `direction` saraksta filtri.

## Pabeidziet vai noraidiet pārvedumu

Iestatiet rezultātu ar [`POST /v3/sandbox/transfers/{transferId}/state`](/api-reference/sandbox/post-v3-sandbox-transfers-by-transfer-id-state):

<Tabs>
  <Tab title="Pabeigt">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"state":"completed"}'
```

  </Tab>
  <Tab title="Noraidīt">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "state": "failed",
  "stateDetail": {
    "code": "sandbox_review",
    "message": "Sandbox transfer failed."
  }
}
JSON
```

  </Tab>
</Tabs>
