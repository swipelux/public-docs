Izveidojiet klientu, pirms veidojat iemaksu, izmaksu vai izsniegtu bankas kontu. Iespējas, konti un pārvedumi ir ierobežoti ar šo klientu. Izmantojiet `externalId` kā stabilu piesaisti attiecīgajam ierakstam jūsu sistēmā.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Privātpersonas klienti

Privātpersonai nepieciešams tikai `type`. Iekļaujiet profila laukus, kurus jau zināt, un pievienojiet citus tikai tad, kad pašreizējai iespējai vai uzdevumam tie ir nepieciešami.

Izveidojiet klientu ar [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Saglabājiet atgriezto `data.id` kā `CUSTOMER_ID`. Skatiet [Privātpersonu iesaiste](/lv/knowledge-base/individual-onboarding/overview), lai iepazītos ar politikas kontekstu.

## Uzņēmumu klienti

Uzņēmumam nepieciešams `business.legalName`. Izveidojiet uzņēmumu ar to pašu operāciju:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Saglabājiet atgriezto `data.id` kā `CUSTOMER_ID`. Skatiet [Uzņēmumu iesaiste](/lv/knowledge-base/business-onboarding/overview), lai iepazītos ar politiku un dokumentu kontekstu.

## Pievienojiet uzņēmuma saistītās puses

Pievienojiet direktorus, īpašniekus un citus uzņēmuma dalībniekus, kad tie ir zināmi vai pieprasīti. Šis piemērs izveido direktoru ar [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Saglabājiet atgriezto `data.id` kā `RELATED_PARTY_ID`.

## Nolasiet gatavību no iespējām

Klientam API nav verifikācijas vai gatavības statusa. Nolasiet klientu ar [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id), lai iegūtu pašreizējos profila datus, pēc tam izmantojiet iespējas un to `openTaskIds`, lai izlemtu, ko klients var darīt tālāk.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Tālāk turpiniet uz [Iespējas un uzdevumi](/lv/integration/onboarding/capabilities-and-requirements), lai atklātu un aktivizētu nepieciešamo produkta rezultātu.
