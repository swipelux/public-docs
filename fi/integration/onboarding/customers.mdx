---
title: "Asiakkaat"
description: "Luo yksityishenkilö tai yritys, joka omistaa kyvyt, tilit ja siirrot."
---

Luo asiakas ennen kuin rakennat maksun vastaanottoa, maksua ulos tai luotua pankkitiliä. Kyvyt, tilit ja siirrot on rajattu tähän asiakkaaseen. Käytä `externalId`-kenttää vakaana yhdistämisenä järjestelmäsi vastaavaan tietueeseen.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Yksityisasiakkaat {#individual-customers}

Yksityishenkilö vaatii vain `type`-kentän. Sisällytä jo tiedossa olevat profiilikentät ja lisää lisää vain, kun nykyinen kyky tai tehtävä niitä tarvitsee.

Luo asiakas [`POST /v3/customers`](/api-reference/customers/post-v3-customers) -toiminnolla:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Tallenna palautettu `data.id` muuttujaan `CUSTOMER_ID`. Katso [Yksityishenkilön käyttöönotto](/fi/knowledge-base/individual-onboarding/overview) käytäntökontekstia varten.

## Yritysasiakkaat {#business-customers}

Yritys vaatii `business.legalName`-kentän. Luo yritys samalla toiminnolla:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Tallenna palautettu `data.id` muuttujaan `CUSTOMER_ID`. Katso [Yrityksen käyttöönotto](/fi/knowledge-base/business-onboarding/overview) käytäntö- ja dokumenttikontekstia varten.

## Lisää yritykseen liittyvät osapuolet

Lisää johtajat, omistajat ja muut yrityksen osallistujat, kun ne ovat tiedossa tai pyydettyjä. Tämä esimerkki luo johtajan [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) -toiminnolla:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Tallenna palautettu `data.id` muuttujaan `RELATED_PARTY_ID`.

## Lue valmius kyvyistä

Asiakkaalla ei ole vahvistus- tai valmiustilaa API:ssa. Lue asiakas [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) -toiminnolla nykyisten profiilitietojen saamiseksi, käytä sitten kykyjä ja niiden `openTaskIds`-kenttiä päättämään, mitä asiakas voi tehdä seuraavaksi.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Seuraavaksi jatka kohtaan [Kyvyt ja tehtävät](/fi/integration/onboarding/capabilities-and-requirements), joka löytää ja aktivoi tarvitsemasi tuotetuloksen.
