Sandbox käyttää samaa API-isäntää kuin tuotanto. Sandbox-API-avain valitsee testiympäristön, jossa apuvälineet simuloivat tuloksia siirtämättä oikeita varoja.

Pidä avain taustapalvelussasi. Sandbox-apuvälineet eivät korvaa tuotannon vaatimustenmukaisuutta tai käyttöönottoa.

Käytä [Virheet ja uudelleenyritykset](/fi/integration/errors) -sivua testataksesi, miten integraatiosi käsittelee sandbox-toimintojen palauttamat validointi-, tila- ja uudelleenyritettävät alustavirheet.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

## Testaa kyvyn valmius

Kun olet pyytänyt kykyä, aseta sen sandbox-tila [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status) -toiminnolla:

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"status":"ready"}'
```

Hae kyky uudelleen apuvälineen käytön jälkeen. Käsittele sen nykyistä `status`- ja `openTaskIds`-tulosta tuotteesi käsittelemänä tuloksena.

## Testaa avoin tehtävä

Luo sandbox-tehtävä [`POST /v3/sandbox/tasks`](/api-reference/sandbox/post-v3-sandbox-tasks) -toiminnolla. Kohdista se testattavan työnkulun resurssiin ja kuvaa asiakkaan toimitus `items`-kentässä. Tässä oppaassa näytetään capability- ja transfer-työnkulut; API Reference määrittää customer-laajuuden ja koko pyyntöskeeman.

Käytä `explanation`-elementtiä tekstivastaukseen ja `document`-elementtiä tiedoston lataamiseen. Uudet `profile`-elementit vaativat myös `profilePointer`-kentän, joka on asiakaskentän nimeävä JSON Pointer. Muut elementtityypit ja kentät ovat kohdassa [Luo sandbox-tehtävä](/api-reference/sandbox/post-v3-sandbox-tasks).

Luo transfer-esimerkkiä varten ensin sandbox-transfer [pay-in](/fi/integration/receive-funds)- tai [payout](/fi/integration/send-funds)-työnkululla ja vie sitten palautettu `data.id`:

```bash
export TRANSFER_ID='tr_replace_with_your_transfer_id'
```

```bash
curl --request POST \
```

Kohdista tehtävä tarkasteltavana olevaan siirtoon ja pyydä dokumenttia `constraints`-määrittelyillä, jotka rajaavat hyväksyttyjä tyyppejä, muotoja ja ikää.

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "transfer",
    "customerId": "${CUSTOMER_ID}",
    "transferId": "${TRANSFER_ID}"
  },
  "category": "transaction_rfi",
  "items": [
    {
      "type": "document",
      "request": "Upload a bank statement showing the source of funds for this transfer.",
      "constraints": {
        "acceptedDocumentTypes": ["bank_statement"],
        "acceptedFormats": ["pdf", "jpeg"],
        "maxAgeDays": 90
      }
    }
  ]
}
JSON
```

Esimerkki rajaa hyväksytyn dokumenttityypin, muodon ja iän. Kaikki tuetut dokumenttirajoitukset ovat kohdassa [Luo sandbox-tehtävä](/api-reference/sandbox/post-v3-sandbox-tasks).

  </Tab>
</Tabs>

Tallenna `data.id` muuttujaan `TASK_ID`, `data.revision` muuttujaan `TASK_REVISION` ja nykyinen `data.requirements[0].id` muuttujaan `REQUIREMENT_ID`. Kun kutsut [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) -toimintoa, sovita vastaus luomaasi elementtiin:

<Tabs>
  <Tab title="Selitysvastaus">

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "text",
        "value": "Sandbox requirement completed."
      }
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="Dokumenttivastaus">

Lataa vaatimuksia vastaava tiedosto [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents) -toiminnolla, tallenna palautettu `data.id` muuttujaan `DOCUMENT_ID` ja lähetä se dokumenttivastauksena:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-document-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "document",
        "documentIds": ["${DOCUMENT_ID}"]
      }
    }
  ]
}
JSON
```

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks/${TASK_ID}/review" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"outcome":"accepted"}'
```

Käytä [Kyvyt ja tehtävät](/fi/integration/onboarding/capabilities-and-requirements) -sivua tuotannon tehtävän suorittamisen mallia varten.

## Rahoita sandbox-lompakko

Hyvitä luotu lompakko [`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup) -toiminnolla:

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${ACCOUNT_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"amount":"250.00","currency":"USDC"}'
```

Tallenna palautettu `data.id` muuttujaan `TRANSFER_ID`, kun haluat tarkastella simuloitua rahoitussiirtoa.

Topupin tunniste on siirron tunniste. Hae se [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) -toiminnolla tai listaa se [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers) -toiminnolla harjoitellaksesi saapuvien talletusten koodipolkuasi sandbox-topupeja vastaan. Siirron projisointi on valmistunut saapuva stablecoin-talletus, jonka `origin: "inbound_deposit"`, `method: "stablecoin_transfers"` ja `direction: "stablecoin_move"`, ja se palautetaan vastaavilla `accountId`-, `origin`-, `method`- ja `direction`-listasuodattimilla.

## Suorita tai epäonnistu siirto

Aseta tulos [`POST /v3/sandbox/transfers/{transferId}/state`](/api-reference/sandbox/post-v3-sandbox-transfers-by-transfer-id-state) -toiminnolla:

<Tabs>
  <Tab title="Suorita">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"state":"completed"}'
```

  </Tab>
  <Tab title="Epäonnistu">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "state": "failed",
  "stateDetail": {
    "code": "sandbox_review",
    "message": "Sandbox transfer failed."
  }
}
JSON
```

  </Tab>
</Tabs>

Seuraavaksi suorita [maksun vastaanotto](/fi/integration/receive-funds), [maksu ulos](/fi/integration/send-funds) tai [luotu pankkitili](/fi/integration/issue-bank-account) -virta sandboxissa.
