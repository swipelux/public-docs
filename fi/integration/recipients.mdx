---
title: "Vastaanottajat ja kohteet"
description: "Luo kolmannen osapuolen vastaanottaja ja pankki- tai lompakkopäätepiste, joka vastaanottaa maksun."
---

Käytä asiakastiliä, kun asiakas omistaa päätepisteen. Käytä vastaanottajaa ja kohdetta, kun toinen henkilö tai yritys vastaanottaa varat.

Vastaanottaja kirjaa, kuka vastaanottaa varat. Kohde kirjaa, missä he saavat ne.

## 1. Luo vastaanottaja

Luo yksityishenkilö tai yritys [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients) -toiminnolla. Lähetä nämä otsakkeet:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-create-001
Content-Type: application/json
```

```json
{
  "type": "individual",
  "relationship": "contractor",
  "firstName": "Jason",
  "lastName": "Swipelux",
  "email": "jason@swipelux.com",
  "phone": "+14155551234",
  "address": {
    "streetLine1": "1 Market Street",
    "city": "San Francisco",
    "state": "CA",
    "postalCode": "94105",
    "country": "US"
  },
  "label": "Jason contractor"
}
```

`relationship` kuvaa, miten vastaanottaja liittyy asiakkaaseesi. Lähetä yksi arvoista `employee`, `contractor`, `vendor`, `subsidiary`, `merchant`, `customer`, `landlord`, `family` tai `other`. Kenttä hyväksyy vain nämä arvot; `other`-arvon rinnalla ei ole vapaamuotoista kuvausta.

Sisällytä osoite ennen fiat-kohteen luomista. Tallenna palautettu vastaanottajan `data.id` muuttujaan `RECIPIENT_ID` ja säilytä sen nykyinen tila.

## 2. Lisää kohde

Luo päätepiste [`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations) -toiminnolla. Käytä uutta avainta tälle aiotulle kohteelle:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-destination-create-001
Content-Type: application/json
```

<Tabs>
  <Tab title="Pankkikohde">

```json
{
  "type": "ach",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "Example Bank",
    "accountHolderName": "Jason Swipelux",
    "country": "US"
  }
}
```

  </Tab>
  <Tab title="Lompakkokohde">

```json
{
  "type": "wallet",
  "currency": "USDC",
  "ownership": {
    "type": "self_custodied"
  },
  "details": {
    "network": "base",
    "address": "0x1111111111111111111111111111111111111111"
  }
}
```

  </Tab>
</Tabs>

Käytä `self_custodied`-arvoa vain, kun vastaanottaja hallitsee lompakkoa. Seuraa nykyistä API-referenssin muunnelmaa, kun lompakko on toisen säilyttäjän hallussa.

Tallenna palautettu kohteen `data.id` muuttujaan `DESTINATION_ID` ja säilytä sen nykyinen tila.

## 3. Odota kohteen valmiutta

Lue [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id) ennen tarjouksen luomista.

Jatka vain, kun kohteen nykyinen tila sallii maksun ja sen valuutta, menetelmä ja verkko vastaavat aiottua liikkumista. Vastaanottajan ja kohteen tilat ovat itsenäisiä.

Käytä `dst_`-kohteen ID:tä maksun tarjouksessa. `rcp_`-vastaanottajan ID tunnistaa omistajatietueen, eikä se ole tarjouskohde.

Seuraavaksi vie valmis kohde kohtaan [Lähetä varoja](/fi/integration/send-funds).
