## 核验状态与流程

面向政策的 KYC 过程从信息收集开始,经过审核,最终得出批准或拒绝的决定。当前的 API 资源暴露的是各自独立的能力、申请、任务和提交生命周期。

<Warning>
  政策上的审核标签和时间估算并不定义 API 行为。请不要基于下面的标签
  实现状态机。
</Warning>

## 面向政策的审核概念

以下概念描述的是入驻过程中的政策审核阶段。它们不是当前的 API 枚举、Webhook 值,也不代表保证的状态迁移。

| 政策标签 | 含义 |
| --- | --- |
| `not_started` | 客户已存在,但 KYC 工作尚未开始 |
| `incomplete` | KYC 工作已开始,但缺少所需信息 |
| `pending_verification` | 审核在等待客户完成操作 |
| `under_review` | 提交的信息或材料正在审核中 |
| `approved` | 政策审核已批准该客户使用适用的资金流 |
| `rejected` | 政策审核已拒绝该客户 |

请仅在讨论政策阶段时使用这些标签。除非当前生成的 schema 在自身上下文中明确要求提交同名的值,否则不要将它们作为当前状态值发送。

## 标准 KYC 审核流程

1. 创建个人客户。
2. 发现并申请符合条件的能力。
3. 阅读当前任务的详情。
4. 将客户引导至第一方托管的核验会话,或提交任务所要求的完整答案。
5. 在审核进行期间,让当前资源各自报告它们的审核状态。
6. 重新读取当前资源,判断是需要采取更多操作,还是能力已经就绪、受限、拒绝或取消。

政策阶段可能会将其描述为 not started、pending verification、under review,最后是 approved 或 rejected。这些说法并不定义 API 的状态迁移顺序。

## 加强 KYC 审核流程

1. 完成当前所要求的标准身份与活体检查工作。
2. 当加强审核要求补充信息时,阅读最新的任务。
3. 通过当前的托管会话或任务提交,提供所要求的地址证明、资金证明或其他证据。
4. 仅在当前任务要求时才上传材料。
5. 在人工审核期间持续监控当前资源。
6. 根据当前的能力、申请、任务和提交状态决定是否继续。

对于加强审核,合规团队还可能通过客户的注册邮箱与其协调。

## 常见拒绝原因

| 原因 | 解决方式 |
| --- | --- |
| 材料无法辨认 | 提供清晰、高分辨率的图片 |
| 材料已过期 | 提供未过期的有效身份证件 |
| 人脸不匹配 | 确保自拍与证件照片明显一致 |
| 信息不完整 | 提供当前任务所要求的每一项内容 |
| 可疑活动 | 联系支持团队进行人工审核 |

## 核验时间

| 阶段 | 通常时长 |
| --- | --- |
| 材料上传 | 即时 |
| 自动化检查 | 1-3 分钟 |
| 标准审核 | 1-24 小时 |
| 加强审核 | 1-3 个工作日 |

上述时长为通常的政策估计,不代表保证的 API 行为。

## 当前 API 状态词汇

当前资源使用各自独立的封闭词汇:

- **能力状态:** `pending`、`ready`、`restricted`、`rejected`、`canceled`
- **申请状态:** `requested`、`in_review`、`action_required`、`ready`、`rejected`、`disabled`、`canceled`
- **任务状态:** `action_required`、`in_review`、`satisfied`、`rejected`、`canceled`
- **提交结果:** `in_review`、`accepted`、`changes_requested`、`rejected`

请勿将这些词汇简化归并为单一的核验状态。

## 事件与当前状态

请将当前已经文档化的 [Webhook](/cn/integration/webhooks) 视为变更通知,然后重新获取当前的客户、能力、申请和任务资源。事件不能替代权威的资源读取,任何面向政策的标签都不隐含某种特定事件。

当前的操作循环请参阅[能力与任务](/cn/integration/onboarding/capabilities-and-requirements#complete-current-tasks)。
