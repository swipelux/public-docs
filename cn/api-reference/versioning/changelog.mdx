## 2026-08-17

**版本：** v3

### 新增
- 在 OpenAPI 规范中发布了 v3 Problem Details 目录，集成方可直接从架构中映射错误响应。
- 在 v3 账户 webhook 事件中新增了 `customerId`，让您无需再进行一次读取即可将账户活动与其所属客户关联。参见 [Webhook](/cn/integration/webhooks)。
- 商户面板中完整覆盖 V3 个人档案字段，入驻操作员可查看并编辑通过 v3 API 收集的每个 KYC 字段。参见 [客户](/cn/integration/onboarding/customers)。
- 发布了 v1/v2 → v3 的开发者迁移指南。参见 [迁移到 v3](/cn/api-reference/versioning/migrate-to-v3)。

### 变更
- 客户与账户的国家/地区代码在写入时现按已分配的 ISO 3166-1 alpha-2 值进行校验。读取时兼容遗留的存储值，因此现有记录仍可解析。参见 [账户与钱包](/cn/integration/accounts)。
- BlindPay 的 USDC 可用性现按目的网络进行限定，因此报价与转账仅在目的地实际支持的网络上提供 USDC。
- 现在每个通道的接入都需要 Swipelux 的 Terms of Service，ACH 接入从第一步起即包含其 ToS。在提供商审核期间，现有会话可继续恢复。参见 [客户](/cn/integration/onboarding/customers)。
- `Capability.ready` 不再意味着已开立账户。请先等待账户事件（或读取账户）后再假定其存在。参见 [能力与任务](/cn/integration/onboarding/capabilities-and-requirements)。
- 现已支持从 iPhone 上传 HEIC 作为身份和地址证明文件。

### 修复
- 重新执行已消费的报价现返回 `409 quote_execution_consumed`，而不是通用错误。参见 [报价与转账](/cn/integration/quotes-and-transfers)。
- 大规模历史结果下的转账列表读取与报价金额读取不再出现 500。
- 出现争用的 KYC 重定向现返回冲突而非 404，因此重试可干净地完成。托管的 Align 重定向不再在中途回滚，process-KYC 链接在提供商审核期间保持可恢复。
- 个人客户的关联方读取不再返回 404。
- 外部 ACH 账户导入在被拒绝时现会呈现提供商所报告的原因，便于操作员针对真实原因采取行动。参见 [账户与钱包](/cn/integration/accounts)。
- 标准审批扫描不再卡在自身队列头部，因此入驻决定可无须操作员介入即完成审核流转。
- 沙箱中的 Align 客户现已端到端配置完成，自建的转账在沙箱中不再被报告为冲突。
- 含钱包无效字段的 KYB 提交在提交前即被拒绝，与提供商同步失败也不再在商户面板中被报告为成功。
- 商户面板中的 RFI（信息请求）任务：已提交的响应现显示为已完成，条款操作与其他步骤分开跟踪，去除了重复的文档文案，已开始的 KYC 会话在申请人完成前保持待处理，过期的 RFI 任务不再破坏需求视图。
- 商户面板中的验证链接行现在每行都显示 **Open** 操作，每个钱包基础设施任务链接都会在需求视图中渲染。
