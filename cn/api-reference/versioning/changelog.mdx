本页列出 Swipelux API 按日期排列的变更。每条记录会注明所影响的版本、变更类型，以及集成方需要采取的任何操作。

如需将现有集成从较早版本升级，请参阅 [迁移到 v3](/cn/api-reference/versioning/migrate-to-v3)。

## 未发布

_即将上线的变更将在正式发布前列于此处。_

## 2026-09-28

**版本：** v3

### 新增
- `POST /v3/quotes` 现在接受可选的 `institutionId`，用于为加密货币到法币的出金报价选择已获批准的银行通道。省略该字段则保持自动路由。选择对该出金不可用的银行会返回 `422 bank_not_supported_for_customer`，在其他任何报价类型中发送 `institutionId` 会返回 `400 validation_error`。请参阅[发送资金](/cn/integration/send-funds)。
- `POST /v3/customers/{customerId}/accounts` 上签发银行账户的请求接受 `institution`，用于将账户固定到某一家银行且不进行回退；并接受 `allowPending: true`，用于在该银行的申请仍待批准时保存请求。`allowPending` 需要同时提供 `institution`。已保存的请求会报告其所属的 `applicationId`。请参阅[发行银行账户](/cn/integration/issue-bank-account)。
- 商户面板新增原生 **Webhooks** 页面，用于管理端点。请参阅[Webhook](/cn/integration/webhooks)。
- 商户面板新增 **Pay in** 抽屉，包含已命名的银行账户、加密货币入金和审核步骤。
- 商户面板的 **Pay out** 流程会在来源选择器中显示钱包余额，新增 **Max** 金额选项，并包含审核步骤。
- 商户面板中的客户档案新增 **Recipients & destinations** 标签页。
- 任务要求可以包含简短的 `title` 标题。请求的 `prompt` 仍承载指导说明。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。

### 变更
- 共享 Wire 通道上的电汇入金报价现在要求至少 20 美元。低于所在通道最低金额，或金额过小、不足以支付转账费用的报价会返回 `422 amount_not_deliverable`，而不是通用的报价失败。请参阅[接收资金](/cn/integration/receive-funds)。
- Webhook 门户现在按资源对 v3 事件类型进行分组，并显示每个事件的负载架构和示例。旧版事件类型显示在单独的 **Legacy** 分组中，并标记为已弃用。已订阅这些事件类型的端点会继续收到它们；新订阅请使用 v3 事件类型。请参阅[Webhook](/cn/integration/webhooks)。
- 沙盒充值现在会发出 `transfer.created` 和 `transfer.state_changed` Webhook 事件。请参阅[在沙盒中测试](/cn/integration/sandbox)。
- 当客户已拥有处于活跃状态的已签发账户时，`accountProvisioning` 现在会报告 `issued`。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 商户面板中的银行账户详情会在抽屉中打开，并显示银行徽标。请参阅[账户](/cn/integration/accounts)。
- 商户面板将资金流动标记为 **Pay in** 和 **Pay out**，保持登录状态六小时，并通过电子邮件将帮助请求发送给 Swipelux 支持团队。
- 在接受直接提交的受理任务中，已由客户档案或已上传文档支持的符合条件的要求会自动进入 `in_review`。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements#reused-profile-evidence)。

### 修复
- 重新请求已取消的能力不再因已被取代的申请记录或过时的要求而失败。
- 以已停用的 Fedwire ID 存储的能力现在读取为 `wire`，而不是返回 `500`。

## 2026-09-21

**版本：** v3

### 新增
- `GET /v3/customers/{customerId}/applications` 列出客户的申请案例，包括针对每个案例请求的能力以及其批准所覆盖的能力。在一家银行获得的一次批准可以覆盖多项能力。保留的历史案例会通过 `supersededByApplicationId` 指向其后继案例。该列表支持游标分页和 `updatedAfter`。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 对于基于申请案例的能力，`POST /v3/customers/{customerId}/capabilities/{capabilityId}` 的响应包含 `selectedApplicationId`。它标识该请求复用的现有申请案例，或其新开启的案例。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 由 `GET /v3/institutions` 和支持的能力列表返回的机构包含可为空的 `logoUrl`。可用时使用它显示银行品牌标识，为 `null` 时回退为显示机构名称。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 美元 SWIFT 出金现已可用。SWIFT 出金最低需要 100 美元。商户面板会收集收款方的 SWIFT 银行指令。请参阅[发送资金](/cn/integration/send-funds)。
- 已签发银行账户可以使用具名收款详情通过 SWIFT 收款。请参阅[发行银行账户](/cn/integration/issue-bank-account)。
- USDT 现在支持作为 ACH 和 Wire 出金的来源。请参阅[发送资金](/cn/integration/send-funds)。
- 已签发银行账户接受值为 `USDC` 或 `USDT` 的 `settlement.currency`，用于选择交付到结算钱包的稳定币，与钱包账户币种无关。省略该字段则继续以钱包的币种结算。请参阅[发行银行账户](/cn/integration/issue-bank-account)。
- SWIFT 银行账户和收款方目的地接受 `bankCity`、`bankState`、`bankPostalCode` 和 `bankAddressLine2`，以及可选的 `beneficiaryTaxId`、`beneficiaryPhoneNumber`、`ifscBranchCode`、`paymentCode` 和中转银行详情。请参阅[发送资金](/cn/integration/send-funds)。
- 当银行提供分开的 ACH 和 Wire 路由号码时，已签发银行账户详情会包含 `achRoutingNumber` 和 `wireRoutingNumber`，并包含收款银行的 `bankLogoUrl`。请参阅[发行银行账户](/cn/integration/issue-bank-account)。
- `capability.created` Webhook 事件包含 `applicationId` 以及值为 `requested` 或 `approval` 的 `origin`，便于您区分自己请求的能力和由批准覆盖的能力。请参阅[Webhook](/cn/integration/webhooks)。
- 要求请求可以声明用于校验的 `constraints.format`，例如 `http_url`、`us_ssn`、`us_ein` 或 `bank_industry_classification`。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。

### 变更
- 商户面板中的银行账户创建现在从选择银行开始，银行账户会显示分开的 ACH 和 Wire 路由号码。请参阅[账户](/cn/integration/accounts)。
- `network` 枚举现在包含 `solana`。这是一个开放枚举，因此请容忍您无法识别的网络值。请参阅[账户](/cn/integration/accounts)。
- 如果任务的剩余要求需要直接提交，为该任务打开托管验证链接会返回 `409 verification_session_not_allowed`。请改为以任务提交的方式提交这些要求。请参阅[错误与重试](/integration/errors#verification-session-not-allowed)。
- 归档预配尚未完成的已签发账户会返回 `409 account_provisioning_unresolved`。请在预配完成后重试。请参阅[错误与重试](/integration/errors#account-provisioning-unresolved)。
- 新的具名银行账户请求会在账户创建后立即排队等待预配，而不是等到下一次客户刷新。请参阅[发行银行账户](/cn/integration/issue-bank-account)。

### 移除
- 新账户不再提供共享的 SWIFT 收款详情。请改用具名 SWIFT 收款详情。请参阅[发行银行账户](/cn/integration/issue-bank-account)。

### 修复
- 出金转账读取现在会返回报价中的收款方。
- 归档现有 ACH 账户后再创建 ACH 账户不再返回 `409`，已归档的待处理账户请求也不再占用账户名额。
- 本币入金报价上的银行费用现在以正确的法币币种报告。

## 2026-09-14

**版本：** v3

### 新增
- `GET /v3/webhooks/{webhookId}` 可读取单个 Webhook 端点及其 `events` 选择。请参阅[Webhook](/cn/integration/webhooks)。
- 任务要求现在会为档案字段（包括必填地址字段）发布 `allowedValues` 和 JSON Schema `valueSchema`。国家/地区字段会将 `valueType` 或 `itemValueType` 报告为 `country`，即 ISO 3166-1 alpha-2 代码。您无需硬编码即可渲染输入项和选项。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 现有的 Tron 钱包现在可以向客户的外部钱包账户发送 USDT，转账读取会包含 Tron 交易的区块浏览器链接。无法在 Tron 上签发新钱包。请参阅[发送资金](/cn/integration/send-funds)。
- 任务要求可以声明 `requiredWhen`（仅当指定的是/否回答匹配时才需作答）、`profileAssertion`（`us_person`）和 `ownershipPolicy`，文档请求可以设置 `identityMetadataRequired` 和 `maxIssueAgeDays`。任务回答接受针对所引用文档的 `documentMetadata`（`idNumber`、`issuingCountry`、`issuedOn`），任务读取会在 `conditionValues` 中返回已审核的控制性回答。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 文档要求可以列出 `acceptedDocumentSets`，关联方要求除 `beneficial_owner` 外还可以要求 `associated_person` 或 `control_person` 资格。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 转账 `correction` 对象现在也涵盖已注资但失败的出金：`kind: funding_failure`，附带 `recover_source_funding` 补偿操作、值为 `unknown` 或 `reported` 的 `recoveryStatus`，以及 `USDT` 入账输出。请参阅[报价与转账](/cn/integration/quotes-and-transfers)。

### 变更
- `PATCH /v3/webhooks/{webhookId}` 现在接受端点已订阅的旧版事件类型，因此您可以在添加 v3 事件类型时保留它们。`events` 会替换完整的选择，因此请包含您想保留的每一种事件类型。添加端点原本没有的旧版事件类型会返回 `400 validation_error`。请参阅[Webhook](/cn/integration/webhooks)。
- 收款方和账户上的银行标识符会在保存前进行校验。请参阅[收款方](/cn/integration/recipients)。
- 当能力是在较早的入驻模型下创建时，能力请求、任务提交和沙盒状态变更现在会返回 `409 capability_application_stale`，而不是 `500`。请参阅[错误与重试](/integration/errors)。
- 公开的 RFI 页面现在是一个连续的表单。它支持关联人员，并为每个人收集一个税号。请参阅[文档要求](/cn/knowledge-base/business-onboarding/document-requirements)。
- 当付款超过客户在银行的剩余每日或每月额度时，报价和转账会返回 `409 customer_bank_limit_exceeded`；无法检查该额度时会返回 `503 customer_bank_limits_unavailable`。当出金无法从其报价启动时，转账会返回 `409 payout_execution_unavailable`。请参阅[错误与重试](/integration/errors)。
- 与已完成的银行受理相冲突的客户和关联方更新会返回 `409 field_conflicts_with_completed_intake`，并附带 `taskId` 和 `fields`。请参阅[错误与重试](/integration/errors#field-conflicts-with-completed-intake)。

### 修复
- 已取消的能力历史仍可读取。
- 电汇出金在商户面板的交易列表中能够正确显示和筛选。

## 2026-09-08

**版本：** v3

### 变更
- `POST /v3/transfers` 和转账读取现在使用 `checkoutMethod` 而非 `paymentMethod` 来预选银行卡结账方式，并接受 `card`、`apple_pay`、`google_pay`、`cash_app`、`sepa` 和 `blik`。该列表是开放的，可能会增加。`paymentMethod` 不再被识别；仍发送该字段的请求会被视为省略了它。`sepa` 和 `blik` 是银行卡结账内部的付款选项，而不是 Swipelux 的能力。请参阅[接收资金](/cn/integration/receive-funds)。

## 2026-09-07

**版本：** v3

### 新增
- `POST /v3/transfers` 现在接受可选的 `paymentMethod`（`card`、`apple_pay` 或 `google_pay`），用于银行卡报价。当请求的方式对客户及其设备可用时，托管结账会以该方式打开；转账读取会回显该请求，报价的金额和费用保持不变。请参阅[接收资金](/cn/integration/receive-funds)。
- `GET /v3/customers/{customerId}/capabilities/{capabilityId}/tasks-preview` 接受 `institutions`，用于预览支持的能力列表所返回的特定银行的任务。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。

### 变更
- 银行卡报价现在会反映结账费用和实际交付的 USDC 净额。请参阅[接收资金](/cn/integration/receive-funds)。
- 被拒绝的出金报价现在返回具体的问题代码，而不是通用失败：`quote_amount_out_of_range`、`quote_volume_limit_exceeded`、`quote_source_network_unsupported` 或 `quote_failed`；当报价可稍后重试时返回 `503 quote_temporarily_unavailable`。请参阅[错误与重试](/integration/errors)。

### 修复
- 银行卡报价不再因费用四舍五入而失败。
- 当问卷答案包含多余空格时，重新打开托管 KYC 链接不再返回 `409 kyc_process_conflict`。
- 商户面板中卡住的通行密钥提现确认现在可以恢复。

## 2026-08-31

**版本：** v3

### 新增
- `POST /v3/customers/{customerId}/documents` 现在还接受携带 `storageKey`、`fileName` 和 `type` 的 `application/json` 请求体。`storageKey` 必须是通过先前的直接上传流程暂存的、客户范围内的新鲜引用，且该上传会经过与 multipart 上传相同的大小和文件签名校验。请参阅[迁移到 v3](/cn/api-reference/versioning/migrate-to-v3)。
- `GET /v3/customers/{customerId}/documents/{documentId}/download` 会为处于活跃状态的客户文档返回一个下载 `url`。该 URL 在一小时后过期，并以附件形式提供文件。已归档、未知或跨客户的文档会返回 `404`。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 为没有受益所有人的企业请求能力时，现在会创建用于添加受益所有人的受理任务，而不是以 `503` 失败。无法继续的请求会返回 `422 beneficial_owner_required`，并附带说明，要求添加一位已申报或至少持股 25% 的个人关联方。请参阅[股东、UBO 与控制人](/cn/knowledge-base/business-onboarding/shareholders-ubos-and-control-persons)。
- 商户面板的任务表现在会显示每个请求的主体和能力范围，让您了解合规请求涉及的对象和内容。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 商户面板中的行业分类字段现在在客户档案和要求任务上提供可搜索的 NAICS 代码。请参阅[KYB 工作流程](/cn/knowledge-base/business-onboarding/kyb-workflow)。
- 银行入金指令可以包含 `bankName`、`bankAddress`、`accountHolderName` 和 `accountHolderAddress`。请将它们与其他银行信息一起显示。请参阅[接收资金](/cn/integration/receive-funds)。
- `POST /v3/transfers` 接受可选的 `redirectUrl`，用于在银行卡或 Apple Pay 托管结账后将客户带回您的应用。到达该 URL 并不能确认已完成；请使用转账读取或 Webhook。请参阅[接收资金](/cn/integration/receive-funds)。
- 由 v3 Rule 创建的转账会以 `origin: rule` 出现在转账读取和列表中，并像其他转账一样发出 `transfer.state_changed` 事件。可使用 `GET /v3/transfers?origin=rule` 筛选它们。请参阅[报价与转账](/cn/integration/quotes-and-transfers)。
- 客户和关联方上的身份证件接受 `sideApplicability`（`front_only`、`front_and_back` 或 `unknown`），任务可以将 `type`、`number`、`issuingCountry`、`issuingRegion`、`issuedOn`、`expiresOn` 和 `doesNotExpire` 等身份证件详情作为回答收集。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。

### 变更
- 与正在进行的银行设置冲突的银行详情提交现在会返回 `409 ops_rail_handoff_conflict`。请保留已上传的文档 ID，并在冲突解决后重试同一提交，而不是重新上传文档。请参阅[错误与重试](/integration/errors)。
- 未预告的稳定币入金到客户钱包的最低金额现在为 1 个单位，而不是 10 个。更小的入金仍被视为粉尘。请参阅[接收资金](/cn/integration/receive-funds)。
- Webhook 配置现在按环境隔离。Webhook 门户会以您发起请求的环境为范围打开，因此沙盒和生产端点不再共享设置。请参阅[Webhook](/cn/integration/webhooks)。
- 商户面板现在根据客户的 v3 能力推导可用的入金方式，因此账户设置只会提供客户有权使用的方式。请参阅[账户](/cn/integration/accounts)。
- RFI 表单现在使用更简短、清晰的提示收集符合条件的受益所有人，RFI 历史则以生命周期里程碑的形式显示。请参阅[文档要求](/cn/knowledge-base/business-onboarding/document-requirements)。
- 没有明确截止日期的未完成任务现在默认将 `dueAt` 设为创建后 31 天。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。

### 移除
- 添加新的入金方式时，商户面板不再提供 Fedwire。现有 Fedwire 账户仍可读取。请参阅[账户](/cn/integration/accounts)。

### 修复
- 未预告的 USDT 入金到客户钱包现在会被识别并结算，而不是被忽略。
- 您已提交的证明材料现在会沿用到需要同一项目的其他任务，因此不会向客户重复索要同一份文档。
- 重新请求能力不再丢弃已就绪的银行通道，因此已签发的账户详情保持稳定。
- 商户面板中的银行指令视图现在显示完整详情，包括 SWIFT 地址和目标钱包地址。
- RFI 表单现在会显示提交校验错误、在提交前校验法律形式描述，并接受多个企业网站。
- 您现在可以在提交前编辑 RFI 表单中的关联方草稿。
- 已取消的合规请求不再出现在商户面板任务列表中。
- 文档审核状态在商户面板中再次正确显示。

## 2026-08-24

**版本：** v3

### 新增
- 客户范围内托管的验证和服务条款会话现在包含权威的 `action` 对象。请遵循其 `available` 或 `unavailable` 类型；对于可用操作，顶层的 `url` 和 `expiresAt` 字段继续作为兼容性镜像。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 沙盒钱包充值现在返回可通过 `GET /v3/transfers/{transferId}` 读取或通过 `GET /v3/transfers` 列出的转账 ID。它们显示为已完成的稳定币入金。请参阅[在沙盒中测试](/cn/integration/sandbox)。
- 当转账完成后其资金被退回或冲正时，转账读取会包含 `correction` 对象。它会报告更正的 `kind`、规范化的 `providerStatus`、任何 `providerShortfall`，以及 Swipelux 采取的 `compensatingIntent`。请参阅[报价与转账](/cn/integration/quotes-and-transfers)。

### 变更
- 商户面板中用于银行卡和 Apple Pay 的 **First pay-in** 引导现在要求客户拥有 Polygon 钱包。请先创建该钱包，再开始引导。请参阅[账户](/cn/integration/accounts)。
- 新请求和公开响应使用 `sepa` 作为规范的方法和能力名称。`sepa_instant` 输入别名及以前存储的资源仍然兼容，但公开响应使用 `sepa`。请参阅[账户](/cn/integration/accounts)。
- 新的 Faster Payments 能力、发行账户和报价请求已不可用。现有账户、报价和转账仍可读取。请参阅[账户](/cn/integration/accounts)。
- KYB 第一页不再收集代表的出生日期。股东出生日期仍是独立要求。请参阅[KYB 工作流程](/cn/knowledge-base/business-onboarding/kyb-workflow)。
- RFI 文档引用现在除 `image/jpeg` 外还接受 MIME 别名 `image/jpg`。请参阅[文档要求](/cn/knowledge-base/business-onboarding/document-requirements)。
- 商户面板中的任务历史现在显示不含修订计数器的易读审计记录。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 报价和转账现在会在任何资金流动之前检查能力支持的方向。在能力不支持的方向上使用该能力会返回 `422 capability_direction_unsupported`，钱包之间的资金转移需要 `stablecoin_transfers` 能力。请参阅[错误与重试](/integration/errors#capability-direction-unsupported)。

### 移除
- 商户面板不再提供新的 UAEFTS 账户设置。现有 UAEFTS 账户仍可读取。请参阅[账户](/cn/integration/accounts)。

### 修复
- 审核人员添加新的文档上传项时，RFI 表单会保留现有输入，因此重新提交时不会丢失之前的回答。
- 商户面板可从可用操作继续托管的合规会话，而不会丢弃有效链接。
- 托管的服务条款链接现在适用于 API 返回的所有任务范围。
- 在商户面板中请求 Payment Access 后，面板会打开该请求返回的受理任务，而不是先前请求中的任务。
- 商户面板的 KYB 演示现在会要求填写当前必填字段。
- 当报价将其来源钱包重新用作 `destinationId` 时，现在会在启动任何提供商操作前返回可操作的 `422 quote_direction_invalid` 详情。请参阅[报价与转账](/cn/integration/quotes-and-transfers)。
- API 现在会对格式错误的查询字符串编码返回 `400`，而不是静默规范化请求。请参阅[错误与重试](/integration/errors)。
- `POST /v3/customers/{customerId}/documents` 现在会对空、非 multipart 或格式错误的请求体返回 `400`。

## 2026-08-17

**版本：** v3

### 新增
- 在 OpenAPI 规范中发布了 v3 Problem Details 目录，集成方可直接从架构中映射错误响应。参见 [错误](/integration/errors)。
- 在 v3 账户 webhook 事件中新增了 `customerId`，让您无需再进行一次读取即可将账户活动与其所属客户关联。参见 [Webhook](/cn/integration/webhooks)。

- 发布了 v3 的开发者迁移指南。参见 [迁移到 v3](/cn/api-reference/versioning/migrate-to-v3)。

### 变更
- 客户与账户的国家/地区代码在写入时现按已分配的 ISO 3166-1 alpha-2 值进行校验。读取时兼容遗留的存储值，因此现有记录仍可解析。参见 [账户与钱包](/cn/integration/accounts)。
- USDC 可用性现按目的网络进行限定，因此报价与转账仅在目的地实际支持的网络上提供 USDC。
- 现在每个入驻流程都需要同意 Swipelux 服务条款。现有会话仍可继续。参见 [客户](/cn/integration/onboarding/customers)。
- `Capability.ready` 仍然表示权限已获批准。使用 `accountProvisioning` 跟踪账户签发状态：`not_applicable`、`not_started`、`in_progress`、`issued` 或 `failed`。参见 [能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 现已支持从 iPhone 上传 HEIC 作为身份和地址证明文件。
- 清除未完成任务仍需要的客户或关联方字段现在会返回 `409 field_required_by_open_task`，并附带造成阻塞的 `taskId` 和 `fields`，而不是可重试的冲突。请先完成或取消该任务，再更改这些字段。参见 [错误与重试](/integration/errors#field-required-by-open-task)。

### 修复
- 重新执行已消费的报价现返回 `409 quote_execution_consumed`，而不是通用错误。参见 [报价与转账](/cn/integration/quotes-and-transfers)。
- 大规模历史结果下的转账列表读取与报价金额读取不再出现 `500`。
- 并发的 KYC 重定向现在返回冲突而不是 `404`，因此重试可以顺利完成。托管重定向不再中途回滚，KYC 链接仍可继续使用。
- 个人客户的关联方读取不再返回 `404`。
- 含有无效钱包字段的 KYB 提交会在提交前被拒绝，且失败的同步不再在商户面板中显示为成功。
- 商户面板中的要求任务现在会将已提交的回答显示为已完成，单独跟踪条款操作，去除重复的文档文本，将已开始的 KYC 会话在完成前保持为待处理，并且在处理过期任务时不会破坏需求视图。
- 商户面板中的验证链接行现在每行都显示 **Open** 操作，每个任务链接都会在需求视图中渲染。
