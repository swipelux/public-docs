## 2026-08-24

**版本：** v3

### 新增
- 客户范围内托管的验证和服务条款会话现在包含权威的 `action` 对象。请遵循其 `available` 或 `unavailable` 类型；对于可用操作，顶层的 `url` 和 `expiresAt` 字段继续作为兼容性镜像。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 沙盒钱包充值现在返回可通过 `GET /v3/transfers/{transferId}` 读取或通过 `GET /v3/transfers` 列出的转账 ID。它们显示为已完成的稳定币入金。请参阅[在沙盒中测试](/cn/integration/sandbox)。

### 变更
- 商户面板中用于银行卡和 Apple Pay 的 **First pay-in** 引导现在要求客户拥有 Polygon 钱包。请先创建该钱包，再开始引导。请参阅[账户](/cn/integration/accounts)。
- 新请求和公开响应使用 `sepa` 作为规范的方法和能力名称。`sepa_instant` 输入别名及以前存储的资源仍然兼容，但公开响应使用 `sepa`。请参阅[账户](/cn/integration/accounts)。
- 新的 Faster Payments 能力、发行账户和报价请求已不可用。现有账户、报价和转账仍可读取。请参阅[账户](/cn/integration/accounts)。
- KYB 第一页不再收集代表的出生日期。股东出生日期仍是独立要求。请参阅[KYB 工作流程](/cn/knowledge-base/business-onboarding/kyb-workflow)。
- RFI 文档引用现在除 `image/jpeg` 外还接受 MIME 别名 `image/jpg`。请参阅[文档要求](/cn/knowledge-base/business-onboarding/document-requirements)。
- 商户面板中的任务历史现在显示不含修订计数器的易读审计记录。请参阅[能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。

### 移除
- 商户面板不再提供新的 UAEFTS 账户设置。现有 UAEFTS 账户仍可读取。请参阅[账户](/cn/integration/accounts)。

### 修复
- 审核人员添加新的文档上传项时，RFI 表单会保留现有输入，因此重新提交时不会丢失之前的回答。
- 商户面板可从可用操作继续托管的合规会话，而不会丢弃有效链接。
- 托管的服务条款链接现在适用于 API 返回的所有任务范围。
- 在商户面板中请求 Payment Access 后，面板会打开该请求返回的受理任务，而不是先前请求中的任务。
- 商户面板的 KYB 演示现在会要求填写当前必填字段。
- 当报价将其来源钱包重新用作 `destinationId` 时，现在会在启动任何提供商操作前返回可操作的 `422 quote_direction_invalid` 详情。请参阅[报价与转账](/cn/integration/quotes-and-transfers)。
- API 现在会对格式错误的查询字符串编码返回 `400`，而不是静默规范化请求。请参阅[错误与重试](/cn/integration/errors)。
- `POST /v3/customers/{customerId}/documents` 现在会对空、非 multipart 或格式错误的请求体返回 `400`。

## 2026-08-17

**版本：** v3

### 新增
- 在 OpenAPI 规范中发布了 v3 Problem Details 目录，集成方可直接从架构中映射错误响应。参见 [错误](/cn/integration/errors)。
- 在 v3 账户 webhook 事件中新增了 `customerId`，让您无需再进行一次读取即可将账户活动与其所属客户关联。参见 [Webhook](/cn/integration/webhooks)。
- 商户面板中完整覆盖 V3 个人档案字段，入驻操作员可查看并编辑通过 v3 API 收集的每个 KYC 字段。参见 [客户](/cn/integration/onboarding/customers)。
- 发布了 v3 的开发者迁移指南。参见 [迁移到 v3](/cn/api-reference/versioning/migrate-to-v3)。

### 变更
- 客户与账户的国家/地区代码在写入时现按已分配的 ISO 3166-1 alpha-2 值进行校验。读取时兼容遗留的存储值，因此现有记录仍可解析。参见 [账户与钱包](/cn/integration/accounts)。
- 的 USDC 可用性现按目的网络进行限定，因此报价与转账仅在目的地实际支持的网络上提供 USDC。
- 现在每个入驻流程都需要同意 Swipelux 服务条款。现有会话仍可继续。参见 [客户](/cn/integration/onboarding/customers)。
- `Capability.ready` 仍然表示权限已获批准。使用 `accountProvisioning` 跟踪账户签发状态：`not_applicable`、`not_started`、`in_progress`、`issued` 或 `failed`。参见 [能力与要求](/cn/integration/onboarding/capabilities-and-requirements)。
- 现已支持从 iPhone 上传 HEIC 作为身份和地址证明文件。

### 修复
- 重新执行已消费的报价现返回 `409 quote_execution_consumed`，而不是通用错误。参见 [报价与转账](/cn/integration/quotes-and-transfers)。
- 大规模历史结果下的转账列表读取与报价金额读取不再出现 `500`。
- 并发的 KYC 重定向现在返回冲突而不是 `404`，因此重试可以顺利完成。托管重定向不再中途回滚，KYC 链接仍可继续使用。
- 个人客户的关联方读取不再返回 `404`。
- 含有无效钱包字段的 KYB 提交会在提交前被拒绝，且失败的同步不再在商户面板中显示为成功。
- 商户面板中的要求任务现在会将已提交的回答显示为已完成，单独跟踪条款操作，去除重复的文档文本，将已开始的 KYC 会话在完成前保持为待处理，并且在处理过期任务时不会破坏需求视图。
- 商户面板中的验证链接行现在每行都显示 **Open** 操作，每个任务链接都会在需求视图中渲染。
