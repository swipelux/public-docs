title: "客户"
description: "创建拥有能力、账户和转账的个人或企业。"
---

在构建入金、出金或发行的银行账户之前,先创建客户。能力、账户和转账都属于该客户的范围。请使用 `externalId` 作为与您系统中对应记录之间的稳定映射。

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## 个人客户 {#individual-customers}

个人客户只需要 `type`。请包含您已经掌握的资料字段,只有在当前的能力或任务需要时,才添加更多字段。

使用 [`POST /v3/customers`](/api-reference/customers/post-v3-customers) 创建客户:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

将返回的 `data.id` 保存为 `CUSTOMER_ID`。政策背景请参阅[个人入驻](/cn/knowledge-base/individual-onboarding/overview)。

## 企业客户 {#business-customers}

企业客户需要 `business.legalName`。使用同一个操作创建企业:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

将返回的 `data.id` 保存为 `CUSTOMER_ID`。政策和材料背景请参阅[企业入驻](/cn/knowledge-base/business-onboarding/overview)。

## 添加企业相关人员

在已知或被要求时,添加董事、股东和其他企业参与人员。以下示例使用 [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) 创建一位董事:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

将返回的 `data.id` 保存为 `RELATED_PARTY_ID`。

## 导出客户数据 {#export-customer-data}

使用 [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) 下载某个客户,或将已通过审核的 KYC 数据移交给你自己的 Sumsub 项目。每次导出都需要一个 `Idempotency-Key`;使用相同的密钥和请求体重放会得到相同的结果。

在请求体中选择格式。

<Tabs>
  <Tab title="基础资料 JSON">

以 JSON 附件形式返回公开的 v3 客户资源,包含资料、地址、税务、元数据以及相关方数据。不包含文档及文档元数据。

```json
{
  "format": "json_basic_data"
}
```

  </Tab>
  <Tab title="Sumsub 共享令牌">

为已通过审核的个人客户创建一个一次性 Sumsub 共享令牌,以便接收方的 Sumsub 项目可以导入其 KYC 数据。企业客户会返回 `422 invalid_field_for_type`。

```json
{
  "format": "sumsub_share_token",
  "forClientId": "partner-sumsub-client-id"
}
```

`forClientId` 是你的 Sumsub `clientId`,而不是 Swipelux 的 `customerId`。它标识将接收申请人数据的 Sumsub 项目,因此该值由你自行决定。

响应会返回 `provider`、`token` 和 `expiresAt`(Unix 秒):

```json
{
  "data": {
    "provider": "sumsub",
    "token": "_shr-...",
    "expiresAt": 1800000000
  }
}
```

在 `expiresAt` 之前,将 `token` 传给 Sumsub 的共享令牌导入 API,用于由 `forClientId` 标识的项目。仅可使用一次。如需重新签发,请使用新的 `Idempotency-Key` 再次调用导出。

  </Tab>
</Tabs>

## 通过能力读取就绪状态

客户在 API 中并没有验证或就绪状态。请使用 [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) 读取客户当前的资料数据,然后基于能力及其 `openTaskIds` 来判断该客户下一步可以做什么。

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```
