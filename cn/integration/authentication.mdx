请将每一个 Swipelux API 密钥都保存在受保护的后端。切勿将密钥放入浏览器代码、移动应用打包产物,或客户端可见的配置文件中。

## 发送您的 API 密钥

使用共享的基础地址 `https://platform.swipelux.com`,并在 `X-API-Key` 请求头中发送您的密钥。

```bash Verify your API key
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'

curl --request GET \
  "${API_BASE}/v3/capabilities" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

[`GET /v3/capabilities`](/api-reference/capabilities/get-v3-capabilities) 可用于确认该密钥有效,并且您的后端能够访问该 API。

## 沙盒与生产环境

沙盒和生产环境使用同一个 API 主机。由 API 密钥来选择环境。

请在部署配置中固定环境选择。生产环境的部署绝不能回退使用沙盒密钥,沙盒部署也绝不能使用生产环境的凭证。

## 密钥作用范围 {#key-scope}

每个 API 密钥只能操作其所属环境和开发者空间中的客户及其账户。在客户相关路由上，超出该范围的客户会返回 `404 customer_not_found`。在报价中，超出范围的客户或来源会返回 `404 not_found`。

沙盒密钥无法转移生产环境资金：指定生产环境账户或目的地的报价会返回 `404 not_found`，与未知 ID 的结果相同。当目的地账户属于其他商户，或者在使用沙盒密钥时目的地账户是生产环境账户，钱包资金转移报价会返回带有 `Destination was not found.` 的 `404 not_found`。

请将资源 ID 与创建它们的环境和空间一起存储。之后针对这些资源的每个请求都请使用对应的密钥。

## 安全存储凭证

请将沙盒与生产环境的密钥存放在不同的密钥管理条目中。每个后端部署仅授予它所需的那一个条目的访问权限。

请勿将密钥保留在源代码库、日志、分析系统、支持截图或错误响应中。如果您认为密钥可能已经泄露,请立即轮换该密钥。

如果请求返回 `unauthorized` 或 `forbidden`,请使用[错误与重试](/integration/errors)来区分是凭证无效还是权限缺失。
