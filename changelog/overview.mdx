<Update label="August 10, 2026">

## New

**Refund recovery details in the transaction history**
When a refund triggers a recovery adjustment, the transaction detail panel now shows the recovery amount, status, and audit trail alongside the original transfer. Merchant fee lines display the exact charged amount so reconciliation matches the payload. See [Receive funds](/integration/receive-funds).

**Additional supporting documents for individual customers**
Customer requests now include a documents step for individual customers, and the business flow accepts additional supporting documents beyond the identity set. Identity types and empty finalize submissions are rejected. See [Individual onboarding API workflow](/knowledge-base/individual-onboarding/api-workflow).

**Documents live inside the customer profile**
The Documents tab has been merged into the Profile tab in the customer view. Submitted merchants now land on the customer documents section by default, and the standalone route redirects to the new location.

**Sandbox KYC verification screen**
Sandbox merchants can now render and complete a first-party KYC verification page end-to-end, including the Align completion boundary. Use it to rehearse the full onboarding flow without a real provider. See [Sandbox](/integration/sandbox).

## Updates

**Pooled ACH available in the V3 payin rail matrix**
Align `ach_pooled` is now bound directly in the V3 provider rail matrix, so quotes routed to Align pooled ACH complete instead of falling back or failing. Pooled ACH requests now also require an account purpose. See [Quotes and transfers](/integration/quotes-and-transfers).

**Stricter bank account format validation**
Accounts are now checked for ABA and SWIFT/BIC format compliance before being marked ready. Malformed identifiers are rejected upfront rather than surfacing failures at settlement. See [Accounts](/integration/accounts).

**Unified intake tasks for onboarding**
V3 now publishes a purpose-based task taxonomy and a unified intake shape, with a single intake task authored per capability subject. Missing obligations are cross-healed automatically when a capability opens. See [Capabilities and requirements](/integration/onboarding/capabilities-and-requirements).

**Hosted terms bundled in Align hosted links**
Hosted Align links now include the Terms of Service in-line, so customers accept terms as part of the hosted flow rather than through a separate journey. Provider session keys are no longer exposed in the hosted URL.

**Customer external ID constraints published**
The public contract now documents the constraints on `externalId` for customers, so integrations validate identifiers up front. See the [API reference](/api-reference/introduction).

**Import external accounts renamed to "Payout"**
The dashboard now uses "Payout" wording throughout for imported external destinations, replacing the older "import external wallet/account" labels. The import-external entry point also returns on the empty state when a customer has no bank accounts.

## Fixes

**Onboarding tasks load again after completion policy change**
Tasks with `null` or leaf completion policies no longer break the task loader in the merchant dashboard. Every task now loads correctly.

**Profile RFI submissions unblocked**
Compliance profile RFI submissions now go through, and residence-country answers are accepted where they were previously rejected.

**Accurate Balances copy for spaces without a business customer**
Balances no longer tells fully approved merchants to "finish business verification" when a space simply has no business-customer designation. The `no_link` case is distinguished from KYB-not-passed.

**KYB document uploads accept blank-MIME files**
KYB and wallet document uploads now validate and retype files with a missing MIME, and report client-side rejections back to the merchant instead of failing silently. Autosave session failures during KYB are also now surfaced.

**Accounts list matches account detail**
The V3 accounts list now returns one row per account, matching what `GET /accounts/{accountId}` returns. Duplicate rows caused by multiple readers hitting the same account are collapsed. See [Accounts](/integration/accounts).

**Archived resources handled cleanly**
Archived customer tasks no longer expose detail responses, and archived recipients now reject updates with a clear terminal state.

**Webhook acknowledgments accept empty bodies**
Successful webhook responses with empty bodies are now accepted, and optional acknowledgments are modeled explicitly. See [Webhooks](/integration/webhooks).

**Quote failures return typed error classes**
Provider quote failures now surface as typed causes with preserved legacy error messages, so integrations can distinguish transient, validation, and routing errors without brittle string matching. See [Quotes and transfers](/integration/quotes-and-transfers).

**1Money provider retired**
1Money execution paths (scheduler jobs, payin and intermediary schedules, webhooks, and balance collection) have been removed. Read paths remain for historical data. Live routing no longer selects 1Money.
