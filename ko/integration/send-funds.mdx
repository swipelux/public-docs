모든 페이아웃은 준비되고 충전된 발급 지갑에서 시작해요. 목적지 모델은 엔드포인트를 누가 소유하는지에 따라 달라져요.

```mermaid
flowchart TD
  A["Funded issued wallet"] --> B{"Who owns the endpoint?"}
  B -->|"Customer"| C["Customer account acc_..."]
  B -->|"Another person or business"| D["Recipient destination dst_..."]
  C --> E["Create quote"]
  D --> E
  E --> F["Execute and track transfer"]
```

## 시작 전에

출처 지갑을 다시 조회하세요. 현재 상태가 페이아웃을 허용하고 가용 잔액이 의도한 출처 금액을 감당하는지 확인하세요. 응답에서 파생된 ID를 `SOURCE_WALLET_ID`로 저장하세요.

또한 현재 고객과 선택한 목적지에 대해 준비된 페이아웃 케이퍼빌리티가 필요해요.

기존 Tron 지갑은 `stablecoin_transfers` 견적으로 다른 Tron 지갑에 USDT를 보낼 수 있어요. 입력과 출력은 동일한 네트워크와 스테이블코인을 사용해야 해요. Tron에서는 새 발급 지갑을 생성할 수 없어요.

## 2. 페이아웃 견적 생성

다음 헤더로 [`POST /v3/quotes`](/api-reference/money-movement/post-v3-quotes)를 사용하세요:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-quote-001
Content-Type: application/json
```

```json
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "in": {
    "amount": "150.00",
    "currency": "USDC",
    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${PAYOUT_DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }
}
```

`data.id`를 `QUOTE_ID`로 저장하고 반환된 가격과 수수료를 표시하세요.

### 은행 경로 선택 {#choose-a-bank-route}

암호화폐에서 법정화폐로의 페이아웃에서는 선택 사항인 `institutionId`를 설정해 고객에 대해 승인된 은행 경로를 요구할 수 있어요. 자동 라우팅을 사용하려면 생략하세요.

```json
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "institutionId": "${INSTITUTION_ID}",
  "in": {
    "amount": "150.00",
    "currency": "USDC",
    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${PAYOUT_DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }
}
```

- 명시적인 `institutionId`는 다른 은행으로 대체되지 않아요. 선택한 은행에 이 고객, 케이퍼빌리티, 목적지에 대해 준비된 경로가 없으면 `POST /v3/quotes`는 포인터 `/institutionId`와 함께 `422` [`bank_not_supported_for_customer`](/integration/errors#bank-not-supported-for-customer)를 반환해요.
- `institutionId`는 암호화폐에서 법정화폐로의 페이아웃 견적에서만 유효해요. 페이인, 카드 또는 스테이블코인 전송 견적에 보내면 `400` [`validation_error`](/integration/errors#validation-error)가 반환돼요.
- 견적 및 전송 조회는 은행을 식별할 수 있는 경우 자동으로 선택된 경로를 포함해 선택된 경로의 `institutionId`를 그대로 반환해요.

### SWIFT 페이아웃 {#swift-payouts}

프로덕션에서 USD SWIFT 페이아웃에는 페이아웃을 지원하는 준비된 SWIFT 케이퍼빌리티(`swift_pooled` 또는 `swift_named`)가 필요하며, Ethereum, Base, Polygon의 USDC 또는 Ethereum, Polygon의 USDT로 자금이 조달돼야 해요. 수수료 차감 후 수취 금액은 최소 100.00 USD여야 해요.

SWIFT 목적지에는 `bankAddress`, `bankCity`, `bankState`, `bankPostalCode`에 은행의 도로명 주소가 필요해요. BIC 국가는 은행 국가와 일치해야 해요. Swipelux는 수혜자 주소를 고객 또는 수취인 프로필에서 가져와요.

## 3. 페이아웃 실행

[`POST /v3/transfers`](/api-reference/money-movement/post-v3-transfers)로 전송을 생성하세요. 의도한 이 실행에 새 키 하나를 사용하세요:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-transfer-001
Content-Type: application/json
```

```json
{
  "quoteId": "${QUOTE_ID}"
}
```

전송의 `data.id`를 `TRANSFER_ID`로 저장하세요. 성공적인 생성은 페이아웃을 시작해요. 전달을 증명하지는 않아요.

## 4. 전달 추적

생성 후 그리고 각 이벤트 이후에 [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id)를 조회하세요. 최신 `data.state`, `data.stateDetail`, `data.openTaskIds`를 사용해 대기할지, 조치할지, 종료 결과를 표시할지 결정하세요.

다음으로 정확한 금액, 안전한 실행 복구, 전송 태스크에 대해 [견적과 전송](/ko/integration/quotes-and-transfers)을 검토하세요.
