모든 Swipelux API 키를 보호된 백엔드에 보관하세요. 브라우저 코드, 모바일 애플리케이션 번들, 클라이언트가 볼 수 있는 구성 파일에 키를 절대 두지 마세요.

## API 키 전송

공유 기본 URL `https://platform.swipelux.com`을 사용하고 `X-API-Key` 헤더에 키를 실어 보내세요.

```bash Verify your API key
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'

curl --request GET \
  "${API_BASE}/v3/capabilities" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

[`GET /v3/capabilities`](/api-reference/capabilities/get-v3-capabilities)는 키가 유효하고 백엔드가 API에 도달할 수 있음을 확인해 줘요.

## 샌드박스와 프로덕션

샌드박스와 프로덕션은 동일한 API 호스트를 사용해요. API 키가 환경을 선택해요.

환경 선택은 배포 구성에 두세요. 프로덕션 배포는 절대로 샌드박스 키로 폴백해서는 안 되며, 샌드박스 배포는 절대로 프로덕션 자격 증명을 받아서는 안 돼요.

## 키 범위 {#key-scope}

각 API 키는 자체 환경과 개발자 스페이스에 있는 고객 및 그 계좌에서 작동해요. 고객 경로에서는 해당 범위 밖의 고객이 `404 customer_not_found`를 반환해요. 견적에서는 범위 밖의 고객이나 출처가 `404 not_found`를 반환해요.

샌드박스 키로는 라이브 자금을 이동할 수 없어요. 라이브 계좌나 목적지를 지정한 견적은 알 수 없는 ID와 마찬가지로 `404 not_found`를 반환해요. 지갑 간 이동 견적은 목적지 계좌가 다른 머천트에 속하거나, 샌드박스 키의 경우 라이브 계좌이면 `Destination was not found.`와 함께 `404 not_found`를 반환해요.

리소스 ID를 해당 리소스를 생성한 환경 및 스페이스와 함께 저장하세요. 이후 해당 리소스에 대한 모든 요청에는 일치하는 키를 사용하세요.

## 자격 증명을 안전하게 저장

샌드박스와 프로덕션 키를 별도의 시크릿 매니저 항목에 저장하세요. 각 백엔드 배포에는 필요한 항목에만 접근을 부여하세요.

키를 소스 컨트롤, 로그, 애널리틱스, 지원용 스크린샷, 오류 응답에서 배제하세요. 노출된 것으로 의심되면 키를 순환시키세요.

요청이 `unauthorized` 또는 `forbidden`을 반환하면 [오류 및 재시도](/integration/errors)를 사용해 유효하지 않은 자격 증명과 누락된 권한을 구분하세요.

다음으로, [샌드박스 테스트를 구성](/ko/integration/sandbox)하거나 [퀵스타트](/ko/integration/quickstart)를 시작하세요.
