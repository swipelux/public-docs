고객이 엔드포인트를 소유할 때는 고객 계좌를 사용하세요. 다른 사람이나 기업이 자금을 받을 때는 수취인과 목적지를 사용하세요.

수취인은 자금을 받는 대상을 기록해요. 목적지는 그들이 어디에서 받는지 기록해요.

## 1. 수취인 생성

[`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients)로 개인 또는 기업을 생성하세요. 다음 헤더를 보내세요:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-create-001
Content-Type: application/json
```

```json
{
  "type": "individual",
  "relationship": "contractor",
  "firstName": "Jason",
  "lastName": "Swipelux",
  "email": "jason@swipelux.com",
  "phone": "+14155551234",
  "address": {
    "streetLine1": "1 Market Street",
    "city": "San Francisco",
    "state": "CA",
    "postalCode": "94105",
    "country": "US"
  },
  "label": "Jason contractor"
}
```

`relationship`은 수취인이 귀하의 고객과 어떤 관계인지 설명해요. `employee`, `contractor`, `vendor`, `subsidiary`, `merchant`, `customer`, `landlord`, `family`, `other` 중 하나를 보내세요. 이 필드는 이 값들만 받아요; `other`와 함께 사용하는 자유 서술 설명은 없어요.

법정화폐 목적지를 생성하기 전에 주소를 포함하세요. 반환된 수취인 `data.id`를 `RECIPIENT_ID`로 저장하고 현재 상태를 유지하세요.

## 2. 목적지 추가

[`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations)로 엔드포인트를 생성하세요. 의도한 이 목적지에 새 키를 사용하세요:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-destination-create-001
Content-Type: application/json
```

<Tabs>
  <Tab title="은행 목적지">

```json
{
  "type": "ach",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "Example Bank",
    "accountHolderName": "Jason Swipelux",
    "country": "US"
  }
}
```

  </Tab>
  <Tab title="지갑 목적지">

```json
{
  "type": "wallet",
  "currency": "USDC",
  "ownership": {
    "type": "self_custodied"
  },
  "details": {
    "network": "base",
    "address": "0x1111111111111111111111111111111111111111"
  }
}
```

  </Tab>
</Tabs>

수취인이 지갑을 통제할 때만 `self_custodied`를 사용하세요. 지갑이 다른 커스터디에 의해 보유될 경우 현재 API 레퍼런스 변형을 따르세요.

반환된 목적지 `data.id`를 `DESTINATION_ID`로 저장하고 현재 상태를 유지하세요.

## 3. 목적지 준비 상태 대기

견적을 생성하기 전에 [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id)를 조회하세요.

현재 목적지 상태가 페이아웃을 허용하고, 그 통화, 방법, 네트워크가 의도한 이동과 일치할 때만 계속 진행하세요. 수취인과 목적지 상태는 독립적이에요.

페이아웃 견적에 `dst_` 목적지 ID를 사용하세요. `rcp_` 수취인 ID는 소유자 레코드를 식별하며, 견적 목적지가 아니에요.

다음으로, 준비된 목적지를 [자금 지급](/ko/integration/send-funds)으로 가져가세요.
