---

샌드박스는 프로덕션과 동일한 API 호스트를 사용해요. 샌드박스 API 키가 테스트 환경을 선택하며, 헬퍼가 실제 자금을 이동시키지 않고 결과를 시뮬레이션해요.

키는 백엔드에 보관하세요. 샌드박스 헬퍼는 프로덕션 컴플라이언스나 온보딩을 대체하지 않아요.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

## 케이퍼빌리티 준비 상태 테스트

케이퍼빌리티를 요청한 후 [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status)로 샌드박스 상태를 설정하세요:

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"status":"ready"}'
```

헬퍼를 사용한 후에는 케이퍼빌리티를 다시 조회하세요. 현재 `status`와 `openTaskIds`를 제품이 처리해야 하는 결과로 다루세요.

## 열린 태스크 테스트

[`POST /v3/sandbox/tasks`](/api-reference/sandbox/post-v3-sandbox-tasks)로 샌드박스 태스크를 생성하세요. 테스트할 워크플로우의 리소스로 범위를 지정하고 `items`로 고객이 제출해야 할 내용을 설명하세요. 이 가이드는 capability 및 transfer 워크플로우를 보여 줘요. customer 스코프와 전체 요청 스키마는 API Reference에서 확인하세요.

텍스트 답변에는 `explanation` 항목을, 파일 업로드에는 `document` 항목을 사용하세요. 새 `profile` 항목에는 고객 필드를 지정하는 JSON Pointer인 `profilePointer`도 필요해요. 다른 항목 타입과 필드는 [샌드박스 태스크 생성](/api-reference/sandbox/post-v3-sandbox-tasks)을 참고하세요.

transfer 예시에서는 먼저 [입금](/ko/integration/receive-funds) 또는 [지급](/ko/integration/send-funds) 플로우로 샌드박스 transfer를 생성한 다음, 반환된 `data.id`를 내보내세요:

```bash
export TRANSFER_ID='tr_replace_with_your_transfer_id'
```

<Tabs>
  <Tab title="케이퍼빌리티 + explanation">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "capability",
    "customerId": "${CUSTOMER_ID}",
    "capabilityId": "${CAPABILITY_ID}"
  },
  "items": [
    {
      "type": "explanation",
      "request": "Explain the source of funds."
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="전송 RFI + document">

검토 중인 전송으로 태스크의 범위를 지정하고, 허용되는 유형, 형식, 유효 기간을 좁히는 `constraints`와 함께 document를 요청하세요.

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "transfer",
    "customerId": "${CUSTOMER_ID}",
    "transferId": "${TRANSFER_ID}"
  },
  "category": "transaction_rfi",
  "items": [
    {
      "type": "document",
      "request": "Upload a bank statement showing the source of funds for this transfer.",
      "constraints": {
        "acceptedDocumentTypes": ["bank_statement"],
        "acceptedFormats": ["pdf", "jpeg"],
        "maxAgeDays": 90
      }
    }
  ]
}
JSON
```

이 예시는 허용되는 문서 타입, 형식, 유효 기간을 제한해요. 지원되는 모든 문서 제약 조건은 [샌드박스 태스크 생성](/api-reference/sandbox/post-v3-sandbox-tasks)을 참고하세요.

  </Tab>
</Tabs>

`data.id`를 `TASK_ID`, `data.revision`을 `TASK_REVISION`, 현재 `data.requirements[0].id`를 `REQUIREMENT_ID`로 저장하세요. [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission)를 호출할 때는 생성한 항목 타입에 답변을 맞추세요:

<Tabs>
  <Tab title="설명 답변">

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "text",
        "value": "Sandbox requirement completed."
      }
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="문서 답변">

[`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents)로 조건에 맞는 파일을 업로드하고, 반환된 `data.id`를 `DOCUMENT_ID`로 저장한 다음 문서 답변으로 제출하세요:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-document-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "document",
        "documentIds": ["${DOCUMENT_ID}"]
      }
    }
  ]
}
JSON
```

  </Tab>
</Tabs>

그런 다음 [`POST /v3/sandbox/tasks/{taskId}/review`](/api-reference/sandbox/post-v3-sandbox-tasks-by-task-id-review)로 현재 제출을 승인하거나 거부하세요:

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks/${TASK_ID}/review" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"outcome":"accepted"}'
```

프로덕션 태스크 완료 패턴은 [케이퍼빌리티와 태스크](/ko/integration/onboarding/capabilities-and-requirements)를 참고하세요.

## 샌드박스 지갑 충전

[`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup)로 발급 지갑에 크레딧을 적립하세요:

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${ACCOUNT_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"amount":"250.00","currency":"USDC"}'
```

시뮬레이션된 자금 조달 전송을 확인하려면 반환된 `data.id`를 `TRANSFER_ID`로 저장하세요.

topup id는 전송 id입니다. [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id)로 조회하거나 [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers)로 나열하여 인바운드 입금 코드 경로를 샌드박스 topup으로 시험하세요. 전송 프로젝션은 `origin: "inbound_deposit"`, `method: "stablecoin_transfers"`, `direction: "stablecoin_move"`가 설정된 완료된 인바운드 스테이블코인 입금이며, 이에 대응하는 `accountId`, `origin`, `method`, `direction` 목록 필터로 반환됩니다.

## 전송 완료 또는 실패

[`POST /v3/sandbox/transfers/{transferId}/state`](/api-reference/sandbox/post-v3-sandbox-transfers-by-transfer-id-state)로 결과를 설정하세요:

<Tabs>
  <Tab title="완료">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"state":"completed"}'
```

  </Tab>
  <Tab title="실패">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "state": "failed",
  "stateDetail": {
    "code": "sandbox_review",
    "message": "Sandbox transfer failed."
  }
}
JSON
```

  </Tab>
</Tabs>
