## KYB 워크플로

KYB 워크플로는 현재 고객, 관계자, 케이퍼빌리티, 태스크, 제출, 문서 리소스를 기업과 그 소유권에 대한 정책 검토와 결합해요.

<Warning>
  KYB 결과와 타임라인은 정책 추정치예요. API 전환, 승인 또는 가용성을
  보장하지 않아요.
</Warning>

## 현재 워크플로 순서

### 1. 기업 고객 생성

[`POST /v3/customers`](/api-reference/customers/post-v3-customers)로 기업 고객을 생성하세요. [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id)로 현재 고객을 조회하세요.

### 2. 관계자 유지

현재 관계자를 검토하려면 [`GET /v3/customers/{customerId}/related-parties`](/api-reference/customers/get-v3-customers-by-customer-id-related-parties)를, 생성하려면 [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties)를, 제공된 사실을 업데이트하려면 [`PATCH /v3/customers/{customerId}/related-parties/{relatedPartyId}`](/api-reference/customers/patch-v3-customers-by-customer-id-related-parties-by-related-party-id)를 사용하세요.

현재 태스크가 요청하는 직접 소유자, 모기업, UBO, 통제 담당자, 이사, 임원, 서명자를 유지하세요. 그들의 역할은 뚜렷해요.

### 3. 자격 있는 케이퍼빌리티 발견 및 요청

[`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported)를 조회하세요. 고객이 자격 있을 때만 [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id)로 available 또는 beta 케이퍼빌리티를 요청하세요.

### 4. 현재 태스크 조회

[`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks)로 현재 작업을 나열하세요. [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task)를 통해 각 실행 가능한 태스크를 가져온 뒤, 현재 리비전, 요건, 세션에서 다음 조치를 도출하세요.

### 5. 현재 태스크가 요청한 문서 업로드

[`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents)로 요청된 파일을 업로드하세요. 현재 태스크가 문서가 필요한지 여부를 결정하고 수락되는 유형, 개수, 형식을 좁힐 수 있어요.

### 6. 완전한 태스크 답변 제출

[`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission)로 현재 태스크 리비전에 대한 완전한 답변 세트 하나를 제출하세요. 현재 requirement id를 사용하고 태스크가 요청하는 곳에서만 업로드된 document id를 참조하세요.

### 7. 현재 리소스 모니터링

모든 조치나 이벤트 후, [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id)로 고객을, [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id)로 케이퍼빌리티를, [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications)로 그 애플리케이션을, 그리고 현재 태스크를 다시 조회하세요.

전체 메커니즘은 [기업 온보딩](/ko/integration/onboarding/customers#business-customers), [케이퍼빌리티와 태스크](/ko/integration/onboarding/capabilities-and-requirements#complete-current-tasks), [통합 문서 가이드](/ko/integration/onboarding/capabilities-and-requirements#upload-documents)를 참고하세요.

## 강화된 실사 (EDD) 트리거

EDD가 필요할 수 있는 경우:

- 고위험 관할권
- 게이밍, 트레이딩, 크립토 거래소를 포함한 고위험 업종
- 복잡한 소유권 구조
- 적용 가능한 임계값을 초과하는 예상 월별 볼륨
- 제재 대상 국가와 관련된 운영

## 정책 검토 결과

**결과:** KYB 승인, 한도가 있는 조건부 승인, 또는 거부.

이것들은 정책 검토 결과이며 현재 API 상태 값이 아니에요. 조건부 정책 결정은 "conditional approval"이라는 상태를 만들지 않고도 현재 리소스를 통해 반영될 수 있어요.

## 검증 타임라인

| 단계 | 일반적인 소요 시간 |
| --- | --- |
| 문서 업로드 | 즉시 |
| 초기 검토 | 1-2 영업일 |
| 표준 KYB | 2-5 영업일 |
| EDD 발동 시 | 5-10 영업일 |

이 소요 시간은 일반적인 정책 추정치이며 보장된 API 동작이 아니에요.

## 일반적인 거부 사유

| 사유 | 해결 |
| --- | --- |
| 누락된 문서 | 현재 태스크가 요청한 모든 문서 유형을 제공하세요 |
| 불분명하거나 흐릿한 문서 | 더 높은 품질의 스캔이나 이미지를 제공하세요 |
| 일치하지 않는 정보 | 제출된 증거 전반에 걸쳐 법인 이름이 일치하는지 확인하세요 |
| 불완전한 소유권 구조 | 소유권의 100%를 반영하는 증거를 제공하세요 |
| 만료된 문서 | 현재 유효한 문서를 제공하세요 |

## 정책 용어와 API 상태

정책 결정을 현재 리소스 어휘와 분리해서 유지하세요:

- **케이퍼빌리티 상태:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **애플리케이션 상태:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **태스크 상태:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **제출 결과:** `in_review`, `accepted`, `changes_requested`, `rejected`

정책 결과를 API 값으로 번역하지 말고 최신 리소스를 조회하세요.
