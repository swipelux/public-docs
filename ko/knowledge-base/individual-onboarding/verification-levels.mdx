## KYC 검증 수준

Swipelux는 세 가지 정책 티어의 신원 검증을 사용해요. 적용 가능한 티어는 고객 리스크, 관할권, 예상 거래 볼륨, 규제 요건에 따라 달라져요.

<Warning>
  이 티어들은 현재 API enum이 아닌 정책 분류를 설명해요.
  현재 태스크가 특정 고객에 대한 요건을 결정해요.
</Warning>

## Simplified KYC

Simplified KYC는 승인된 저위험, 저가치 흐름에 사용돼요.

### 필수 정보

- 이름
- 성
- 생년월일

### 사용 시점

- 거래 금액이 적용 가능한 simplified 임계값 미만
- 고객이 저위험 관할권에 있음

## Standard KYC

Standard KYC는 정부 발급 문서와 셀피 또는 실물 확인으로 신원을 검증해요.

### 필수 문서

- 정부 발급 ID
- 셀피 또는 실물 확인

### 수락되는 ID 문서

- 여권
- 운전면허증
- 국가 신분증

## Enhanced KYC (강화된 실사)

Enhanced KYC는 고위험 시나리오를 위한 주소와 자금 증거를 추가해요.

### 필수 문서

- Standard KYC에 필요한 모든 것
- 주소 증명
- 자금 증명

### Enhanced KYC 트리거

- 거래 볼륨이 표준 임계값을 초과
- 고위험 관할권
- 리스크 평가에 기반한 컴플라이언스 팀 플래그
- 규제 요건

### 주소 증명 요건

| 문서 유형 | 요건 |
| --- | --- |
| Bank statement | 지난 90일 이내 발행 |
| Utility bill | 전기, 가스, 수도 또는 인터넷; 지난 90일 이내 발행 |
| Government-issued letter | 지난 90일 이내에 발행된 세무 통지 또는 공식 서신 |

### 자금 증명 요건

| 문서 유형 | 설명 |
| --- | --- |
| Bank statements | 충분한 잔액이나 소득을 보여주는 최근 명세서 |
| Pay stubs | 고용 소득 검증 |
| Tax returns | 연간 세금 문서 |
| Investment statements | 브로커리지 또는 은퇴 계좌 명세서 |

## 정책 티어와 현재 태스크

현재 태스크 세부 정보가 다음 API 조치의 정보 출처예요. 자사 호스팅 세션을 제공하거나, 제출을 통해 답변을 요청하거나, 문서 증거를 요청할 수 있어요.

새 개인 접수 태스크에서 호스팅된 신원 인증 세션은 `coveredRequirementIds`에 나열된 요건을 처리해요. 신분증, 셀피, 그리고 태스크에서 요구하는 경우 주소 증명이 포함돼요.

새 개인 접수 태스크에서는 호스팅된 세션에서 자금 증명을 수집하지 않아요. 태스크는 이를 문서 요건으로 요청해요. 문서를 업로드하고 태스크와 함께 제출한 다음 Swipelux의 검토를 기다리세요. Swipelux가 자금 증명을 승인할 때까지 태스크는 열린 상태로 유지돼요.

Swipelux의 신원 인증 제공업체에 있는 자체 계정에서 이미 고객을 인증했다면, 고객이 호스팅된 세션을 거치게 하는 대신 share token으로 해당 인증을 가져올 수 있어요. 가져오기는 `coveredRequirementIds`에 나열된 요건을 처리해요. 신분증, 셀피, 그리고 태스크에서 요구하는 경우 주소 증명이 포함돼요. Swipelux는 자체 요건을 기준으로 검사를 다시 실행해요. [기존 신원 인증 가져오기](/ko/integration/onboarding/capabilities-and-requirements#import-an-existing-identity-verification)를 참조하세요.

일부 강화된 검토의 경우, 컴플라이언스 팀이 고객의 등록된 이메일 주소로 연락할 수도 있어요. 이 연락은 정책 검토 조정으로 다루고, 현재 API 리소스 조회의 대체물로 다루지 마세요.
