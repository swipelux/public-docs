## 검증 상태와 워크플로

정책 관점의 KYC 여정은 정보 수집에서 검토를 거쳐 승인 또는 거부 결정으로 이동해요. 현재 API 리소스는 별도의 케이퍼빌리티, 애플리케이션, 태스크, 제출 라이프사이클을 노출해요.

<Warning>
  정책 검토 라벨과 타이밍 추정치는 API 동작을 정의하지 않아요. 아래
  라벨로 상태 머신을 구현하지 마세요.
</Warning>

## 정책 관점 검토 개념

이 정책 관점 검토 개념들은 온보딩 여정을 설명해요. 현재 API enum, 웹훅 값 또는 보장된 전환이 아니에요.

| 정책 라벨 | 의미 |
| --- | --- |
| `not_started` | 고객이 존재하지만 KYC 작업이 시작되지 않음 |
| `incomplete` | KYC 작업이 시작되었으나 필수 정보가 누락됨 |
| `pending_verification` | 검토가 고객 완료를 대기 중 |
| `under_review` | 제출된 정보 또는 문서가 검토 중 |
| `approved` | 정책 검토가 해당 흐름에 대해 고객을 승인함 |
| `rejected` | 정책 검토가 고객을 거부함 |

이 라벨은 정책 여정을 논의할 때만 사용하세요. 현재 생성된 스키마가 자체 컨텍스트에서 동일한 값을 명시적으로 요청하지 않는 한 현재 상태 값으로 전송하지 마세요.

## Standard KYC 검토 흐름

1. 개인 고객을 생성해요.
2. 자격 있는 케이퍼빌리티를 발견하고 요청해요.
3. 현재 태스크 세부 정보를 조회해요.
4. 고객을 자사 호스팅 검증 세션으로 보내거나 태스크가 요청한 완전한 태스크 답변을 제출해요.
5. 현재 리소스가 자체 검토 상태를 보고하는 동안 검토가 실행되도록 해요.
6. 더 많은 조치가 필요한지 또는 케이퍼빌리티가 ready, restricted, rejected 또는 canceled인지 결정하기 위해 현재 리소스를 다시 조회해요.

정책 여정은 이를 not started, pending verification, under review로 설명한 뒤 approved 또는 rejected로 설명할 수 있어요. 이 용어들은 API 전환 순서를 정의하지 않아요.

## Enhanced KYC 검토 흐름

1. 현재 요청된 표준 신원 및 실물 확인 작업을 완료하세요.
2. 강화된 검토가 추가 정보를 요청할 때 최신 태스크를 조회하세요.
3. 현재 호스팅된 세션 또는 태스크 제출을 통해 요청된 주소 증명, 자금 증명 또는 기타 증거를 제공하세요.
4. 현재 태스크가 요청할 때만 문서를 업로드하세요.
5. 수동 검토 중에도 현재 리소스를 계속 모니터링하세요.
6. 현재 케이퍼빌리티, 애플리케이션, 태스크, 제출 상태를 기반으로 중지하거나 계속 진행하세요.

컴플라이언스 팀은 고객의 등록된 이메일 주소를 통해 강화된 검토를 조정할 수도 있어요.

## 일반적인 거부 사유

| 사유 | 해결 |
| --- | --- |
| 문서를 읽을 수 없음 | 명확한 고해상도 이미지를 제공하세요 |
| 문서가 만료됨 | 유효한 만료되지 않은 신원 문서를 제공하세요 |
| 얼굴이 일치하지 않음 | 셀피가 신원 문서 사진과 명확히 일치하는지 확인하세요 |
| 정보 불완전 | 현재 태스크가 요청한 모든 항목을 제공하세요 |
| 의심스러운 활동 | 수동 검토를 위해 지원팀에 문의하세요 |

## 검증 타임라인

| 단계 | 일반적인 소요 시간 |
| --- | --- |
| 문서 업로드 | 즉시 |
| 자동 확인 | 1-3분 |
| 표준 검토 | 1-24시간 |
| 강화된 검토 | 1-3 영업일 |

이 소요 시간은 일반적인 정책 추정치이며 보장된 API 동작이 아니에요.

## 현재 API 상태 어휘

현재 리소스는 별도의 닫힌 어휘를 사용해요:

- **케이퍼빌리티 상태:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **애플리케이션 상태:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **태스크 상태:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **제출 결과:** `in_review`, `accepted`, `changes_requested`, `rejected`

이 어휘들을 하나의 검증 상태로 통합하지 마세요.

## 이벤트와 현재 상태

현재 문서화된 [웹훅](/ko/integration/webhooks)을 변경 알림으로 사용한 뒤 현재 고객, 케이퍼빌리티, 애플리케이션, 태스크 리소스를 다시 조회하세요. 이벤트는 권위 있는 리소스 조회를 대체하지 않으며, 어떤 정책 관점 라벨도 특정 이벤트를 함의하지 않아요.

현재 조치 루프는 [케이퍼빌리티와 태스크](/ko/integration/onboarding/capabilities-and-requirements#complete-current-tasks)를 참고하세요.
