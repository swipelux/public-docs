## 개인 온보딩 (KYC)

개인 고객은 거래하기 전에 KYC를 완료해요. 검증 수준은 관할권, 거래 볼륨, 리스크 평가, 규제 요건에 따라 달라져요.

<Warning>
  요건은 고객, 관할권, 케이퍼빌리티, 검토에 따라 달라져요. 현재
  태스크와 생성된 스키마가 제출해야 할 항목을 통제해요.
</Warning>

## KYC가 다루는 것

KYC는 고객의 신원을 확인하고, 리스크와 규제 요건이 증가함에 따라 주소, 실물 확인, 재무 프로필 또는 자금 출처 검토를 추가할 수 있어요. 요건은 관할권, 거래 볼륨, 사용 사례에 따라 달라질 수 있어요.

## KYC 검증 수준

| 수준 | 요건 | 일반적인 사용 사례 |
| --- | --- | --- |
| Simplified | 이름, 성, 생년월일 | 승인된 저가치 흐름 |
| Standard | 정부 발급 ID와 셀피/실물 확인 | 표준 한도 내 일반 거래 |
| Enhanced | ID, 셀피/실물 확인, 주소 증명, 자금 증명 | 고가치 거래 또는 고위험 프로필 |

Simplified, Standard, Enhanced는 정책 티어이며 현재 API 상태 값이 아니에요.

## 수집되는 정보

현재 검토에 따라 Swipelux는 다음을 요청할 수 있어요:

- 법적 이름과 생년월일
- 연락처 정보
- 필요한 경우 거주 주소
- 정부 발급 신원 증거와 실물 확인 증거
- 필요한 경우 예상 활동과 자금 출처를 포함한 재무 프로필 정보

이 목록을 범용 요청 본문으로 다루지 마세요. 특정 케이퍼빌리티에 필요한 정보는 현재 고객 스키마와 태스크 세부 정보가 결정해요.

## 현재 구현

개인 고객을 생성하고, 자격 있는 케이퍼빌리티를 발견하고 요청한 뒤, 현재 태스크를 따르세요. 태스크는 자사 호스팅 검증 세션을 제공하거나 태스크 제출을 요구할 수 있어요. 그 태스크가 요청할 때만 문서를 업로드하세요.

[개인 온보딩 가이드](/ko/integration/onboarding/customers#individual-customers), [케이퍼빌리티와 태스크](/ko/integration/onboarding/capabilities-and-requirements#complete-current-tasks), [개인 API 워크플로 맵](/ko/knowledge-base/individual-onboarding/api-workflow)을 따르세요.
