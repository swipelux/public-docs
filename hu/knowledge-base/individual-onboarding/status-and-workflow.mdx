## Ellenőrzési státusz és munkafolyamat

A szabályzat-orientált KYC út az információgyűjtéstől a felülvizsgáláson át az elfogadó vagy elutasító döntésig halad. Az aktuális API-erőforrások külön képesség-, alkalmazás-, feladat- és beküldés-életciklusokat jelenítenek meg.

<Warning>
  A szabályzati felülvizsgálati címkék és időbecslések nem határozzák meg az
  API viselkedését. Ne valósítson meg állapotgépet az alábbi címkékből.
</Warning>

## Szabályzat-orientált felülvizsgálati fogalmak

Ezek a szabályzat-orientált felülvizsgálati fogalmak az onboarding utat írják le. Nem aktuális API enumok, webhook értékek vagy garantált átmenetek.

| Szabályzati címke | Jelentés |
| --- | --- |
| `not_started` | Az ügyfél létezik, de a KYC munka nem kezdődött el |
| `incomplete` | A KYC munka elkezdődött, de a szükséges információk hiányoznak |
| `pending_verification` | A felülvizsgálat az ügyfél befejezésére vár |
| `under_review` | A beküldött információk vagy dokumentumok felülvizsgálat alatt állnak |
| `approved` | A szabályzati felülvizsgálat jóváhagyta az ügyfelet az alkalmazandó folyamatokra |
| `rejected` | A szabályzati felülvizsgálat elutasította az ügyfelet |

Csak akkor használja ezeket a címkéket, amikor a szabályzati útról beszél. Ne küldje őket aktuális státusz értékként, hacsak egy aktuális generált séma kifejezetten nem kéri ugyanazt az értéket a saját kontextusában.

## Standard KYC felülvizsgálati folyamat

1. Hozza létre a magánszemély ügyfelet.
2. Fedezze fel és kérje a jogosult képességet.
3. Olvassa el az aktuális feladatrészletet.
4. Küldje el az ügyfelet egy első fél hosted ellenőrzési munkamenetre vagy küldje be a feladat által kért teljes válaszokat.
5. Hagyja a felülvizsgálatot futni, miközben az aktuális erőforrások jelentik saját felülvizsgálati állapotukat.
6. Frissítse le az aktuális erőforrásokat annak eldöntéséhez, hogy több művelet szükséges-e, vagy a képesség ready, restricted, rejected vagy canceled.

A szabályzati út ezt not started, pending verification, under review, majd approved vagy rejected címkékkel írhatja le. Ezek a kifejezések nem határozzák meg az API átmenet sorrendjét.

## Enhanced KYC felülvizsgálati folyamat

1. Fejezze be az aktuálisan kért standard személyazonossági és élőségi munkát.
2. Olvassa el a legfrissebb feladatot, amikor a fokozott felülvizsgálat további információkat kér.
3. Adja meg a kért lakcímigazolást, pénzforrás-igazolást vagy egyéb bizonyítékot az aktuális hosted munkameneten vagy feladatbeküldésen keresztül.
4. Csak akkor töltsön fel dokumentumokat, amikor az aktuális feladat kéri.
5. Folytassa az aktuális erőforrások figyelését a manuális felülvizsgálat során.
6. Álljon meg vagy folytassa az aktuális képesség-, alkalmazás-, feladat- és beküldés-állapotok alapján.

A megfelelőségi csapat egy fokozott felülvizsgálatot az ügyfél regisztrált e-mail címén keresztül is koordinálhat.

## Gyakori elutasítási okok

| Ok | Megoldás |
| --- | --- |
| A dokumentum nem olvasható | Adjon tiszta, nagy felbontású képet |
| A dokumentum lejárt | Adjon érvényes, nem lejárt személyazonossági dokumentumot |
| Az arc nem egyezik | Győződjön meg róla, hogy a szelfi egyértelműen egyezik az azonosító dokumentum fényképével |
| Hiányos információ | Adjon meg minden elemet, amelyet az aktuális feladat kér |
| Gyanús tevékenység | Lépjen kapcsolatba a támogatással manuális felülvizsgálatért |

## Ellenőrzési idővonal

| Szakasz | Tipikus időtartam |
| --- | --- |
| Dokumentumfeltöltés | Azonnali |
| Automatikus ellenőrzések | 1-3 perc |
| Standard felülvizsgálat | 1-24 óra |
| Fokozott felülvizsgálat | 1-3 munkanap |

Ezek az időtartamok tipikus szabályzati becslések, nem garantált API viselkedés.

## Aktuális API-állapot szótárak

Az aktuális erőforrások külön zárt szótárakat használnak:

- **Képesség státusz:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Alkalmazás státusz:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Feladat státusz:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Beküldés kimenetele:** `in_review`, `accepted`, `changes_requested`, `rejected`

Ne olvassza össze ezeket a szótárakat egy ellenőrzési státuszba.

## Események és aktuális állapot

Használja az aktuálisan dokumentált [Webhookokat](/hu/integration/webhooks) változási értesítésekként, majd frissítse le az aktuális ügyfél-, képesség-, alkalmazás- és feladaterőforrásokat. Az események nem helyettesítik a hiteles erőforrás-olvasásokat, és egyetlen szabályzati címke sem sugall egy adott eseményt.

Lásd a [Képességek és feladatok](/hu/integration/onboarding/capabilities-and-requirements#complete-current-tasks) oldalt az aktuális műveleti ciklushoz.
