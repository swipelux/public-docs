Hozza létre az ügyfelet, mielőtt pénzbefizetést, kifizetést vagy kibocsátott bankszámlát épít. A képességek, számlák és átutalások az adott ügyfélhez tartoznak. Az `externalId` használatával stabil hozzárendelést tehet a rendszerében lévő rekordhoz.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Magánszemély ügyfelek {#individual-customers}

Egy magánszemélyhez csak a `type` szükséges. Adja hozzá a már ismert profilmezőket, és csak akkor tegyen hozzá többet, ha az aktuális képességnek vagy feladatnak szüksége van rájuk.

Hozza létre az ügyfelet a [`POST /v3/customers`](/api-reference/customers/post-v3-customers) művelettel:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Tárolja a visszakapott `data.id` értéket `CUSTOMER_ID`-ként. A szabályzati kontextushoz lásd a [Magánszemély onboarding](/hu/knowledge-base/individual-onboarding/overview) oldalt.

## Üzleti ügyfelek {#business-customers}

Az üzleti ügyfélhez a `business.legalName` szükséges. Hozza létre a vállalkozást ugyanazzal a művelettel:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Tárolja a visszakapott `data.id` értéket `CUSTOMER_ID`-ként. A szabályzati és dokumentum-kontextushoz lásd az [Üzleti onboarding](/hu/knowledge-base/business-onboarding/overview) oldalt.

## Üzleti kapcsolt felek hozzáadása

Adja hozzá az igazgatókat, tulajdonosokat és egyéb üzleti résztvevőket, ha ismertek vagy kértek. Ez a példa egy igazgatót hoz létre a [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) művelettel:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Tárolja a visszakapott `data.id` értéket `RELATED_PARTY_ID`-ként.

## Ügyféladatok exportálása {#export-customer-data}

Használja a [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) műveletet egy ügyfél letöltéséhez, vagy a jóváhagyott KYC-adatok átadásához a saját Sumsub projektjébe. Minden export `Idempotency-Key` fejlécet igényel; ugyanazzal a kulccsal és törzzsel megismételve ugyanazt az eredményt kapja.

Válassza ki a formátumot a kérés törzsében.

<Tabs>
  <Tab title="Alap profil JSON">

A nyilvános v3 ügyfél-erőforrást JSON mellékletként adja vissza, amely tartalmazza a profil-, cím-, adó-, metaadat- és kapcsolt fél adatokat. A dokumentumok és a dokumentum-metaadatok nem szerepelnek benne.

```json
{
  "format": "json_basic_data"
}
```

  </Tab>
  <Tab title="Sumsub megosztási token">

Egyszer használatos Sumsub megosztási tokent hoz létre egy jóváhagyott magánszemély ügyfélhez, hogy a fogadó Sumsub projekt importálhassa a KYC-adatokat. Üzleti ügyfelek esetén `422 invalid_field_for_type` választ ad.

```json
{
  "format": "sumsub_share_token",
  "forClientId": "partner-sumsub-client-id"
}
```

A `forClientId` az Ön Sumsub `clientId` értéke, nem pedig a Swipelux `customerId`. Azt a Sumsub projektet azonosítja, amely megkapja a kérelmező adatait, így az érték az Ön választása.

A válasz a `provider`, `token` és `expiresAt` (Unix másodpercek) értékeket adja vissza:

```json
{
  "data": {
    "provider": "sumsub",
    "token": "_shr-...",
    "expiresAt": 1800000000
  }
}
```

Adja át a `token` értéket a Sumsub megosztási token importáló API-jának a `forClientId` által azonosított projekthez az `expiresAt` előtt. Csak egyszer használja. Újbóli kiadáshoz hívja meg az exportot új `Idempotency-Key` értékkel.

  </Tab>
</Tabs>

## Készenlét olvasása képességekből

Az ügyfélnek nincs ellenőrzési vagy készenléti státusza az API-ban. Olvassa be az ügyfelet a [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) művelettel az aktuális profiladatokért, majd használja a képességeket és azok `openTaskIds` értékeit annak eldöntéséhez, hogy az ügyfél mit tehet legközelebb.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Ezután folytassa a [Képességek és feladatok](/hu/integration/onboarding/capabilities-and-requirements) oldalon a szükséges termékeredmény felfedezéséhez és aktiválásához.
