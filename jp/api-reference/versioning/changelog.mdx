このページには、Swipelux API に対する日付付きの変更が一覧表示されます。各エントリには、影響を受けるバージョン、変更の種類、およびインテグレーターに求められる対応が記載されています。

既存のインテグレーションを以前のバージョンからアップグレードする場合は、[v3 への移行](/jp/api-reference/versioning/migrate-to-v3) を参照してください。

## 未リリース

_今後の変更は、リリース前にここに記載されます。_

## 2026-08-31

**バージョン:** v3

### 追加
- 実質的支配者のいないビジネスに対してケイパビリティをリクエストすると、`503` で失敗する代わりに、実質的支配者を追加するための受付タスクが作成されるようになりました。続行できないリクエストは、申告済みまたは 25% 以上の所有権を持つ個人の関係者を追加するよう案内する `422 beneficial_owner_required` を返します。[株主、UBO、および管理者](/jp/knowledge-base/business-onboarding/shareholders-ubos-and-control-persons)を参照してください。
- マーチャントパネルのタスクテーブルに、各リクエストの対象者とケイパビリティのスコープが表示されるようになり、コンプライアンスリクエストが誰と何を対象としているかを確認できます。[ケイパビリティと要件](/jp/integration/onboarding/capabilities-and-requirements)を参照してください。
- マーチャントパネルの業種分類フィールドで、顧客プロファイルと要件タスクにおいて検索可能な NAICS コードを利用できるようになりました。[KYB ワークフロー](/jp/knowledge-base/business-onboarding/kyb-workflow)を参照してください。

### 変更
- 進行中の銀行設定と競合する銀行詳細の送信は、`409 ops_rail_handoff_conflict` を返すようになりました。書類を再アップロードするのではなく、アップロード済みの書類 ID を保持し、競合が解消された後に同じ送信を再試行してください。[エラーと再試行](/integration/errors)を参照してください。
- 顧客ウォレットへの事前通知のないステーブルコイン入金の最小額が 10 単位から 1 単位になりました。それより小さい入金は引き続きダストとして扱われます。[資金を受け取る](/jp/integration/receive-funds)を参照してください。
- Webhook の設定が環境ごとに分離されるようになりました。Webhook ポータルはリクエスト元の環境にスコープされた状態で開くため、サンドボックスと本番のエンドポイントが設定を共有しなくなりました。[Webhook](/jp/integration/webhooks)を参照してください。
- マーチャントパネルは、顧客の v3 ケイパビリティから利用可能な pay-in メソッドを導出するようになり、口座設定では顧客に権限のあるメソッドのみが提供されます。[口座](/jp/integration/accounts)を参照してください。
- RFI フォームは、より短く明確なプロンプトで該当する実質的支配者を収集するようになり、RFI 履歴はライフサイクルのマイルストーンとして表示されます。[書類要件](/jp/knowledge-base/business-onboarding/document-requirements)を参照してください。

### 削除
- マーチャントパネルでは、新しい pay-in メソッドの追加時に Fedwire を提供しなくなりました。既存の Fedwire 口座は引き続き取得できます。[口座](/jp/integration/accounts)を参照してください。

### 修正
- 顧客ウォレットへの事前通知のない USDT 入金が、無視されずに認識・決済されるようになりました。
- すでに提出した証跡が、同じ項目を必要とする他のタスクに引き継がれるようになり、顧客が同じ書類を二度求められることがなくなりました。
- ケイパビリティを再リクエストしても、すでに準備完了の銀行ルートが破棄されなくなり、発行済みの口座詳細が安定して維持されます。
- マーチャントパネルの銀行指示ビューに、SWIFT アドレスや宛先ウォレットアドレスを含む完全な詳細が表示されるようになりました。
- RFI フォームは、送信時の検証エラーを表示し、送信前に法的形態の説明を検証し、複数のビジネスウェブサイトを受け付けるようになりました。
- RFI フォームで、送信前に関係者のドラフトを編集できるようになりました。
- キャンセルされたコンプライアンスリクエストが、マーチャントパネルのタスクリストに表示されなくなりました。
- マーチャントパネルで書類レビューのステータスが再び正しく表示されるようになりました。

## 2026-08-24

**バージョン:** v3

### 追加
- 顧客スコープのホスト型本人確認および利用規約セッションに、信頼すべき `action` オブジェクトが追加されました。`available` または `unavailable` の種類に従ってください。利用可能なアクションでは、トップレベルの `url` と `expiresAt` は互換性のためのミラーとして残ります。[ケイパビリティと要件](/jp/integration/onboarding/capabilities-and-requirements)を参照してください。
- サンドボックスのウォレット入金で、`GET /v3/transfers/{transferId}` から取得、または `GET /v3/transfers` から一覧取得できる送金 ID が返されるようになりました。完了したステーブルコインの入金として表示されます。[サンドボックスでテストする](/jp/integration/sandbox)を参照してください。

### 変更
- カードおよび Apple Pay 向けのマーチャントパネルの **First pay-in** ガイドで、顧客に Polygon ウォレットが必要になりました。ガイドを開始する前にウォレットを作成してください。[口座](/jp/integration/accounts)を参照してください。
- 新しいリクエストと公開レスポンスでは、メソッドおよびケイパビリティの正規名として `sepa` を使用します。`sepa_instant` 入力エイリアスと以前に保存されたリソースには互換性がありますが、公開レスポンスでは `sepa` が返されます。[口座](/jp/integration/accounts)を参照してください。
- Faster Payments の新しいケイパビリティ、発行口座、見積もりリクエストは利用できません。既存の口座、見積もり、送金は引き続き取得できます。[口座](/jp/integration/accounts)を参照してください。
- KYB の最初のページでは代表者の生年月日を収集しなくなりました。株主の生年月日は引き続き別の要件です。[KYB ワークフロー](/jp/knowledge-base/business-onboarding/kyb-workflow)を参照してください。
- RFI の書類参照で、`image/jpeg` に加えて MIME エイリアス `image/jpg` を受け付けるようになりました。[書類要件](/jp/knowledge-base/business-onboarding/document-requirements)を参照してください。
- マーチャントパネルのタスク履歴に、リビジョンカウンターを含まない読みやすい監査証跡が表示されるようになりました。[ケイパビリティと要件](/jp/integration/onboarding/capabilities-and-requirements)を参照してください。

### 削除
- マーチャントパネルでは新しい UAEFTS 口座の設定を提供しなくなりました。既存の UAEFTS 口座は引き続き取得できます。[口座](/jp/integration/accounts)を参照してください。

### 修正
- レビュー担当者が新しい書類提出欄を追加しても、RFI フォームの既存入力が保持され、再送信時に以前の回答が失われなくなりました。
- マーチャントパネルは、有効なリンクを破棄せず、利用可能なアクションからホスト型コンプライアンスセッションを再開します。
- ホスト型の利用規約リンクが、API から返されるすべてのタスクスコープで機能するようになりました。
- マーチャントパネルで Payment Access をリクエストすると、以前のリクエストのタスクではなく、そのリクエストから返された受付タスクが開くようになりました。
- マーチャントパネルの KYB デモで、現在必要なフィールドが求められるようになりました。
- ソースウォレットを `destinationId` として再利用する見積もりは、プロバイダー処理を開始する前に、対処可能な `422 quote_direction_invalid` の詳細を返すようになりました。[見積もりと送金](/jp/integration/quotes-and-transfers)を参照してください。
- API は不正なクエリ文字列エンコーディングを暗黙に正規化せず、`400` エラーで拒否するようになりました。[エラーと再試行](/integration/errors)を参照してください。
- `POST /v3/customers/{customerId}/documents` は、空、multipart 以外、または不正な形式のリクエストボディを `400` エラーで拒否するようになりました。
## 2026-08-17

**バージョン:** v3

### 追加
- OpenAPI 仕様に v3 Problem Details カタログを公開しました。これにより、インテグレーターはスキーマから直接エラー応答をマッピングできます。 [Errors](/integration/errors).
- v3 の口座 webhook イベントに `customerId` を追加し、追加の読み取りなしに口座アクティビティを所有者の顧客に関連付けられるようにしました。[Webhook](/jp/integration/webhooks) を参照してください。
- マーチャントパネルで V3 個人プロファイルフィールドを全面的にカバーし、オンボーディング担当者が v3 API 経由で収集されたすべての KYC フィールドを確認・編集できるようになりました。[顧客のオンボーディング](/jp/integration/onboarding/customers) を参照してください。
- v3 の開発者向け移行ガイドを公開しました。[v3 への移行](/jp/api-reference/versioning/migrate-to-v3) を参照してください。

### 変更
- 顧客および口座の国コードは、書き込み時に割り当て済みの ISO 3166-1 alpha-2 値として検証されるようになりました。読み取りはレガシーの保存値を許容するため、既存のレコードは引き続き解決されます。[口座とウォレット](/jp/integration/accounts) を参照してください。
- の USDC 提供は宛先ネットワークによってスコープが限定されるようになりました。これにより、見積もりと送金は宛先が実際にサポートするネットワーク上でのみ USDC を提供します。
- `Capability.ready` は利用権限の承認を示し、口座の発行を意味しません。口座発行は `accountProvisioning` で追跡してください：`not_applicable`、`not_started`、`in_progress`、`issued`、`failed`。
- iPhone からの HEIC アップロードが本人確認および住所確認書類として受け入れられるようになりました。

### 修正
- 使用済みの見積もりを再実行すると、汎用エラーではなく `409 quote_execution_consumed` を返すようになりました。[見積もりと送金](/jp/integration/quotes-and-transfers) を参照してください。
- 大量の履歴結果に対する送金一覧の読み取りおよび見積もり金額の読み取りが `500` を返さなくなりました。
- 個人顧客の関係者読み取りが `404` を返さなくなりました。
- マーチャントパネルの検証リンク行に、すべての行で **Open** アクションが表示されるようになり、ウォレットインフラストラクチャのすべてのタスクリンクが要件ビューにレンダリングされるようになりました。
