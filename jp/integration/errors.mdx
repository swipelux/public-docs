---
title: "エラーと再試行"
description: "Swipelux API のすべての公開問題コードを処理し、再試行のタイミングを判断して、バリデーション、状態、冪等性、プラットフォームの失敗を解決します。"
---

Swipelux API のエラーは `application/problem+json` メディアタイプを使用します。安定した `code` 値に基づいてアプリケーションの動作を分岐させ、以下の操作とガイダンスを使用して失敗を解決してください。

| フィールド | 使い方 |
| --- | --- |
| `type` | 問題コードの安定したドキュメント URI。 |
| `title` | 人が読める短い問題タイトル。 |
| `status` | このレスポンスに関連付けられた HTTP ステータス。 |
| `code` | アプリケーションロジック用の安定した機械可読値。 |
| `detail` | この発生に関する文脈的で人が読めるテキスト。解析や比較には使用しないでください。 |
| `correlationId` | ログに保存し、サポートへの問い合わせ時に含めるリクエスト識別子。 |
| `retryable` | `true` の場合、同じリクエストが後で成功する可能性があります。`false` の場合、再試行する前にリクエストを変更するか、前提条件を満たしてください。 |
| `errors[]` | フィールドレベルのバリデーション詳細。利用可能な場合は JSON Pointer を含みます。 |

冪等な書き込みは、元の `Idempotency-Key` と変更していないメソッド、パス、ボディで再試行してください。そのキーを別の意図した操作に再利用しないでください。

```json
{
  "type": "https://docs.swipelux.com/errors/validation-error",
  "title": "Validation Error",
  "status": 400,
  "code": "validation_error",
  "detail": "The request contains invalid fields.",
  "correlationId": "01JERRORVALIDATION",
  "retryable": false,
  "errors": [
    {
      "pointer": "/externalId",
      "code": "invalid_format",
      "message": "Use a valid external identifier."
    }
  ]
}
```

### `forbidden`

**HTTP ステータス:** `403`<br />
**再試行可能:** いいえ<br />
**問題タイプ:** `https://docs.swipelux.com/errors/forbidden`

**意味:** API キーは有効ですが、この操作の実行を許可されていません。

**発生する状況:** 認証情報に必要な権限がないか、本番の認証情報がサンドボックス専用エンドポイントを呼び出しています。

**対処方法:** 必要な権限を持つ、正しい環境用の認証情報を使用してください。クライアントサイドのコードでキーを公開したり差し替えたりしないでください。

**再試行ガイダンス:** 変更していないリクエストを再試行しないでください。次のリクエストを送信する前に、上記の対応を実施してください。

**関連する API 操作:** 認証が必要なすべての API 操作。

### `invalid_field_for_type`

**HTTP ステータス:** `400`, `422`<br />
**再試行可能:** 返されません<br />
**問題タイプ:** `https://docs.swipelux.com/errors/invalid-field-for-type`

**意味:** リクエストに、選択したリソースタイプでは有効でないフィールドが含まれています。

**発生する状況:** 個人と法人のプロフィールのように型で判別されるリクエストが、別のバリアントのフィールドを含んでいるか、選択したタイプで必須のフィールドを欠いています。

**対処方法:** 選択したタイプのスキーマを使用し、他のバリアントに属するフィールドを削除し、必須フィールドを指定して、修正したリクエストを送信してください。

**再試行ガイダンス:** この問題は `retryable` を返しません。変更なしの再試行が安全であると想定せず、上記の対応とその操作の冪等性要件に従ってください。

**関連する API 操作:**

- [`POST /v3/customers`](/api-reference/customers/post-v3-customers) (`postV3Customers`, ステータス `400`)
- [`PATCH /v3/customers/{customerId}`](/api-reference/customers/patch-v3-customers-by-customer-id) (`patchV3CustomersByCustomerId`, ステータス `400`)
- [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) (`postV3CustomersByCustomerIdExport`, ステータス `422`)
- [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) (`postV3CustomersByCustomerIdRelated-parties`, ステータス `400`)
- [`PATCH /v3/customers/{customerId}/related-parties/{relatedPartyId}`](/api-reference/customers/patch-v3-customers-by-customer-id-related-parties-by-related-party-id) (`patchV3CustomersByCustomerIdRelated-partiesByRelatedPartyId`, ステータス `400`)

### `request_body_too_large`

**HTTP ステータス:** `413`<br />
**再試行可能:** いいえ<br />
**問題タイプ:** `https://docs.swipelux.com/errors/request-body-too-large`

**意味:** リクエストボディが、この操作で受け付けられるサイズを超えています。

**発生する状況:** タスクの送信が、API が 1 つのボディで処理できる量を超えるリクエストデータを送っています。

**対処方法:** 不要なデータを削除し、ファイル内容を埋め込む代わりにドキュメント参照を使用して、現在の要件に回答できる範囲でより小さな送信を行ってください。
