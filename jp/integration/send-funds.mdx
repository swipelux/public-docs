すべての支払いは、ready 状態で入金済みの発行ウォレットから開始します。送金先モデルは、エンドポイントの所有者に応じて異なります。

```mermaid
%%{init: {"flowchart": {"rankSpacing": 20, "nodeSpacing": 16, "wrappingWidth": 80, "padding": 8}}}%%
flowchart LR
  A["入金済みの発行ウォレット"] --> B{{"エンドポイントの所有者は？"}}
  B -->|"顧客"| C["顧客の口座 acc_..."]
  B -->|"別の個人または事業者"| D["受取人の送金先 dst_..."]
  C --> E["見積もりを作成"]
  D --> E
  E --> F["送金を実行して追跡"]
```

## 開始前に必要なもの

送金元ウォレットを再取得します。現在のステータスが支払いを許可し、利用可能な残高が意図する送金元金額をカバーすることを確認してください。レスポンスから得られる ID を `SOURCE_WALLET_ID` として保存します。

現在の顧客と選択した送金先に対する ready 状態の支払いケイパビリティも必要です。

既存の Tron ウォレットは、`stablecoin_transfers` の見積もりを使用して、別の Tron ウォレットに USDT を送金できます。入力と出力には同じネットワークと同じステーブルコインを使用する必要があります。Tron では新しい発行ウォレットを作成できません。

## 1. 送金先を準備する

<Tabs>
  <Tab title="ファーストパーティ">

顧客がエンドポイントを所有する場合は、顧客所有の外部銀行口座を使用します。次のヘッダーとともに [`POST /v3/customers/{customerId}/accounts`](/api-reference/accounts/post-v3-customers-by-customer-id-accounts) で作成します。

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-account-001
Content-Type: application/json
```

```json Request body
{
  "origin": "external",
  "type": "bank",
  "methods": ["ach", "wire"],
  "country": "US",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "Example Bank",
    "accountHolderName": "Acme Payments SAS"
  },
  "label": "Customer operating account"
}
```

[`GET /v3/customers/{customerId}/accounts/{accountId}`](/api-reference/accounts/get-v3-customers-by-customer-id-accounts-by-account-id) で読み取ります。現在のステータスが支払いを許可する場合にのみ続行してください。その `acc_` ID を `PAYOUT_DESTINATION_ID` として保存します。

  </Tab>
  <Tab title="サードパーティ">

[受取人と送金先](/jp/integration/recipients) を通じて、個人または事業者、およびその銀行またはウォレットのエンドポイントを作成します。送金先が ready になったときのみ続行してください。

返された `dst_` ID を `PAYOUT_DESTINATION_ID` として保存します。受取人の `rcp_` ID を見積もりの送金先として使用しないでください。

  </Tab>
</Tabs>

## 2. 支払い見積もりを作成する

次のヘッダーとともに [`POST /v3/quotes`](/api-reference/money-movement/post-v3-quotes) を使用します。

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-quote-001
Content-Type: application/json
```

```json Request body
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "in": {
    "amount": "150.00",
    "currency": "USDC",
    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${PAYOUT_DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }
}
```

`data.id` を `QUOTE_ID` として保存し、返された価格と手数料を提示してください。

### 銀行ルートを選択する {#choose-a-bank-route}

暗号資産からフィアットへの支払いでは、オプションの `institutionId` を設定して、顧客に対して承認済みの銀行ルートを必須にできます。自動ルーティングを使用する場合は省略してください。

```json Request body with institutionId
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "institutionId": "${INSTITUTION_ID}",
  "in": {
    "amount": "150.00",
    "currency": "USDC",
    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${PAYOUT_DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }
}
```

- 明示的に指定した `institutionId` が別の銀行にフォールバックすることはありません。選択した銀行に、この顧客、ケイパビリティ、送金先に対する ready 状態のルートがない場合、`POST /v3/quotes` はポインター `/institutionId` とともに `422` [`bank_not_supported_for_customer`](/integration/errors#bank-not-supported-for-customer) を返します。
- `institutionId` は暗号資産からフィアットへの支払い見積もりでのみ有効です。入金、カード、またはステーブルコイン送金の見積もりで送信すると、`400` [`validation_error`](/integration/errors#validation-error) が返されます。
- 見積もりと送金の読み取りでは、銀行を特定できる場合、自動的に選択されたルートを含め、選択されたルートの `institutionId` が返されます。

### SWIFT 支払い {#swift-payouts}

本番環境では、USD の SWIFT 支払いには、支払いをサポートする ready 状態の SWIFT ケイパビリティ（`swift_pooled` または `swift_named`）が必要です。また、資金は Ethereum、Base、Polygon 上の USDC、または Ethereum、Polygon 上の USDT で拠出される必要があります。手数料差し引き後の受取金額は 100.00 USD 以上である必要があります。

SWIFT の送金先には、`bankAddress`、`bankCity`、`bankState`、`bankPostalCode` に銀行の所在地住所が必要です。BIC の国は銀行の国と一致している必要があります。Swipelux は受益者の住所を顧客または受取人のプロファイルから取得します。

## 3. 支払いを実行する

[`POST /v3/transfers`](/api-reference/money-movement/post-v3-transfers) で送金を作成します。この意図した実行には新しいキーを 1 つ使用してください。

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-transfer-001
Content-Type: application/json
```

```json Request body
{
  "quoteId": "${QUOTE_ID}"
}
```

送金の `data.id` を `TRANSFER_ID` として保存します。作成成功は支払いを開始しますが、配信を証明するものではありません。

## 4. 配信を追跡する

作成後および各イベントの後に、[`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) を読み取ります。最新の `data.state`、`data.stateDetail`、`data.openTaskIds` を使用して、待機するか、アクションを実行するか、終端の結果を表示するかを判断してください。

次に、正確な金額、安全な実行のリカバリー、送金タスクについて [見積もりと送金](/jp/integration/quotes-and-transfers) を確認してください。
