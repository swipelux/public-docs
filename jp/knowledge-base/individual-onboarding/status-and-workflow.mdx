## 検証ステータスとワークフロー

ポリシー面の KYC ジャーニーは、情報収集からレビューを経て、承認または拒否の決定へと進みます。現在の API リソースは、個別のケイパビリティ、application、タスク、送信のライフサイクルを露出します。

<Warning>
  ポリシーレビューのラベルとタイミングの見積もりは API 動作を定義しません。
  以下のラベルからステートマシンを実装しないでください。
</Warning>

## ポリシー面のレビュー概念

これらのポリシー面のレビュー概念は、オンボーディングジャーニーを説明します。現在の API enum、Webhook 値、または保証された遷移ではありません。

| ポリシーラベル | 意味 |
| --- | --- |
| `not_started` | 顧客は存在するが、KYC 作業が開始されていない |
| `incomplete` | KYC 作業は開始されたが、必要な情報が不足している |
| `pending_verification` | レビューが顧客の完了を待っている |
| `under_review` | 提出された情報またはドキュメントがレビュー中 |
| `approved` | ポリシーレビューが該当するフローに対して顧客を承認した |
| `rejected` | ポリシーレビューが顧客を拒否した |

これらのラベルは、ポリシージャーニーを議論するときにのみ使用してください。生成された現在のスキーマが独自の文脈で同じ値を明示的に要求しない限り、これらを現在のステータス値として送信しないでください。

## Standard KYC レビューフロー

1. 個人顧客を作成します。
2. 適格なケイパビリティを発見してリクエストします。
3. 現在のタスクの詳細を読み取ります。
4. ファーストパーティのホスト型検証セッションに顧客を送るか、タスクが要求する完全なタスク回答を送信します。
5. 現在のリソースが独自のレビュー状態を報告する間、レビューを実行させます。
6. 現在のリソースを再取得して、さらにアクションが必要か、ケイパビリティが ready、restricted、rejected、canceled のいずれかを判断します。

ポリシージャーニーはこれを not started、pending verification、under review、そして approved または rejected として説明できます。これらの用語は API の遷移シーケンスを定義しません。

## Enhanced KYC レビューフロー

1. 現在要求されている standard の身分および liveness 作業を完了します。
2. Enhanced レビューが追加情報を要求する場合は、最新のタスクを読み取ります。
3. 現在のホスト型セッションまたはタスク送信を通じて、要求された住所証明、資金証明、その他の証拠を提供します。
4. ドキュメントは、現在のタスクが要求する場合にのみアップロードします。
5. 手動レビュー中も現在のリソースの監視を続けます。
6. 現在のケイパビリティ、application、タスク、および送信の状態に基づいて停止または続行します。

コンプライアンスチームは、顧客の登録メールアドレスを通じて enhanced レビューを調整する場合もあります。

## 一般的な拒否理由

| 理由 | 解決策 |
| --- | --- |
| ドキュメントが判読不可 | 鮮明で高解像度の画像を提供する |
| ドキュメントの期限切れ | 有効期限内の有効な身分証明書を提供する |
| 顔が一致しない | 自撮りが身分証明書の写真と明確に一致することを確認する |
| 情報が不完全 | 現在のタスクが要求する各項目を提供する |
| 疑わしい活動 | 手動レビューのためサポートに連絡する |

## 検証タイムライン

| 段階 | 典型的な所要時間 |
| --- | --- |
| ドキュメントアップロード | 即時 |
| 自動チェック | 1〜3 分 |
| 標準レビュー | 1〜24 時間 |
| 強化レビュー | 1〜3 営業日 |

これらの所要時間は典型的なポリシーの見積もりであり、API の動作を保証するものではありません。

## 現在の API 状態語彙

現在のリソースは、別々の閉じた語彙を使用します。

- **Capability status:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Application status:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Task status:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Submission outcome:** `in_review`, `accepted`, `changes_requested`, `rejected`

これらの語彙を 1 つの検証ステータスに集約しないでください。

## イベントと現在の状態

現在文書化されている [Webhooks](/jp/integration/webhooks) を変更通知として使用し、その後現在の顧客、ケイパビリティ、application、タスクリソースを再取得してください。イベントは信頼できるリソース読み取りを置き換えるものではなく、ポリシー面のラベルが特定のイベントを暗示するものでもありません。

現在のアクションループについては [ケイパビリティとタスク](/jp/integration/onboarding/capabilities-and-requirements#complete-current-tasks) をご覧ください。
