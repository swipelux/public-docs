## 個人オンボーディング (KYC)

個人顧客は、取引を行う前に KYC を完了します。検証レベルは、管轄区域、取引量、リスク評価、および規制要件によって異なります。

<Warning>
  要件は顧客、管轄区域、ケイパビリティ、レビューによって異なります。
  現在のタスクおよび生成されたスキーマが、提出する内容を制御します。
</Warning>

## KYC が対象とするもの

KYC は顧客の身分を確認するもので、リスクと規制要件が高まるにつれて、住所、liveness、財務プロファイル、または資金源のレビューを追加できます。要件は管轄区域、取引量、およびユースケースによって異なる場合があります。

## KYC 検証レベル

| レベル | 要件 | 典型的なユースケース |
| --- | --- | --- |
| Simplified | 氏名、姓、生年月日 | 承認された低額のフロー |
| Standard | 政府発行 ID と自撮り/liveness チェック | 標準上限内の通常取引 |
| Enhanced | ID、自撮り/liveness、住所証明、資金証明 | 高額取引または高リスクプロファイル |

Simplified、Standard、Enhanced はポリシー階層であり、現在の API ステータス値ではありません。

## 収集される情報

現在のレビューに応じて、Swipelux は次を要求できます。

- 法的氏名と生年月日
- 連絡先詳細
- 必要な場合の居住先住所
- 政府発行の身分証拠および liveness の証拠
- 必要な場合の、想定される活動および資金源を含む財務プロファイル情報

このリストを普遍的なリクエストボディとして扱わないでください。特定のケイパビリティに必要な情報は、現在の顧客スキーマとタスクの詳細によって決定されます。

## 現在の実装

個人顧客を作成し、適格なケイパビリティを発見してリクエストし、その後現在のタスクに従ってください。タスクは、ファーストパーティのホスト型検証セッションを提供する場合、またはタスク送信を要求する場合があります。ドキュメントは、そのタスクが要求する場合にのみアップロードしてください。

[個人オンボーディングガイド](/jp/integration/onboarding/customers#individual-customers)、[ケイパビリティとタスク](/jp/integration/onboarding/capabilities-and-requirements#complete-current-tasks)、および [個人 API ワークフローマップ](/jp/knowledge-base/individual-onboarding/api-workflow) に従ってください。
