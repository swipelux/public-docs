## KYB ワークフロー

KYB ワークフローは、現在の顧客、関連当事者、ケイパビリティ、タスク、送信、およびドキュメントリソースを、ビジネスとその所有のポリシーレビューと組み合わせたものです。

<Warning>
  KYB の結果とタイムラインはポリシーの見積もりです。API の遷移、承認、または
  可用性を保証するものではありません。
</Warning>

## 現在のワークフローシーケンス

### 1. ビジネス顧客を作成する

[`POST /v3/customers`](/api-reference/customers/post-v3-customers) でビジネス顧客を作成します。[`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) で現在の顧客を読み取ります。

### 2. 関連当事者を維持する

現在の当事者を確認するには [`GET /v3/customers/{customerId}/related-parties`](/api-reference/customers/get-v3-customers-by-customer-id-related-parties)、作成するには [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties)、提供した事実を更新するには [`PATCH /v3/customers/{customerId}/related-parties/{relatedPartyId}`](/api-reference/customers/patch-v3-customers-by-customer-id-related-parties-by-related-party-id) を使用します。

現在のタスクが要求する直接所有者、親事業体、UBO、管理者、取締役、役員、および署名者を維持してください。彼らの役割は区別されます。

### 3. 適格なケイパビリティを発見しリクエストする

[`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported) を読み取ります。available または beta のケイパビリティは、顧客が適格である場合にのみ [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id) を使用してリクエストしてください。

### 4. 現在のタスクを読み取る

[`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks) で現在の作業を一覧表示します。実行可能な各タスクを [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task) で取得し、その現在のリビジョン、要件、およびセッションから次のアクションを導出してください。

### 5. 現在のタスクが要求するドキュメントをアップロードする

要求されたファイルを [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents) でアップロードします。現在のタスクがドキュメントの要否を判断し、受理されるタイプ、件数、またはフォーマットをより狭く制限する場合があります。

### 6. 完全なタスク回答を送信する

現在のタスクのリビジョンに対する完全な回答セットを、[`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) で 1 回送信します。現在の要件 ID を使用し、タスクが求める場合にのみ、アップロード済みドキュメント ID を参照してください。

### 7. 現在のリソースを監視する

各アクションまたはイベントの後で、[`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) で顧客を、[`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id) でケイパビリティを、[`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications) でその applications を、および現在の任意のタスクを再取得してください。

完全な仕組みについては、[ビジネスオンボーディング](/jp/integration/onboarding/customers#business-customers)、[ケイパビリティとタスク](/jp/integration/onboarding/capabilities-and-requirements#complete-current-tasks)、および [インテグレーションドキュメントガイド](/jp/integration/onboarding/capabilities-and-requirements#upload-documents) をご覧ください。

## 強化デューデリジェンス (EDD) のトリガー

EDD は次の場合に必要となる場合があります。

- 高リスクの管轄区域
- ゲーミング、トレーディング、暗号資産交換所を含む高リスクの業種
- 複雑な所有構造
- 該当するしきい値を超える想定月次取引量
- 制裁対象国を含む運営

## ポリシーレビューの結果

**結果:** KYB 承認、上限付き条件付き承認、または拒否。

これらはポリシーレビューの結果であり、現在の API ステータス値ではありません。条件付きのポリシー決定は、"conditional approval" という名前のステータスを作成することなく、現在のリソースを通じて反映される場合があります。

## 検証タイムライン

| 段階 | 典型的な所要時間 |
| --- | --- |
| ドキュメントアップロード | 即時 |
| 初回レビュー | 1〜2 営業日 |
| 標準 KYB | 2〜5 営業日 |
| EDD(トリガー時) | 5〜10 営業日 |

これらの所要時間は典型的なポリシーの見積もりであり、API の動作を保証するものではありません。

## 一般的な拒否理由

| 理由 | 解決策 |
| --- | --- |
| ドキュメント不足 | 現在のタスクが要求するすべてのドキュメントタイプを提供する |
| ドキュメントが不鮮明または不明瞭 | より高品質のスキャンまたは画像を提供する |
| 情報の不一致 | 提出された証拠全体で法人名が一致していることを確認する |
| 所有構造が不完全 | 所有の 100% を説明する証拠を提供する |
| 期限切れのドキュメント | 現行かつ有効なドキュメントを提供する |

## ポリシー用語と API 状態

ポリシー決定を、現在のリソースの語彙とは別にしてください。

- **Capability status:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Application status:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Task status:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Submission outcome:** `in_review`, `accepted`, `changes_requested`, `rejected`

ポリシーの結果を API 値に翻訳するのではなく、最新のリソースを読み取ってください。
