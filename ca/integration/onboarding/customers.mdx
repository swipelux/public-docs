Crea el client abans de construir un cobrament, un pagament o un compte bancari emès. Les capacitats, els comptes i les transferències s'associen a aquest client. Utilitza `externalId` com a mapatge estable al registre corresponent al teu sistema.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Clients individuals {#individual-customers}

Un individu només requereix `type`. Inclou els camps de perfil que ja coneixes i afegeix-ne més només quan la capacitat o la tasca actual els necessiti.

Crea el client amb [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Emmagatzema el `data.id` retornat com a `CUSTOMER_ID`. Consulta [Incorporació d'individus](/ca/knowledge-base/individual-onboarding/overview) per al context de política.

## Clients de negoci {#business-customers}

Un negoci requereix `business.legalName`. Crea el negoci amb la mateixa operació:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Emmagatzema el `data.id` retornat com a `CUSTOMER_ID`. Consulta [Incorporació de negocis](/ca/knowledge-base/business-onboarding/overview) per al context de política i documents.

## Afegeix parts relacionades del negoci

Afegeix directors, propietaris i altres participants del negoci quan siguin coneguts o sol·licitats. Aquest exemple crea un director amb [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Emmagatzema el `data.id` retornat com a `RELATED_PARTY_ID`.

## Exporta les dades del client {#export-customer-data}

Utilitza [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) per descarregar un client o per entregar el KYC aprovat al teu propi projecte de Sumsub. Cada exportació requereix una `Idempotency-Key`; si reprodueixes la mateixa clau i el mateix cos obtindràs el mateix resultat.

Selecciona el format al cos de la sol·licitud.

<Tabs>
  <Tab title="Perfil bàsic JSON">

Retorna el recurs públic v3 del client com a fitxer adjunt JSON amb dades de perfil, adreça, fiscalitat, metadades i parts relacionades. No inclou documents ni metadades de documents.

```json
{
  "format": "json_basic_data"
}
```

  </Tab>
  <Tab title="Token de compartició de Sumsub">

Crea un token de compartició de Sumsub d'un sol ús per a un client individual aprovat perquè el projecte de Sumsub receptor pugui importar les dades de KYC. Els clients de negoci retornen `422 invalid_field_for_type`.

```json
{
  "format": "sumsub_share_token",
  "forClientId": "partner-sumsub-client-id"
}
```

`forClientId` és el teu `clientId` de Sumsub, no el `customerId` de Swipelux. Identifica el projecte de Sumsub que rebrà les dades del sol·licitant, per la qual cosa el valor l'esculls tu.

La resposta retorna `provider`, `token` i `expiresAt` (segons Unix):

```json
{
  "data": {
    "provider": "sumsub",
    "token": "_shr-...",
    "expiresAt": 1800000000
  }
}
```

Passa el `token` a l'API d'importació de share-token de Sumsub per al projecte identificat per `forClientId` abans de `expiresAt`. Utilitza'l una sola vegada. Per reemetre'l, torna a cridar l'exportació amb una nova `Idempotency-Key`.

  </Tab>
</Tabs>

## Llegeix la preparació a partir de les capacitats

Un client no té un estat de verificació o de preparació a l'API. Llegeix el client amb [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) per obtenir les dades de perfil actuals, i després utilitza les capacitats i els seus `openTaskIds` per decidir què pot fer a continuació el client.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

A continuació, continua a [Capacitats i tasques](/ca/integration/onboarding/capabilities-and-requirements) per descobrir i activar el resultat de producte que necessites.
