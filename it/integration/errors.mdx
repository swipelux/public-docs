Gli errori dell'API di Swipelux usano il media type `application/problem+json`. Basa la logica della tua applicazione sul valore stabile `code`, poi usa l'operazione e le indicazioni qui sotto per risolvere il fallimento.

| Campo | Come usarlo |
| --- | --- |
| `type` | URI di documentazione stabile per il codice problema. |
| `title` | Titolo breve del problema leggibile da persone. |
| `status` | Status HTTP associato a questa risposta. |
| `code` | Valore stabile leggibile dalle macchine per la logica applicativa. |
| `detail` | Testo contestuale leggibile da persone per questa occorrenza. Non fare parsing o confronti su di esso. |
| `correlationId` | Identificatore della richiesta da salvare nei log e includere quando contatti il supporto. |
| `retryable` | Quando è `true`, la stessa richiesta può riuscire più tardi. Quando è `false`, modifica la richiesta o soddisfa un prerequisito prima di riprovare. |
| `errors[]` | Dettagli di validazione a livello di campo, incluso un JSON Pointer quando disponibile. |

Ritenta le scritture idempotenti con l'`Idempotency-Key` originale e metodo, percorso e body invariati. Non riusare mai quella chiave per un'operazione prevista diversa.

```json
{
  "type": "https://docs.swipelux.com/errors/validation-error",
  "title": "Validation Error",
  "status": 400,
  "code": "validation_error",
  "detail": "The request contains invalid fields.",
  "correlationId": "01JERRORVALIDATION",
  "retryable": false,
  "errors": [
    {
      "pointer": "/externalId",
      "code": "invalid_format",
      "message": "Use a valid external identifier."
    }
  ]
}
```

### `forbidden`

**Status HTTP:** `403`<br />
**Ritentabile:** No<br />
**Tipo di problema:** `https://docs.swipelux.com/errors/forbidden`

**Significato:** La chiave API è valida ma non è autorizzata a eseguire questa operazione.

**Quando si verifica:** La credenziale manca di un permesso richiesto, oppure una credenziale di produzione chiama un endpoint riservato alla sandbox.

**Cosa fare:** Usa una credenziale per l'ambiente corretto con i permessi richiesti. Non esporre o sostituire le chiavi nel codice lato client.

**Indicazioni per i nuovi tentativi:** Non ritentare la richiesta invariata. Applica l'azione indicata sopra prima di inviare un'altra richiesta.

**Operazioni API rilevanti:** Tutte le operazioni API autenticate.

### `invalid_field_for_type`

**Status HTTP:** `400`, `422`<br />
**Ritentabile:** Non restituito<br />
**Tipo di problema:** `https://docs.swipelux.com/errors/invalid-field-for-type`

**Significato:** La richiesta include campi che non sono validi per il tipo di risorsa selezionato.

**Quando si verifica:** Una richiesta discriminata, come un profilo individuale rispetto a uno business, contiene campi di un'altra variante oppure omette campi richiesti dal tipo selezionato.

**Cosa fare:** Usa lo schema del tipo selezionato, rimuovi i campi appartenenti ad altre varianti, fornisci i suoi campi obbligatori e invia una richiesta corretta.

**Indicazioni per i nuovi tentativi:** Questo problema non restituisce `retryable`. Non dare per scontato che un nuovo tentativo invariato sia sicuro; segui l'azione indicata sopra e i requisiti di idempotenza dell'operazione.

### `request_body_too_large`

**Status HTTP:** `413`<br />
**Ritentabile:** No<br />
**Tipo di problema:** `https://docs.swipelux.com/errors/request-body-too-large`

**Significato:** Il body della richiesta supera la dimensione accettata dall'operazione.

**Quando si verifica:** Una submission di task invia più dati di richiesta di quanti l'API possa elaborare in un solo body.

**Cosa fare:** Rimuovi i dati non necessari, usa riferimenti a documenti invece di incorporare il contenuto dei file e invia una submission più piccola che risponda comunque ai requisiti correnti.

**Indicazioni per i nuovi tentativi:** Non ritentare la richiesta invariata. Applica l'azione indicata sopra prima di inviare un'altra richiesta.

**Operazioni API rilevanti:**

- [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) (`createCustomerTaskSubmission`, status `413`)

### `unauthorized`

**Status HTTP:** `401`<br />
**Ritentabile:** No<br />
**Tipo di problema:** `https://docs.swipelux.com/errors/unauthorized`

**Significato:** La richiesta è priva di una chiave API valida.

**Quando si verifica:** L'header `X-API-Key` è assente, non valido, scaduto o non riconosciuto dall'API.

**Cosa fare:** Invia la chiave corretta specifica dell'ambiente da un backend protetto. Ruota la chiave se potrebbe essere stata esposta.

**Indicazioni per i nuovi tentativi:** Non ritentare la richiesta invariata. Applica l'azione indicata sopra prima di inviare un'altra richiesta.

**Operazioni API rilevanti:** Tutte le operazioni API autenticate.

**Tipo di problema:** `https://docs.swipelux.com/errors/unknown-parameter`

### `request_failed`

**Status HTTP:** `502`, `503`<br />
**Ritentabile:** Contestuale<br />
**Tipo di problema:** `https://docs.swipelux.com/errors/request-failed`

**Significato:** Un servizio necessario per completare l'operazione non ha elaborato la richiesta con successo.

**Quando si verifica:** L'export del cliente, la gestione dei webhook o la verifica sandbox incontra un guasto di un servizio esterno o una configurazione non disponibile.

**Cosa fare:** Ispeziona `retryable`. Ritenta più tardi quando è `true`; altrimenti conserva `correlationId`, verifica i prerequisiti della richiesta e contatta il supporto se il fallimento persiste.

**Indicazioni per i nuovi tentativi:** Leggi `retryable` in questa risposta. Ritenta più tardi solo quando è `true`. Per una scrittura idempotente, riusa la chiave di idempotenza originale e la richiesta invariata.
