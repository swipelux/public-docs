Mantieni ogni chiave API Swipelux su un backend protetto. Non inserire mai una chiave in codice del browser, in un bundle di applicazione mobile o in un file di configurazione visibile al client.

## Invia la tua chiave API

Usa la base URL condivisa `https://platform.swipelux.com` e invia la tua chiave nell'header `X-API-Key`.

```bash Verify your API key
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'

curl --request GET \
  "${API_BASE}/v3/capabilities" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

[`GET /v3/capabilities`](/api-reference/capabilities/get-v3-capabilities) conferma che la chiave è valida e che il tuo backend può raggiungere l'API.

## Sandbox e produzione

Sandbox e produzione usano lo stesso host API. La chiave API seleziona l'ambiente.

Mantieni la scelta dell'ambiente nella configurazione di deployment. Un deployment di produzione non deve mai ripiegare su una chiave sandbox e un deployment sandbox non deve mai ricevere credenziali di produzione.

## Ambito della chiave {#key-scope}

Ogni chiave API opera sui clienti e sui loro conti nel proprio ambiente e spazio sviluppatore. Sulle route dei clienti, un cliente fuori da questo ambito restituisce `404 customer_not_found`. Sui quote, un cliente o una sorgente fuori ambito restituisce `404 not_found`.

Una chiave sandbox non può spostare fondi live: un quote che indica un conto o una destination live restituisce `404 not_found`, come accade per un ID sconosciuto. Un quote per un movimento tra wallet restituisce `404 not_found` con `Destination was not found.` quando il conto di destinazione appartiene a un altro merchant o, con una chiave sandbox, è un conto live.

Salva gli ID delle risorse insieme all'ambiente e allo spazio che li hanno creati. Usa la chiave corrispondente per ogni richiesta successiva su quelle risorse.

## Conserva le credenziali in sicurezza

Conserva le chiavi sandbox e di produzione in voci separate del secret manager. Concedi a ogni deployment del backend l'accesso solo alla voce di cui ha bisogno.

Tieni le chiavi fuori dal controllo sorgente, dai log, dagli analytics, dagli screenshot di supporto e dalle risposte di errore. Ruota una chiave se ritieni che sia stata esposta.

Se una richiesta restituisce `unauthorized` o `forbidden`, usa [Errori e nuovi tentativi](/integration/errors) per distinguere le credenziali non valide dai permessi mancanti.

Successivamente, [configura i test in sandbox](/it/integration/sandbox) o inizia la [Quickstart](/it/integration/quickstart).
