Crea el cliente antes de construir un cobro, pago o cuenta bancaria emitida. Las capacidades, cuentas y transferencias están asociadas a ese cliente. Utiliza `externalId` como mapeo estable al registro correspondiente en tu sistema.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Clientes individuales {#individual-customers}

Un individuo solo requiere `type`. Incluye los campos de perfil que ya conozcas y añade más solo cuando la capacidad o tarea actual los necesite.

Crea el cliente con [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Guarda el `data.id` devuelto como `CUSTOMER_ID`. Consulta [Onboarding de individuos](/es/knowledge-base/individual-onboarding/overview) para el contexto de la política.

## Clientes empresa {#business-customers}

Una empresa requiere `business.legalName`. Crea la empresa con la misma operación:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Guarda el `data.id` devuelto como `CUSTOMER_ID`. Consulta [Onboarding de empresas](/es/knowledge-base/business-onboarding/overview) para el contexto de política y documentos.

## Añade partes relacionadas de la empresa

Añade directores, propietarios y otros participantes de la empresa cuando sean conocidos o solicitados. Este ejemplo crea un director con [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Guarda el `data.id` devuelto como `RELATED_PARTY_ID`.

## Exporta los datos del cliente {#export-customer-data}

Utiliza [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) para descargar un cliente o entregar el KYC aprobado a tu propio proyecto de Sumsub. Cada exportación requiere un `Idempotency-Key`; reenvía la misma clave y el mismo cuerpo para obtener el mismo resultado.

Selecciona el formato en el cuerpo de la solicitud.

<Tabs>
  <Tab title="JSON de perfil básico">

Devuelve el recurso público de cliente v3 como un archivo adjunto JSON con datos de perfil, dirección, fiscales, metadatos y partes relacionadas. No se incluyen los documentos ni sus metadatos.

```json
{
  "format": "json_basic_data"
}
```

  </Tab>
  <Tab title="Token de compartición de Sumsub">

Crea un token de compartición de Sumsub de un solo uso para un cliente individual aprobado, de modo que el proyecto de Sumsub receptor pueda importar los datos de KYC. Los clientes empresa devuelven `422 invalid_field_for_type`.

```json
{
  "format": "sumsub_share_token",
  "forClientId": "partner-sumsub-client-id"
}
```

`forClientId` es tu `clientId` de Sumsub, no el `customerId` de Swipelux. Identifica el proyecto de Sumsub que recibirá los datos del solicitante, por lo que el valor lo eliges tú.

La respuesta devuelve `provider`, `token` y `expiresAt` (segundos Unix):

```json
{
  "data": {
    "provider": "sumsub",
    "token": "_shr-...",
    "expiresAt": 1800000000
  }
}
```

Pasa `token` a la API de importación de tokens de compartición de Sumsub para el proyecto identificado por `forClientId` antes de `expiresAt`. Úsalo una sola vez. Para reemitirlo, llama a la exportación de nuevo con un nuevo `Idempotency-Key`.

  </Tab>
</Tabs>

## Lee la disponibilidad desde las capacidades

Un cliente no tiene un estado de verificación o disponibilidad en la API. Lee el cliente con [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) para obtener los datos actuales del perfil, luego utiliza las capacidades y sus `openTaskIds` para decidir qué puede hacer el cliente a continuación.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

A continuación, pasa a [Capacidades y tareas](/es/integration/onboarding/capabilities-and-requirements) para descubrir y activar el resultado de producto que necesites.
