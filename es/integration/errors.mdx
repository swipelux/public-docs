---
title: "Errores y reintentos"
description: "Gestiona cada código de problema público de la API de Swipelux, decide cuándo reintentar y resuelve fallos de validación, estado, idempotencia y plataforma."
---

Los errores de la API de Swipelux usan el tipo de medio `application/problem+json`. Ramifica el comportamiento de tu aplicación según el valor estable de `code` y luego usa la operación y la guía siguientes para resolver el fallo.

| Campo | Cómo usarlo |
| --- | --- |
| `type` | URI de documentación estable para el código de problema. |
| `title` | Título breve del problema, legible para humanos. |
| `status` | Estado HTTP asociado a esta respuesta. |
| `code` | Valor estable legible por máquinas para la lógica de la aplicación. |
| `detail` | Texto contextual legible para humanos de esta ocurrencia. No lo analices ni lo compares. |
| `correlationId` | Identificador de la solicitud para guardar en los logs e incluir al contactar con soporte. |
| `retryable` | Cuando es `true`, la misma solicitud puede tener éxito más tarde. Cuando es `false`, cambia la solicitud o satisface un requisito previo antes de volver a intentarlo. |
| `errors[]` | Detalles de validación a nivel de campo, incluido un puntero JSON cuando está disponible. |

Reintenta las escrituras idempotentes con el `Idempotency-Key` original y el método, la ruta y el cuerpo sin cambios. Nunca reutilices esa clave para una operación prevista diferente.

```json
{
  "type": "https://docs.swipelux.com/errors/validation-error",
  "title": "Validation Error",
  "status": 400,
  "code": "validation_error",
  "detail": "The request contains invalid fields.",
  "correlationId": "01JERRORVALIDATION",
  "retryable": false,
  "errors": [
    {
      "pointer": "/externalId",
      "code": "invalid_format",
      "message": "Use a valid external identifier."
    }
  ]
}
```

### `forbidden`

**Estado HTTP:** `403`<br />
**Reintentable:** No<br />
**Tipo de problema:** `https://docs.swipelux.com/errors/forbidden`

**Significado:** La clave de API es válida, pero no tiene permiso para realizar esta operación.

**Cuándo ocurre:** La credencial carece de un permiso requerido, o una credencial de producción llama a un endpoint exclusivo del sandbox.

**Qué hacer:** Usa una credencial del entorno correcto con los permisos requeridos. No expongas ni sustituyas claves en código del lado del cliente.

**Guía de reintento:** No reintentes la solicitud sin cambios. Aplica la acción anterior antes de enviar otra solicitud.

**Operaciones de API relevantes:** Todas las operaciones autenticadas de la API.

### `invalid_field_for_type`

**Estado HTTP:** `400`, `422`<br />
**Reintentable:** No se devuelve<br />
**Tipo de problema:** `https://docs.swipelux.com/errors/invalid-field-for-type`

**Significado:** La solicitud incluye campos que no son válidos para el tipo de recurso seleccionado.

**Cuándo ocurre:** Una solicitud discriminada, como un perfil individual frente a uno de empresa, contiene campos de otra variante u omite campos requeridos por el tipo seleccionado.

**Qué hacer:** Usa el esquema del tipo seleccionado, elimina los campos que pertenezcan a otras variantes, proporciona sus campos requeridos y envía una solicitud corregida.

**Guía de reintento:** Este problema no devuelve `retryable`. No asumas que un reintento sin cambios es seguro; sigue la acción anterior y los requisitos de idempotencia de la operación.

### `request_body_too_large`

**Estado HTTP:** `413`<br />
**Reintentable:** No<br />
**Tipo de problema:** `https://docs.swipelux.com/errors/request-body-too-large`

**Significado:** El cuerpo de la solicitud supera el tamaño aceptado por la operación.

**Cuándo ocurre:** Un envío de tarea manda más datos de solicitud de los que la API puede procesar en un solo cuerpo.

**Qué hacer:** Elimina los datos innecesarios, usa referencias de documento en lugar de incrustar el contenido de los archivos y envía un envío más pequeño que siga respondiendo a los requisitos actuales.

**Guía de reintento:** No reintentes la solicitud sin cambios. Aplica la acción anterior antes de enviar otra solicitud.

**Operaciones de API relevantes:**

- [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) (`createCustomerTaskSubmission`, estado `413`)

### `unauthorized`

**Estado HTTP:** `401`<br />
**Reintentable:** No<br />
**Tipo de problema:** `https://docs.swipelux.com/errors/unauthorized`

**Significado:** A la solicitud le falta una clave de API válida.

**Cuándo ocurre:** La cabecera `X-API-Key` está ausente, no es válida, expiró o la API no la reconoce.

**Qué hacer:** Envía la clave correcta específica del entorno desde un backend protegido. Rota la clave si pudo haber quedado expuesta.

**Guía de reintento:** No reintentes la solicitud sin cambios. Aplica la acción anterior antes de enviar otra solicitud.

**Operaciones de API relevantes:** Todas las operaciones autenticadas de la API.
