Esta página muestra los cambios fechados de la API de Swipelux. Cada entrada indica la versión afectada, el tipo de cambio y cualquier acción requerida por parte de los integradores.

Para actualizar una integración existente desde una versión anterior, consulta [Migrar a v3](/es/api-reference/versioning/migrate-to-v3).

## Sin publicar

_Los próximos cambios se listarán aquí antes de su lanzamiento._

## 2026-08-24

**Versión:** v3

### Añadido
- Las claves de API ahora exponen los permisos de la Rules API, para que puedas limitar las claves a la gestión de reglas junto con los alcances existentes. Consulta [Autenticación](/es/integration/authentication).
- El onboarding del primer payin ahora requiere una wallet de cliente en Polygon antes de continuar. Consulta [Cuentas](/es/integration/accounts).

### Cambiado
- La primera página del KYB ya no recopila la fecha de nacimiento del representante. Se captura más adelante en el flujo. Consulta [Flujo de KYB](/es/knowledge-base/business-onboarding/kyb-workflow).
- Las cargas de documentos ahora aceptan el alias MIME `image/jpg` además del canónico `image/jpeg`. Consulta [Requisitos de documentos](/es/knowledge-base/business-onboarding/document-requirements).
- El historial de tareas oculta los contadores internos de revisión. Los revisores ven un rastro de auditoría más limpio y legible. Consulta [Capacidades y requisitos](/es/integration/onboarding/capabilities-and-requirements).
- La configuración de cuentas UAEFTS v1 ha sido retirada. Las nuevas cuentas de desembolso en AED usan el rail actual.

### Corregido
- Los formularios RFI conservan las entradas existentes cuando un revisor añade una nueva solicitud de documento, de modo que las respuestas ya proporcionadas no se pierden al reenviar.
- Las sesiones de compliance conservan los enlaces válidos y respetan la acción explícita devuelta por el contrato de sesión, eliminando continuaciones bloqueadas.
- Compliance acepta los nombres canónicos de scopes para los flujos de ToS, por lo que las integraciones que usan los valores de scope documentados se completan correctamente.
- El acceso al pago ahora abre el intake propiedad de la aplicación en lugar de uno obsoleto propiedad del cliente.
- El onboarding de demo de KYB se alinea con los contratos de wallet, y las entradas de merchant self-customer ya no aparecen en la lista de clientes.
- La API rechaza la codificación mal formada del query string con un error `400` en lugar de normalizar silenciosamente la solicitud, de modo que las entradas inválidas se detectan antes. Consulta [Errores y reintentos](/integration/errors).
- Los endpoints de carga de documentos rechazan las solicitudes con cuerpos vacíos o mal formados con un error `400`.

## 2026-08-17

**Versión:** v3

### Añadido
- Se publicó el catálogo de Problem Details de v3 en la especificación OpenAPI para que los integradores puedan asignar las respuestas de error directamente desde el esquema. [Errors](/integration/errors).
- Se añadió `customerId` a los eventos webhook de cuenta en v3, lo que te permite correlacionar la actividad de cuenta con el cliente propietario sin una lectura adicional. Consulta [Webhooks](/es/integration/webhooks).
- Cobertura completa de los campos del perfil individual en V3 en el panel del comerciante, para que los operadores de onboarding puedan revisar y editar cada campo KYC recopilado a través de la API v3. Consulta [Clientes](/es/integration/onboarding/customers).
- Se publicó una guía de migración para desarrolladores de v3. Consulta [Migrar a v3](/es/api-reference/versioning/migrate-to-v3).

### Cambiado
- Los códigos de país de clientes y cuentas ahora se validan como valores ISO 3166-1 alpha-2 asignados en el momento de la escritura. Las lecturas toleran los valores heredados almacenados para que los registros existentes sigan resolviéndose. Consulta [Cuentas y carteras](/es/integration/accounts).
- La disponibilidad de USDC en ahora se limita según la red de destino, por lo que las cotizaciones y transferencias solo ofrecen USDC en las redes que el destino realmente admite.
- `Capability.ready` indica que el derecho está aprobado, no que exista una cuenta emitida. Usa `accountProvisioning` para seguir la emisión de la cuenta: `not_applicable`, `not_started`, `in_progress`, `issued` o `failed`.
- Ahora se aceptan las subidas HEIC desde iPhone como documentos de identidad y de domicilio.

### Corregido
- Volver a ejecutar una cotización ya consumida ahora devuelve `409 quote_execution_consumed` en lugar de un error genérico. Consulta [Cotizaciones y transferencias](/es/integration/quotes-and-transfers).
- Las lecturas de la lista de transferencias y de los importes de cotización ya no devuelven `500` en resultados históricos grandes.
- Las lecturas de partes relacionadas para clientes individuales ya no devuelven `404`.
- Las filas de enlaces de verificación en el panel del comerciante ahora muestran una acción **Open** en cada fila, y cada enlace de tarea de infraestructura de wallet se representa en la vista de requisitos.
