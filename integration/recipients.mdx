---
title: "Recipients and destinations"
description: "Create a third-party recipient and prepare a bank or wallet payout destination."
---

Use an account when the customer owns the destination; use a recipient and destination for another person or business.

A recipient records the third party. A destination records where that third party receives funds. Keep this ownership boundary explicit before you create a payout.

Use one recipient for the person or business relationship, then attach the bank or wallet endpoints that belong to that recipient. Do not put customer-owned endpoints under a recipient to make the payout shape look uniform; customer accounts and third-party destinations have separate ownership and readiness rules.

## Create an addressed recipient

Create the individual first with [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients). Include a complete address before you add any fiat destination, because the destination can depend on recipient address data.

### Individual recipient

```json
{
  "type": "individual",
  "relationship": "contractor",
  "firstName": "Jason",
  "lastName": "Swipelux",
  "email": "jason@swipelux.com",
  "phone": "+14155551234",
  "address": {
    "streetLine1": "1 Market Street",
    "city": "San Francisco",
    "state": "CA",
    "postalCode": "94105",
    "country": "US"
  },
  "label": "Jason contractor"
}
```

Store the recipient `data.id` and `data.status`. Read the current recipient with [`GET /v3/customers/{customerId}/recipients/{recipientId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id) before you attach or use changed information.

The recipient status and destination status are independent. Keep both values: a stored recipient ID does not prove that a newly created destination is ready for a quote.

Use the latest values whenever your application reopens this payout setup.

## Add a destination

Send the selected type to [`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations).

<Tabs>
  <Tab title="Bank destination">

```json
{
  "type": "ach",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "JPMorgan Chase",
    "accountHolderName": "Jason Swipelux",
    "country": "US"
  }
}
```

  </Tab>
  <Tab title="Wallet destination">

```json
{
  "type": "wallet",
  "currency": "USDC",
  "ownership": {
    "type": "self_custodied"
  },
  "details": {
    "network": "base",
    "address": "0x1111111111111111111111111111111111111111"
  }
}
```

  </Tab>
</Tabs>

The wallet `ownership` object is a declaration needed by the request. Use `self_custodied` only when the recipient controls the wallet; a custodial declaration also requires the custodian name.

Store the destination `data.id` and `data.status`. Before quoting a payout, read it with [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id). Use a bank or wallet destination only when the current destination `data.status` is `ready` and its currency and network or method fit the movement.

For a bank destination, keep the destination currency with the destination ID and select a quote capability that supports the intended payout. For a wallet destination, compare both currency and network with the source movement. A valid create body does not by itself establish that pairing.

## Maintain current resources

Read current resources before you update them, and archive only after you have removed them from new payout selection. [`PATCH /v3/customers/{customerId}/recipients/{recipientId}`](/api-reference/recipients/patch-v3-customers-by-customer-id-recipients-by-recipient-id) changes supported recipient fields. Refetch the recipient before displaying or using those changes.

[`DELETE /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/delete-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id) archives one destination, while [`DELETE /v3/customers/{customerId}/recipients/{recipientId}`](/api-reference/recipients/delete-v3-customers-by-customer-id-recipients-by-recipient-id) archives the recipient. Treat archive as terminal and keep archived IDs out of new quote requests.

Apply safe write behavior from [API reliability](/integration/api-reliability).
