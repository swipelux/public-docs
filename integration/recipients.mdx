---
title: "Recipients and destinations"
description: "Create a third-party Swipelux recipient and the bank account or crypto wallet destination that receives a payout, and reuse them across future transfers."
---

Use a customer account when the customer owns the endpoint. Use a recipient and destination when another person or business receives the funds.

The recipient records who receives funds. The destination records where they receive them.

## 1. Create the recipient

Create an individual or business with [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients). Send these headers:

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-create-001
Content-Type: application/json
```

```json Request body
{
  "type": "individual",
  "relationship": "contractor",
  "firstName": "Jason",
  "lastName": "Swipelux",
  "email": "jason@example.com",
  "phone": "+14155551234",
  "address": {
    "streetLine1": "1 Market Street",
    "city": "San Francisco",
    "state": "CA",
    "postalCode": "94105",
    "country": "US"
  },
  "label": "Jason contractor"
}
```

`relationship` describes how the recipient relates to your customer. Choose a value from the [`POST /v3/customers/{customerId}/recipients` request schema](/api-reference/recipients/post-v3-customers-by-customer-id-recipients). If you send `other`, do not add a companion free-text field. Swipelux ignores fields that the request schema does not define, so the text would not be stored.

Include the address before creating a fiat destination. Store the returned recipient `data.id` as `RECIPIENT_ID` and retain its current status.

## 2. Add a destination

Create the endpoint with [`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations). Use a new key for this intended destination:

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-destination-create-001
Content-Type: application/json
```

Pix and Pix Safe destinations receive BRL and need the customer's ready Pix capability (`pix_pooled`). A Pix destination pays a Pix key: a CPF or CNPJ in digits only, a phone number as `+55` followed by 10 or 11 digits, an email, or a random key. A Pix Safe destination pays a Brazilian bank account identified by the holder's CPF or CNPJ in `taxId`, the bank's 8-digit ISPB code in `bankCode`, the branch, and the account number with its check digit. Responses and webhooks return `taxId` masked to its last four digits.

A Faster Payments destination pays a UK bank account in GBP. Any other `currency` returns `400 validation_error`. Send the 6-digit `sortCode` and the 8-digit `accountNumber`. Swipelux removes spaces and hyphens before validating them. `country` defaults to `GB`. Payouts to it need the customer's ready pooled Faster Payments capability (`faster_payments_pooled`) and are sent in the Bank's name, not the customer's. A named GBP account (`faster_payments_named`) receives funds only.

A NIP destination pays a Nigerian bank account in NGN. Any other `currency` returns `400 validation_error`. Send the 10-digit NUBAN `accountNumber`, with spaces and hyphens removed before validation, and a `bankId` from `GET /v3/recipients/banks?country=NG`. A `bankId` not on that list returns `400 recipient_destination_invalid`. If the bank list is temporarily unavailable, either call returns `503 request_failed` with `retryable: true`. `country` defaults to `NG`. Payouts to it need the customer's ready NIP capability (`nip_pooled`).

An NPP destination pays an Australian bank account in AUD. Any other `currency` returns `400 validation_error`. Send the 6-digit `bsb` and an `accountNumber` of 5 to 9 digits. Swipelux removes spaces and hyphens before validating them. `country` defaults to `AU`. Payouts to it need the customer's ready NPP capability (`npp_pooled`).

An IPP destination pays a UAE bank account in AED. Any other `currency` returns `400 validation_error`. Send a 23-character `iban` starting with `AE`. Swipelux removes spaces and uppercases it, then checks its format and checksum. `country` defaults to `AE`. Payouts to it need the customer's ready IPP capability (`ipp_named`) and a payout purpose on the quote, as described in [Quotes and transfers](/integration/quotes-and-transfers). The recipient also needs `address.streetLine1`. Without it, the payout quote returns `400 validation_error`.

A SEPA destination pays in EUR. Payouts to it need the customer's ready SEPA capability: `sepa_named` sends them in the customer's own name, and `sepa_pooled`, for a customer without a named EUR account, sends them in the Bank's name. `bic` is optional. A SEPA destination in another currency, or one created before November 21, 2026, reads `action_required` with `statusReason.code` set to `destination_provider_retired`. Create a new EUR SEPA destination with the same bank details instead.

Swipelux validates bank identifiers such as IBANs, BICs, ABA routing numbers, and CPF or CNPJ numbers, including checksums, when you create a bank destination. Malformed values return `400 validation_error`. These checks confirm format only, not that the account exists or who owns it.

Use `self_custodied` only when the recipient controls the wallet. Follow the current API Reference variant when the wallet is held by another custodian.

Store the returned destination `data.id` as `DESTINATION_ID` and retain its current status.

## 3. Wait for destination readiness

Read [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id) before creating a quote.

Continue only when the current destination status permits the payout and its currency, method, and network match the intended movement. Recipient and destination statuses are independent.

Use the `dst_` destination ID in the payout quote. The `rcp_` recipient ID identifies the owner record and is not a quote destination.

Next, take the ready destination to [Send funds](/integration/send-funds).
