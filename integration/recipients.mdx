---
title: "Recipients"
description: "Create third-party recipients and their bank or wallet payout destinations."
---

Use customer accounts for first-party movements. Use recipients and recipient destinations when funds land with a third-party relationship.

<Warning>
Call recipient operations from your backend with `X-API-Key`. Do not expose the key to a browser or client.
</Warning>

## Keep ownership boundaries explicit

- **Recipient types:** `individual`, `business`
- **Recipient statuses:** `active`, `rejected`, `archived`
- **Destination types:** `sepa`, `swift`, `ach`, `wire`, `spei`, `pse`, `transfers_3_0`, `wallet`
- **Destination statuses:** `in_review`, `ready`, `action_required`, `archived`

First-party payouts target customer accounts. Third-party payouts target recipient destinations. Do not create a recipient destination for a customer-owned account; use [Accounts](/integration/accounts) instead.

## Create the recipient

Create an individual or business recipient with [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients). There is no universal recipient or destination payload. The individual variant requires `type`, `relationship`, `firstName`, and `lastName`. The business variant requires `type`, `relationship`, and `companyName`.

## Add a payout destination

Add a recipient-owned destination with [`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations). Select the exact type-specific schema. Fiat destinations require their matching bank details; wallet destinations require `currency`, `details.network`, `details.address`, and an `ownership` declaration.

Wallet `ownership` is a declaration only; verification is not performed at creation. For `self_custodied`, omit `custodianName`. `custodial` requires a non-empty `custodianName`.

<Tabs>
  <Tab title="ACH">

```json
{
  "type": "ach",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "JPMorgan Chase",
    "accountHolderName": "Jason Swipelux",
    "country": "US"
  }
}
```

  </Tab>
  <Tab title="Wallet">

```json
{
  "type": "wallet",
  "currency": "USDC",
  "ownership": {
    "type": "self_custodied"
  },
  "details": {
    "network": "base",
    "address": "0x1111111111111111111111111111111111111111"
  }
}
```

  </Tab>
</Tabs>

For fiat destinations, a missing recipient address can return `recipient_address_required`. Ready bank destinations can be fiat quote targets when other quote checks pass. Compatible ready wallet destinations can be stablecoin-move quote targets when they use the same network and asset as the source. `statusReason` is present exactly when destination status is `action_required`; it contains `code`, `message`, `actor`, and `retryable`. Actor is `customer`, `developer`, `provider`, `network`, or `swipelux`.

## Read and maintain current resources

List recipients with [`GET /v3/customers/{customerId}/recipients`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients). Read one recipient and its destinations with [`GET /v3/customers/{customerId}/recipients/{recipientId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id).

List active destinations with [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations). When you supply `updatedAfter`, the inclusive recovery window also returns archived transitions. Read one current destination with [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id).

Update supplied fields on an active recipient with [`PATCH /v3/customers/{customerId}/recipients/{recipientId}`](/api-reference/recipients/patch-v3-customers-by-customer-id-recipients-by-recipient-id). Read the current recipient again before using changed data.

Archive a recipient with [`DELETE /v3/customers/{customerId}/recipients/{recipientId}`](/api-reference/recipients/delete-v3-customers-by-customer-id-recipients-by-recipient-id). Archive is terminal, and archived recipients reject later updates. Archive one destination with [`DELETE /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/delete-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id).

## Replay writes safely

Follow [Request safety](/integration/request-safety) for every write below. Each operation requires `Idempotency-Key`. Generate a fresh key for each intended effect.

- [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients) requires `Idempotency-Key`.
