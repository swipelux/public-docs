description: "Follow every cursor, replay overlapping change windows, and advance checkpoints only after complete success."

Use reconciliation to keep your local records aligned when webhook processing is delayed, interrupted, or missed.

## Read a complete change window

Use `updatedAfter` only on list operations that define it. For those operations, it is an inclusive RFC 3339 lower bound: records updated exactly at the supplied timestamp can appear again.

Start each run at your saved checkpoint minus an overlap chosen for your system. Follow every cursor and collect current resource representations before advancing the checkpoint. This JavaScript-shaped loop uses the response fields returned by [`GET /v3/customers`](/api-reference/customers/get-v3-customers):

For the first run, choose a deliberate RFC 3339 timestamp at or before the earliest data your integration must backfill. Do not initialize it to the current timestamp; that could skip records that already exist.

```js
async function reconcileCustomers({ checkpoint, overlap }) {
  const updatedAfter = checkpointMinusOverlap(checkpoint, overlap);
  const resourcesById = new Map();
  let cursor;
  let hasMore;
  const runStartedAt = new Date().toISOString();

  do {
    const query = new URLSearchParams({ updatedAfter });
    if (cursor) query.set("cursor", cursor);

    const response = await fetch(
      `https://platform.swipelux.com/v3/customers?${query}`,
      { headers: { "X-API-Key": process.env.SWIPELUX_API_KEY } },
    );
    if (!response.ok) throw new Error(`List failed: ${response.status}`);

    const { data, nextCursor, hasMore: morePages } = await response.json();

    for (const resource of data) resourcesById.set(resource.id, resource);
    cursor = nextCursor;
    hasMore = morePages;
  } while (hasMore);

  for (const resource of resourcesById.values()) {
    await applyCurrentState(resource.id, resource);
  }

  await saveCheckpoint(runStartedAt);
}
```

Deduplicate by resource ID across the complete window. Apply the current state for each ID instead of replaying an assumed sequence of intermediate changes.

## Advance the checkpoint after success

Capture `runStartedAt` once immediately before the first API request. Save that exact timestamp only after every page has been read and every resource update has succeeded. If any page or local apply fails, retain the prior checkpoint and retry the window with the same overlap. Repeated records are expected because the lower bound is inclusive and the windows overlap.

Choose overlap from your own processing and clock characteristics. The API does not prescribe one fixed duration.
