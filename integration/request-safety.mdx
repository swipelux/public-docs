---
title: "Request safety"
description: "Use idempotency and contract retry signals to make API requests safely."
---

Idempotency is operation-specific. For each operation, treat the generated operation page, backed by the committed `openapi.json`, as authoritative for required request headers and documented response headers.

When an operation declares `Idempotency-Key` as required, generate a unique key for each intended effect. The normal integration guides use effectful customer, capability, task, account, recipient, quote, transfer, and webhook operations that declare this header.

The six current `/v3/sandbox/*` `POST` helpers do not declare `Idempotency-Key`. Do not add the header to sandbox helper examples unless their generated operation page changes.

## Retry after uncertainty

If transport uncertainty prevents you from receiving a response, reuse the original key with an identical body. Do not change the body while reusing that key.

The generated operation pages document the `idempotency_conflict` and `idempotency_request_in_progress` Problem responses where they apply. Do not assume either response exists for every operation. Follow the returned fields instead of inferring behavior beyond the contract.

## Check replay headers separately

Rely on `Idempotency-Replayed: true` only for operations or responses that document the `Idempotency-Replayed` header. Check the generated operation page rather than rely on this header universally.

For example, quote creation and transfer creation document the replay response header. Transfer cancellation requires `Idempotency-Key`, but its responses do not document `Idempotency-Replayed`.

## Retry reads and failures deliberately

Safe read retries start with `GET`: retry a read after a transient transport failure according to your own bounded client policy. For API failures, use `Problem.retryable` together with HTTP `status` and stable `code`.

Do not blindly retry validation, authentication, or conflict failures. Inspect the current resource and request before deciding whether another attempt is appropriate.
