---
title: "Authentication"
description: "Authenticate public API requests with X-API-Key from a protected backend boundary."
---

The public OpenAPI security scheme is `apiKey`. Send the key in the `X-API-Key` request header.

Production and sandbox use the same base URL:

```text
https://platform.swipelux.com
```

The environment is selected by the API key.

<Warning>
  In your integration, keep every key in your backend service's secret manager. Never embed a key in browser code, mobile application bundles, public repositories, logs, or analytics events.
</Warning>

For example, call [`GET /v3/capabilities`](/api-reference/capabilities/get-v3-capabilities) from your backend:

```bash
curl --request GET \
  "https://platform.swipelux.com/v3/capabilities" \
  --header "X-API-Key: YOUR_API_KEY"
```

Use separate secret-manager entries for each environment, and select the intended entry in your server-side deployment configuration.
