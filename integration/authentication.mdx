Authenticate every API request from a protected backend service.

## Send your API key

Use the shared base URL `https://platform.swipelux.com` and send your key in the `X-API-Key` header. Do not expose the key in browser code or mobile application bundles.

## Make your first request

Call [`GET /v3/capabilities`](/api-reference/capabilities/get-v3-capabilities) to confirm that your backend can reach the API:

```bash
curl --request GET \
  "https://platform.swipelux.com/v3/capabilities" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

## Sandbox and production

Sandbox and production share `https://platform.swipelux.com`. Your API key selects sandbox or production, so keep environment selection in server-side deployment configuration.

## Store credentials safely

Store sandbox and production keys in separate secret-manager entries. Grant each backend deployment access only to the entry it needs, and keep keys out of source code, logs, analytics, and client-visible error messages.
