title: "Customers"
description: "Create the individual or business that will use a pay-in, payout, or issued bank account flow."
---

Start with the customer that owns the pay-in, payout, or issued bank account flow. Capabilities, accounts, and transfers stay scoped to that customer.

Use `externalId` as your stable mapping from the Swipelux customer to the corresponding record in your system.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Individual customers

Create an individual with [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Store the returned `data.id` as `CUSTOMER_ID`. For policy and verification context, see [Individual onboarding](/knowledge-base/individual-onboarding/overview).

## Business customers

Create a business with [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Store the returned `data.id` as `CUSTOMER_ID`. For business policy and document context, see [Business onboarding](/knowledge-base/business-onboarding/overview).

## Add business related parties

After creating a business customer, add a person related party with [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Store the returned `data.id` as `RELATED_PARTY_ID`.

## Read the current customer

Read the current customer before making decisions from its data with [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id):

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```
