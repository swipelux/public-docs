The [Swipelux neobank starter](https://github.com/swipelux/neobank-starter) is a reference application you can run locally. Open the [public hosted demo](https://neobank-starter.vercel.app) to inspect the experience before cloning it. Do not enter any API key into the public hosted demo; use it only with built-in demo data.

## Run it locally

```bash
git clone https://github.com/swipelux/neobank-starter
cd neobank-starter
npm install
npm run dev
```

Follow the repository's setup instructions for the current environment variables and commands.

## Understand the data modes

- **Local demo data** lets you explore the interface without connecting the application to Swipelux.
- **Connected sandbox data** comes from API requests authenticated with a sandbox key.

The cloned starter's in-app connected-sandbox mode exposes a sandbox key to browser runtime. This is demo-only behavior outside the production credential architecture. Never use a production key in this mode.

<Warning>
  A sandbox key is not a production credential. Connecting it does not authorize production or real-money use.
</Warning>

Use the starter to learn the integration boundaries and adapt the application to your product. When adapting it for production, move all Swipelux API credentials behind a backend boundary backed by a secret manager, and complete the normal readiness process with Swipelux.
