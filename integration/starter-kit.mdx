The [public neobank starter](https://github.com/swipelux/neobank-starter) demonstrates customer onboarding, account views, quotes, transfers, and funding flows in one reference interface. Explore the [hosted demo](https://neobank-starter.vercel.app) with its built-in demo data. Never enter an API key in the hosted demo.

## Run it locally

```bash
git clone https://github.com/swipelux/neobank-starter
cd neobank-starter
npm install
npm run dev
```

The local application starts with built-in demo data and does not require API configuration for that mode.

## Choose a data mode

- **Built-in demo data** lets you explore the interface without calling Swipelux.
- **Connected sandbox data** uses API responses authenticated by a sandbox key.

The local connected-sandbox mode exposes the sandbox key to the browser runtime. Treat that browser exposure as demo-only. A sandbox key does not authorize production or real-money use, and you must never enter a production key in this mode.

For a production implementation, move Swipelux requests and production credentials behind your backend and store the key in a secret manager. Follow [Authentication](/integration/authentication) for the credential boundary.
