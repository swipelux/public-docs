title: "Rules"
description: "Create and manage standing sweeps from eligible custodial wallet accounts."

Rules are standing instructions. When funds become available on the watched account, the rule transfers those funds to its configured target.

<Warning>
Call rule operations from your backend with `X-API-Key`. Do not expose the key to a browser or client.
</Warning>

## Use the exact trigger and target shapes

The exact trigger is `funds_received` on a custodial wallet account identified by `trigger.accountId`. Fiat deposits are matched after they settle from an issued bank account into its settlement wallet account.

The action type is `transfer`. Its target is `account` for another custodial wallet account or `destination` for a recipient destination, including a non-custodial wallet destination.

At most one non-archived rule can watch a trigger account. A conflict returns `rule_already_exists` and identifies the existing rule in `conflictingRuleId`.

Create the rule with [`POST /v3/customers/{customerId}/rules`](/api-reference/rules/post-v3-customers-by-customer-id-rules). Use the current account and destination resources when you construct the request.

## Read and manage the lifecycle

- **Rule statuses:** `active`, `paused`, `archived`

List rules with [`GET /v3/customers/{customerId}/rules`](/api-reference/rules/get-v3-customers-by-customer-id-rules). Read the current rule with [`GET /v3/customers/{customerId}/rules/{ruleId}`](/api-reference/rules/get-v3-customers-by-customer-id-rules-by-rule-id). Archived rules stay readable for audit.

Pause or resume a rule and edit its label or metadata with [`PATCH /v3/customers/{customerId}/rules/{ruleId}`](/api-reference/rules/patch-v3-customers-by-customer-id-rules-by-rule-id). The writable statuses are `active` and `paused`. An archived rule is read-only and returns `rule_archived` when an update is attempted.

Archive a rule with [`DELETE /v3/customers/{customerId}/rules/{ruleId}`](/api-reference/rules/delete-v3-customers-by-customer-id-rules-by-rule-id). Archiving is terminal, frees the trigger account for a new rule, and the archived rule stays readable.

## Replay writes safely

- [`POST /v3/customers/{customerId}/rules`](/api-reference/rules/post-v3-customers-by-customer-id-rules) declares `Idempotency-Key`. Reuse a key only with the same body. Successful responses document `Idempotency-Replayed: true`.
- [`PATCH /v3/customers/{customerId}/rules/{ruleId}`](/api-reference/rules/patch-v3-customers-by-customer-id-rules-by-rule-id) declares `Idempotency-Key`. Reuse a key only with the same body. Successful responses document `Idempotency-Replayed: true`.
- [`DELETE /v3/customers/{customerId}/rules/{ruleId}`](/api-reference/rules/delete-v3-customers-by-customer-id-rules-by-rule-id) declares `Idempotency-Key`. Reuse a key only with the same request. Successful responses document `Idempotency-Replayed: true`.
