title: "API reliability"
description: "Use idempotency, safe retries, errors, and correlation IDs in production."
---

Make each write safe to retry and keep enough context to investigate uncertain outcomes.

## Retry writes safely

Use an idempotency key for one intended effect. If a response is uncertain, retry with the same key and identical request body.

## Handle errors

Use the returned problem details and `retryable` value to choose the next action. Log the `correlationId` with your request context so you can trace failures.

## Next step

Add these controls to your write path, then review [Sync and reconciliation](/integration/sync-and-reconciliation) for recovery after missed updates.
