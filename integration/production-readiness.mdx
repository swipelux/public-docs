title: "Production readiness"

Use this checklist to move a tested integration into production without carrying sandbox credentials, configuration, or resource IDs into the launch environment.

## Launch checklist

- [ ] Store the production key separately from sandbox and use it only server-side in a secret manager. Follow [Authentication](/integration/authentication) for credential handling.
- [ ] Keep sandbox and production configuration and IDs separate; both use the same host, `https://platform.swipelux.com`, and the API key selects the environment. Do not treat a key change as automatic migration. Create required production resources separately and review [Sandbox](/integration/sandbox).
- [ ] Confirm intended customer capabilities and compliance approvals are complete for the launch scope. Read current availability and eligibility with [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported).
- [ ] Enable idempotency and correlation logging for production writes by applying [API reliability](/integration/api-reliability).
- [ ] Test durable webhook inbox recovery, portal or manual replay, and reconciliation from a retained checkpoint. Use [Webhooks](/integration/webhooks) with [Sync and reconciliation](/integration/sync-and-reconciliation).
- [ ] Enable account, recipient, destination, and transfer state monitoring. Read current state with [`GET /v3/customers/{customerId}/accounts`](/api-reference/accounts/get-v3-customers-by-customer-id-accounts), [`GET /v3/customers/{customerId}/recipients`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients), [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations), and [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers).
- [ ] Agree a low-risk production smoke test with Swipelux before broad writes. Define the customer, capability, expected readback, operator owner, and stop condition for that test.

When every check is complete, run the agreed smoke test and verify its current resources. After it succeeds, expand production writes gradually while your [operational recovery paths](/integration/webhooks) remain enabled.
