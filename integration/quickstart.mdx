title: "Quickstart"
description: "Create a sandbox customer, enable a capability, and build a pay-in, payout, or issued bank account flow."
---

Create a customer, enable the capability that matches your intended outcome, and run one complete sandbox flow.

## 1. Configure sandbox

Use a sandbox API key from your backend:

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

The key selects the sandbox environment on the shared API host.

## 2. Create a customer

Create an individual customer with [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-customer-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "quickstart-customer-001"
}
JSON
```

Store the returned `data.id` as `CUSTOMER_ID`.

## 3. Choose the outcome

Choose one outcome before selecting a capability:

- **Pay-in:** receive fiat and settle USDC into an issued wallet.
- **Payout:** send funded USDC to a customer-owned account or recipient destination.
- **Issued bank account:** issue an ACH/USD account that settles into an issued wallet.

## 4. Find an eligible capability

List the customer's options with [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported):

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/capabilities/supported" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}"
```

Use the table below to choose an entry, then store its `id` as `CAPABILITY_ID`. Do not hardcode a universal capability ID.

| Goal | Capability fields to check | Account or destination model | Institution choice |
|---|---|---|---|
| Pay-in | `directions` includes `payin`; `method` matches the intended rail | Use an issued wallet account as `destinationId` | If `institutions` are returned, keep the applicable default or select a returned ID |
| Payout | `directions` includes `payout`; `method` matches the intended rail | Use a customer account ID or recipient destination ID as `destinationId` | Select only from returned `institutions` when you need an explicit choice |
| Issued bank account | `accountType` matches the intended issued-account model and `method` is appropriate | Create an issued bank account with an issued settlement wallet | Use a returned institution choice when the response offers one |

For every outcome, require `availability` to be `available` or `beta` and `eligibility.eligible` to be `true`.

## 5. Request the capability

Request the response-derived capability with [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-capability-001" \
  --header "Content-Type: application/json" \
  --data '{}'
```

An empty object uses the applicable defaults. If you intentionally choose institutions, send only IDs returned for that supported capability. Store `data.status` as `CAPABILITY_STATUS` and `data.openTaskIds` as `TASK_IDS`.

## 6. Complete onboarding in sandbox

If `TASK_IDS` is not empty, list the current tasks with [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks) and follow each current requirement:

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}"
```

Store the ID of each task you act on as `TASK_ID`, and use its current revision and requirements.

For this walkthrough, you can set the requested capability to `ready` with [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "status": "ready"
}
JSON
```

This is a sandbox test control, not production onboarding. Read the capability again with [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id):

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}"
```

Replace `CAPABILITY_STATUS` and `TASK_IDS` with the current `data.status` and `data.openTaskIds`. Continue only when the current status permits the selected operation.

## 7. Build the selected flow

<Tabs>
  <Tab title="Pay-in">

Create an issued USDC wallet on Base with [`POST /v3/customers/{customerId}/accounts`](/api-reference/accounts/post-v3-customers-by-customer-id-accounts):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/accounts" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-payin-wallet-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "origin": "issued",
  "type": "wallet",
  "currency": "USDC",
  "network": "base",
  "label": "Pay-in settlement wallet"
}
JSON
```

Store `data.id` as `ACCOUNT_ID`. Create a fiat-to-stablecoin quote with [`POST /v3/quotes`](/api-reference/money-movement/post-v3-quotes):

```bash
curl --request POST \
  "${API_BASE}/v3/quotes" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-payin-quote-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "externalId": "quickstart-payin-001",
  "in": {
    "amount": "150.00",
    "currency": "USD"
  },
  "destinationId": "${ACCOUNT_ID}",
  "out": {
    "currency": "USDC"
  }
}
JSON
```

Store `data.id` as `QUOTE_ID`. Execute the quote with [`POST /v3/transfers`](/api-reference/money-movement/post-v3-transfers):

```bash
curl --request POST \
  "${API_BASE}/v3/transfers" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-payin-transfer-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "quoteId": "${QUOTE_ID}"
}
JSON
```

Store `data.id` as `TRANSFER_ID`. Retrieve the returned funding instructions with [`GET /v3/transfers/{transferId}/instructions`](/api-reference/money-movement/get-v3-transfers-by-transfer-id-instructions):

```bash
curl --request GET \
  "${API_BASE}/v3/transfers/${TRANSFER_ID}/instructions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}"
```

Store the returned `data` as `FUNDING_INSTRUCTIONS`. Present the current instructions and any required reference exactly as returned.

  </Tab>

Create the issued USDC/Base source wallet with [`POST /v3/customers/{customerId}/accounts`](/api-reference/accounts/post-v3-customers-by-customer-id-accounts):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/accounts" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-payout-wallet-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "origin": "issued",
  "type": "wallet",
  "currency": "USDC",
  "network": "base",
  "label": "Payout source wallet"
}
JSON
```

Store `data.id` as `SOURCE_WALLET_ID`. Fund it in sandbox with [`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${SOURCE_WALLET_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "amount": "250.00",
  "currency": "USDC"
}
JSON
```

Store the returned `data.id` as `FUNDING_TRANSFER_ID`.

### Customer-owned account

Create an external ACH account with [`POST /v3/customers/{customerId}/accounts`](/api-reference/accounts/post-v3-customers-by-customer-id-accounts):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/accounts" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-payout-account-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "origin": "external",
  "type": "bank",
  "methods": ["ach"],
  "country": "US",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "Example Bank",
    "accountHolderName": "Amina Diallo"
  },
  "label": "Primary payout account"
}
JSON
```

Store `data.id` as `ACCOUNT_ID`, then use that value as `DESTINATION_ID`.

### Recipient destination

For a third party, create a recipient with [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/recipients" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-recipient-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "relationship": "contractor",
  "firstName": "Jason",
  "lastName": "Rivera",
  "email": "jason@example.com",
  "label": "Jason contractor"
}
JSON
```

Store `data.id` as `RECIPIENT_ID`. Add its ACH destination with [`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/recipients/${RECIPIENT_ID}/destinations" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-destination-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "ach",
  "currency": "USD",
  "details": {
    "routingNumber": "021000021",
    "accountNumber": "123456789",
    "accountType": "checking",
    "bankName": "Example Bank",
    "accountHolderName": "Jason Rivera",
    "country": "US"
  }
}
JSON
```

Store `data.id` as `DESTINATION_ID`. Use either the customer account ID or recipient destination ID in the quote.

Create a stablecoin-to-fiat quote with [`POST /v3/quotes`](/api-reference/money-movement/post-v3-quotes):

```bash
curl --request POST \
  "${API_BASE}/v3/quotes" \

  --header "Content-Type: application/json" \

  "capabilityId": "${CAPABILITY_ID}",

    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }

```

Store `data.id` as `QUOTE_ID`. Execute it with [`POST /v3/transfers`](/api-reference/money-movement/post-v3-transfers):

```bash
curl --request POST \
  "${API_BASE}/v3/transfers" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-payout-transfer-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "quoteId": "${QUOTE_ID}"
}
JSON
```

Store `data.id` as `TRANSFER_ID`.

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/accounts" \
```

Store `data.id` as `SETTLEMENT_WALLET_ID`. Create the issued ACH/USD account with [`POST /v3/customers/{customerId}/accounts`](/api-reference/accounts/post-v3-customers-by-customer-id-accounts):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/accounts" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: quickstart-bank-account-001" \

{
  "origin": "issued",
  "type": "bank",
  "method": "ach",
  "country": "US",
  "currency": "USD",

    "accountId": "${SETTLEMENT_WALLET_ID}"
```

```bash
curl --request GET \

  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}"
```

Store `data.status` as `BANK_ACCOUNT_STATUS` and `data.details` as `BANK_ACCOUNT_DETAILS`. Details may not be present immediately, so do not assume the account already has bank details.

For pay-ins and payouts, monitor the current transfer with [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id):

```bash
curl --request GET \
  "${API_BASE}/v3/transfers/${TRANSFER_ID}" \

```

Store the current `data.state` as `TRANSFER_STATE` and `data.stateDetail` as `TRANSFER_STATE_DETAIL` when it is returned.
