## KYB workflow

KYB workflow kombinuje aktuální zdroje zákazníka, souvisejících stran, capability, úkolů, odeslání a dokumentů s přezkoumáním politiky firmy a jejího vlastnictví.

<Warning>
  Výsledky a časové rámce KYB jsou odhady politiky. Nezaručují API
  přechody, schválení ani dostupnost.
</Warning>

## Aktuální sekvence workflow

### 1. Vytvořte firemního zákazníka

Vytvořte firemního zákazníka pomocí [`POST /v3/customers`](/api-reference/customers/post-v3-customers). Přečtěte aktuálního zákazníka pomocí [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id).

### 2. Udržujte související strany

Použijte [`GET /v3/customers/{customerId}/related-parties`](/api-reference/customers/get-v3-customers-by-customer-id-related-parties) pro zobrazení aktuálních stran, [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) pro vytvoření a [`PATCH /v3/customers/{customerId}/related-parties/{relatedPartyId}`](/api-reference/customers/patch-v3-customers-by-customer-id-related-parties-by-related-party-id) pro aktualizaci dodaných fakt.

Udržujte přímé vlastníky, mateřské subjekty, UBO, kontrolní osoby, ředitele, funkcionáře a signatáře, které vyžadují aktuální úkoly. Jejich role jsou odlišné.

### 3. Objevte a požádejte o vhodnou capability

Přečtěte [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported). Požádejte o dostupnou nebo beta capability pouze tehdy, když je zákazník způsobilý, pomocí [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id).

### 4. Přečtěte aktuální úkoly

Zjistěte aktuální práci pomocí [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks). Načtěte každý akční úkol přes [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task) a poté odvodíte další akci z jeho aktuální revize, požadavků a relací.

### 5. Nahrajte dokumenty požadované aktuálním úkolem

Nahrajte požadovaný soubor pomocí [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents). Aktuální úkol určuje, zda je dokument vyžadován, a může zúžit jeho přijímaný typ, počet nebo formát.

### 6. Odešlete kompletní odpovědi na úkol

Odešlete jednu kompletní sadu odpovědí pro aktuální revizi úkolu pomocí [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission). Používejte aktuální ID požadavků a odkazujte na ID nahraných dokumentů pouze tam, kde je úkol vyžaduje.

### 7. Monitorujte aktuální zdroje

Po každé akci nebo události znovu načtěte zákazníka pomocí [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id), capability pomocí [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id), její aplikace pomocí [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications) a všechny aktuální úkoly.

Pro kompletní mechaniku viz [onboarding firem](/cs/integration/onboarding/customers#business-customers), [Capabilities a úkoly](/cs/integration/onboarding/capabilities-and-requirements#complete-current-tasks) a [průvodce integračními dokumenty](/cs/integration/onboarding/capabilities-and-requirements#upload-documents).

## Spouštěče Enhanced due diligence (EDD)

EDD může být vyžadováno pro:

- Vysoce rizikové jurisdikce
- Vysoce rizikové vertikály, včetně gamingu, tradingu a kryptoburz
- Složité vlastnické struktury
- Očekávaný měsíční objem překračující platné prahové hodnoty
- Operace zahrnující sankcionované země

## Výsledky přezkoumání politiky

**Výsledek:** Schválení KYB, podmíněné schválení s limity nebo zamítnutí.

Toto jsou výsledky přezkoumání politiky, nikoli aktuální hodnoty stavů API. Podmíněné rozhodnutí politiky lze reflektovat přes aktuální zdroje bez vytváření stavu s názvem "conditional approval".

## Časový rámec ověření

| Fáze | Typická doba trvání |
| --- | --- |
| Nahrání dokumentu | Okamžitě |
| Počáteční přezkoumání | 1-2 pracovní dny |
| Standardní KYB | 2-5 pracovních dnů |
| EDD, pokud spuštěno | 5-10 pracovních dnů |

Tyto doby trvání jsou typické odhady politiky, nikoli zaručené chování API.

## Běžné důvody zamítnutí

| Důvod | Řešení |
| --- | --- |
| Chybějící dokumenty | Poskytněte každý typ dokumentu vyžadovaný aktuálním úkolem |
| Nezřetelné nebo rozmazané dokumenty | Poskytněte skeny nebo obrázky vyšší kvality |
| Neshodné informace | Ujistěte se, že název subjektu odpovídá napříč odeslanými důkazy |
| Neúplná vlastnická struktura | Poskytněte důkazy zohledňující 100 % vlastnictví |
| Vypršelé dokumenty | Poskytněte aktuální, platné dokumenty |

## Politika termínů a stavů API

Udržujte rozhodnutí politiky oddělená od aktuálních slovníků zdrojů:

- **Stav capability:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Stav aplikace:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Stav úkolu:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Výsledek odeslání:** `in_review`, `accepted`, `changes_requested`, `rejected`

Přečtěte nejnovější zdroj místo překládání výsledku politiky do hodnoty API.
