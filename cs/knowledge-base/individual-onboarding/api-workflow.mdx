## API workflow onboardingu fyzických osob

Použijte tuto mapu k propojení politiky KYC pro fyzické osoby s aktuální generovanou API referencí. Postupujte podle aktuálního zdroje v každém kroku místo implementování štítků z pohledu politiky jako stavového automatu API.

## Mapa workflow

### 1. Vytvořte fyzickou osobu jako zákazníka

Vytvořte zákazníka pomocí [`POST /v3/customers`](/api-reference/customers/post-v3-customers). Uložte vrácené id zákazníka a přečtěte aktuální zdroj pomocí [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id).

### 2. Objevte a požádejte o vhodnou capability

Přečtěte [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported). Vyberte variantu pouze tehdy, když aktuální dostupnost a způsobilost umožňují požadavek, poté použijte [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id).

### 3. Přečtěte aktuální capability a aplikace

Přečtěte [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id) a [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications). Postupujte podle aktuálních otevřených ID úkolů místo předpokládání připravenosti z dřívější odpovědi.

### 4. Načtěte detail aktuálního úkolu

Zjistěte úkoly zákazníka pomocí [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks). Načtěte autorizovanou akční plochu pomocí [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task).

Detail úkolu může vystavit URL hostovaných relací první strany a aktuální akční požadavky. Používejte jeho aktuální revizi a stav.

### 5. Dokončete hostované relace nebo odešlete odpovědi úkolu

Když detail úkolu poskytne hostovanou relaci, vraťte klientovi pouze potřebná data relace a API klíč držte v backendu.

Když úkol vyžaduje odpovědi, vytvořte jeden kompletní neměnitelný pokus pomocí [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission). Přečtěte jedno aktuální odeslání a jeho veřejný výsledek pomocí [`GET /v3/customers/{customerId}/tasks/{taskId}/submissions/{submissionId}`](/api-reference/task-submissions/get-customer-task-submission).

### 6. Nahrajte dokumenty pouze, když jsou vyžádány

Nahrávejte dokumenty pouze tehdy, když je aktuální úkol vyžaduje. Použijte [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents) a poté umístěte vrácené ID dokumentu do odpovídající odpovědi na dokument.

### 7. Znovu načtěte aktuální zdroje

Po každé události nebo akci znovu načtěte aktuálního zákazníka, capability, aplikace a úkol. Použijte jejich nejnovější stavy, důvody, požadavky a otevřené ID úkolů k výběru dalšího kroku.

## Mapa generovaných operací

| Zdroj | Generovaná operace | Použití |
| --- | --- | --- |
| Customers | [`POST /v3/customers`](/api-reference/customers/post-v3-customers) | Vytvořit fyzickou osobu jako zákazníka |
| Customers | [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) | Přečíst aktuální data zákazníka |
| Capabilities | [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported) | Objevit aktuální dostupnost a způsobilost |
| Capabilities | [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id) | Požádat o vybranou capability |
| Capabilities | [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id) | Přečíst aktuální stav capability a otevřené úkoly |
| Capabilities | [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications) | Přečíst aplikace institucí a jejich otevřené úkoly |
| Tasks | [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks) | Zjistit úkoly vlastněné zákazníkem |
| Tasks | [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task) | Přečíst aktuální požadavky a hostované relace |
| Task Submissions | [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) | Odeslat kompletní sadu odpovědí |
| Task Submissions | [`GET /v3/customers/{customerId}/tasks/{taskId}/submissions/{submissionId}`](/api-reference/task-submissions/get-customer-task-submission) | Přečíst autorizovaný snapshot odpovědi a výsledek |
| Documents | [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents) | Nahrát soubor vyžadovaný aktuálním úkolem |

## Pokyny k politice a implementaci

Zjednodušené, Standardní a Zvýšené KYC jsou politické úrovně. Nenahrazují aktuální stavy capability, aplikace, úkolu, odeslání, požadavků ani hostovaných relací.

Pro implementační detaily postupujte podle [průvodce onboardingem fyzických osob](/cs/integration/onboarding/customers#individual-customers), [Capabilities a úkoly](/cs/integration/onboarding/capabilities-and-requirements#complete-current-tasks) a [průvodce integračními dokumenty](/cs/integration/onboarding/capabilities-and-requirements#upload-documents).
