## Stav ověření a workflow

Cesta KYC z pohledu politiky přechází ze sběru informací přes přezkoumání až po rozhodnutí o schválení nebo zamítnutí. Aktuální API zdroje vystavují oddělené životní cykly capability, aplikace, úkolu a odeslání.

<Warning>
  Štítky přezkoumání politiky a odhady časování nedefinují chování API. Neimplementujte
  stavový automat podle štítků níže.
</Warning>

## Koncepty přezkoumání z pohledu politiky

Tyto koncepty přezkoumání z pohledu politiky popisují onboardingovou cestu. Nejsou to aktuální API enumy, hodnoty webhooků ani zaručené přechody.

| Štítek politiky | Význam |
| --- | --- |
| `not_started` | Zákazník existuje, ale práce KYC nezačala |
| `incomplete` | Práce KYC začala, ale chybí požadované informace |
| `pending_verification` | Přezkoumání čeká na dokončení zákazníkem |
| `under_review` | Odeslané informace nebo dokumenty jsou v přezkoumání |
| `approved` | Přezkoumání politiky schválilo zákazníka pro platné toky |
| `rejected` | Přezkoumání politiky zákazníka zamítlo |

Tyto štítky používejte pouze při diskuzi o cestě politiky. Neodesílejte je jako aktuální stavové hodnoty, pokud aktuální generované schéma explicitně nevyžaduje stejnou hodnotu ve svém vlastním kontextu.

## Tok standardního přezkoumání KYC

1. Vytvořte fyzickou osobu jako zákazníka.
2. Objevte a požádejte o vhodnou capability.
3. Přečtěte detail aktuálního úkolu.
4. Odešlete zákazníka do hostované ověřovací relace první strany nebo odešlete kompletní odpovědi úkolu vyžadované úkolem.
5. Nechte přezkoumání běžet, zatímco aktuální zdroje hlásí své vlastní stavy přezkoumání.
6. Znovu načtěte aktuální zdroje pro určení, zda je vyžadována další akce, nebo zda je capability připravená, omezená, zamítnutá nebo zrušená.

Cesta politiky to může popsat jako neaktivní, čekající na ověření, v přezkoumání a poté schváleno nebo zamítnuto. Tyto termíny nedefinují sekvenci přechodů API.

## Tok zvýšeného přezkoumání KYC

1. Dokončete aktuálně požadovanou standardní práci na identitě a liveness.
2. Přečtěte nejnovější úkol, když zvýšené přezkoumání vyžaduje dodatečné informace.
3. Poskytněte požadovaný doklad o adrese, doklad o prostředcích nebo jiné důkazy přes aktuální hostovanou relaci nebo odeslání úkolu.
4. Nahrávejte dokumenty pouze tehdy, když je aktuální úkol vyžaduje.
5. Během manuálního přezkoumání pokračujte v monitorování aktuálních zdrojů.
6. Zastavte nebo pokračujte podle aktuálních stavů capability, aplikace, úkolu a odeslání.

Compliance tým může také koordinovat zvýšené přezkoumání přes registrovanou e-mailovou adresu zákazníka.

## Běžné důvody zamítnutí

| Důvod | Řešení |
| --- | --- |
| Dokument není čitelný | Poskytněte jasný obraz ve vysokém rozlišení |
| Dokument vypršel | Poskytněte platný, nevypršelý doklad totožnosti |
| Obličej se neshoduje | Ujistěte se, že selfie jasně odpovídá fotografii na dokladu totožnosti |
| Neúplné informace | Poskytněte každou položku vyžádanou aktuálním úkolem |
| Podezřelá aktivita | Kontaktujte podporu pro manuální přezkoumání |

## Časový rámec ověření

| Fáze | Typická doba trvání |
| --- | --- |
| Nahrání dokumentu | Okamžitě |
| Automatizované kontroly | 1-3 minuty |
| Standardní přezkoumání | 1-24 hodin |
| Zvýšené přezkoumání | 1-3 pracovní dny |

Tyto doby trvání jsou typické odhady politiky, nikoli zaručené chování API.

## Aktuální slovníky stavů API

Aktuální zdroje používají oddělené uzavřené slovníky:

- **Stav capability:** `pending`, `ready`, `restricted`, `rejected`, `canceled`
- **Stav aplikace:** `requested`, `in_review`, `action_required`, `ready`, `rejected`, `disabled`, `canceled`
- **Stav úkolu:** `action_required`, `in_review`, `satisfied`, `rejected`, `canceled`
- **Výsledek odeslání:** `in_review`, `accepted`, `changes_requested`, `rejected`

Nesbalte tyto slovníky do jednoho stavu ověření.

## Události a aktuální stav

Používejte aktuálně zdokumentované [Webhooky](/cs/integration/webhooks) jako oznámení o změně a poté znovu načtěte aktuální zdroje zákazníka, capability, aplikace a úkolu. Události nenahrazují autoritativní čtení zdrojů a žádný štítek z pohledu politiky neimplikuje konkrétní událost.

Pro aktuální smyčku akcí viz [Capabilities a úkoly](/cs/integration/onboarding/capabilities-and-requirements#complete-current-tasks).
