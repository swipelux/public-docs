---
title: "Zákazníci"
description: "Vytvořte fyzickou osobu nebo firmu, která vlastní capabilities, účty a převody."
---

Zákazníka vytvořte předtím, než sestavíte příchozí platbu, výplatu nebo vydaný bankovní účet. Capabilities, účty a převody jsou vymezeny na daného zákazníka. Použijte `externalId` jako stabilní mapování na odpovídající záznam ve vašem systému.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Fyzické osoby {#individual-customers}

Fyzická osoba vyžaduje pouze `type`. Zahrňte profilová pole, která již znáte, a přidejte další jen tehdy, když je aktuální capability nebo úkol vyžaduje.

Vytvořte zákazníka pomocí [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Uložte vrácené `data.id` jako `CUSTOMER_ID`. Kontext politiky viz [Onboarding fyzických osob](/cs/knowledge-base/individual-onboarding/overview).

## Firemní zákazníci {#business-customers}

Firma vyžaduje `business.legalName`. Vytvořte firmu stejnou operací:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Uložte vrácené `data.id` jako `CUSTOMER_ID`. Kontext politiky a dokumentů viz [Onboarding firem](/cs/knowledge-base/business-onboarding/overview).

## Přidejte propojené strany firmy

Přidejte ředitele, vlastníky a další firemní účastníky, když jsou známi nebo vyžadováni. Tento příklad vytvoří ředitele pomocí [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Uložte vrácené `data.id` jako `RELATED_PARTY_ID`.

## Čtěte připravenost z capabilities

Zákazník nemá v API stav ověření ani připravenosti. Přečtěte zákazníka pomocí [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) pro aktuální data profilu, poté použijte capabilities a jejich `openTaskIds` k rozhodnutí, co může zákazník dělat dále.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Dále pokračujte na [Capabilities a úkoly](/cs/integration/onboarding/capabilities-and-requirements), kde objevíte a aktivujete potřebný produktový výsledek.
