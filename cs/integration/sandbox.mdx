Sandbox používá stejný API host jako produkce. Sandbox API klíč vybírá testovací prostředí, kde pomocníci simulují výsledky bez přesunu skutečných prostředků.

Uchovávejte klíč na svém backendu. Sandbox pomocníci nenahrazují produkční compliance ani onboarding.

Použijte [Chyby a opakování](/cs/integration/errors) k otestování toho, jak vaše integrace zpracovává validační a stavové chyby i opakovatelná selhání platformy vracená sandboxovými operacemi.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

## Test připravenosti capability

Po požadavku na capability nastavte její sandbox stav pomocí [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"status":"ready"}'
```

Po použití pomocníka znovu načtěte capability. Zacházejte s jejím aktuálním `status` a `openTaskIds` jako s výsledkem, který musí váš produkt zpracovat.

## Test otevřeného úkolu

Vytvořte sandboxový úkol pomocí [`POST /v3/sandbox/tasks`](/api-reference/sandbox/post-v3-sandbox-tasks). Navažte jej na prostředek, jehož pracovní postup testujete, a pomocí `items` popište, co má zákazník odeslat. Tato příručka ukazuje workflow pro capability a transfer; API Reference definuje customer scope a úplné schéma požadavku.

Pro textovou odpověď použijte položku `explanation` a pro nahrání souboru položku `document`. Nové položky `profile` také vyžadují `profilePointer`, JSON Pointer určující pole zákazníka. Další typy položek a pole najdete v [Create sandbox task](/api-reference/sandbox/post-v3-sandbox-tasks).

Pro příklad transferu nejprve vytvořte sandboxový transfer pomocí workflow [pay-in](/cs/integration/receive-funds) nebo [payout](/cs/integration/send-funds) a potom exportujte vrácené `data.id`:

```bash
export TRANSFER_ID='tr_replace_with_your_transfer_id'
```

Omezte úkol na kontrolovaný převod a vyžádejte dokument s `constraints`, které zúží přijímané typy, formáty a stáří.

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "transfer",
    "customerId": "${CUSTOMER_ID}",
    "transferId": "${TRANSFER_ID}"
  },
  "category": "transaction_rfi",
  "items": [
    {
      "type": "document",
      "request": "Upload a bank statement showing the source of funds for this transfer.",
      "constraints": {
        "acceptedDocumentTypes": ["bank_statement"],
        "acceptedFormats": ["pdf", "jpeg"],
        "maxAgeDays": 90
      }
    }
  ]
}
JSON
```

Příklad omezuje přijímaný typ, formát a stáří dokumentu. Všechny podporované podmínky dokumentu najdete v [Create sandbox task](/api-reference/sandbox/post-v3-sandbox-tasks).

Uložte `data.id` jako `TASK_ID`, `data.revision` jako `TASK_REVISION` a aktuální `data.requirements[0].id` jako `REQUIREMENT_ID`. Při volání [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) musí odpověď odpovídat vytvořené položce:

```bash

    {
      "requirementId": "${REQUIREMENT_ID}",

        "type": "text",
        "value": "Sandbox requirement completed."
      }
    }
  ]
}
JSON
```

  </Tab>

Nahrajte odpovídající soubor pomocí [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents), uložte vrácené `data.id` jako `DOCUMENT_ID` a odešlete jej jako odpověď s dokumentem:

```bash
curl --request POST \

  --header "Idempotency-Key: sandbox-task-document-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "document",
        "documentIds": ["${DOCUMENT_ID}"]
      }
    }
  ]
}
JSON
```

Poté aktuální odeslání přijměte nebo zamítněte pomocí [`POST /v3/sandbox/tasks/{taskId}/review`](/api-reference/sandbox/post-v3-sandbox-tasks-by-task-id-review):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks/${TASK_ID}/review" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"outcome":"accepted"}'
```

Pro produkční vzor dokončování úkolů použijte [Capabilities a úkoly](/cs/integration/onboarding/capabilities-and-requirements).

## Naplnění sandboxové peněženky

Připište prostředky vydané peněžence pomocí [`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${ACCOUNT_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"amount":"250.00","currency":"USDC"}'
```

Uložte vrácené `data.id` jako `TRANSFER_ID`, když chcete zkontrolovat simulovaný financovací převod.

ID topupu je ID převodu. Načtěte jej přes [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) nebo vypište přes [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers), abyste otestovali svůj kód pro příchozí vklady proti sandboxovým topupům. Projekce převodu je dokončený příchozí stablecoinový vklad s `origin: "inbound_deposit"`, `method: "stablecoin_transfers"` a `direction: "stablecoin_move"` a je vracen odpovídajícími filtry seznamu `accountId`, `origin`, `method` a `direction`.

## Dokončení nebo selhání převodu

Nastavte výsledek pomocí [`POST /v3/sandbox/transfers/{transferId}/state`](/api-reference/sandbox/post-v3-sandbox-transfers-by-transfer-id-state):

<Tabs>
  <Tab title="Dokončit">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"state":"completed"}'
```

  </Tab>
  <Tab title="Selhat">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "state": "failed",
  "stateDetail": {
    "code": "sandbox_review",
    "message": "Sandbox transfer failed."
  }
}
JSON
```

  </Tab>
</Tabs>
