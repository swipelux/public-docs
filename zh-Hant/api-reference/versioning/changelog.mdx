## 2026-08-24

**版本:** v3

### 新增
- API 金鑰現在會顯示 Rules API 權限,讓你可以將金鑰的授權範圍限定到規則管理,與既有的 scope 並列。請參閱[身份驗證](/zh-Hant/integration/authentication)。
- 首次 payin 上線流程現在需要先設定 Polygon 客戶錢包才能繼續。請參閱[帳戶](/zh-Hant/integration/accounts)。

### 變更
- KYB 首頁不再收集代表人的出生日期,改為在流程稍後階段擷取。請參閱[KYB 工作流程](/zh-Hant/knowledge-base/business-onboarding/kyb-workflow)。
- 文件上傳現在除了標準的 `image/jpeg` 之外,也接受 `image/jpg` MIME 別名。請參閱[文件需求](/zh-Hant/knowledge-base/business-onboarding/document-requirements)。
- 任務歷史紀錄會隱藏內部修訂計數。審核者可看到更整潔、易讀的稽核軌跡。請參閱[能力與需求](/zh-Hant/integration/onboarding/capabilities-and-requirements)。
- UAEFTS v1 帳戶設定已停用。新的 AED 撥款帳戶會使用目前的通道。

### 修正
- 當審核者新增文件補件請求時,RFI 表單會保留既有的填寫內容,因此重新送出時不再遺失先前提供的答案。
- Compliance 工作階段會保留有效連結,並遵循工作階段合約所回傳的明確動作,消除卡住的接續狀態。
- Compliance 接受 ToS 流程的標準 scope 名稱,因此使用文件中所載 scope 值的整合能夠正確完成。
- 付款存取現在會開啟由應用程式所擁有的收件流程,而非過期的客戶所擁有版本。
- KYB 示範上線流程與錢包合約一致,商戶自身客戶項目也不再出現於客戶清單中。
- API 現在會以 `400` 錯誤拒絕格式錯誤的查詢字串編碼,而非在背後自動正規化該請求,讓無效輸入更早浮現。請參閱[錯誤與重試](/integration/errors)。
- 文件上傳端點會以 `400` 錯誤拒絕請求主體為空或格式錯誤的請求。

## 2026-08-17

**版本:** v3

### 新增
- 在 OpenAPI 規範中發布 v3 Problem Details 目錄,讓整合方可以直接從 schema 對應錯誤回應。 [Errors](/integration/errors).
- 為 v3 帳戶 webhook 事件新增 `customerId`,讓您無需後續讀取即可將帳戶活動關聯至擁有的客戶。請參閱 [Webhook](/zh-Hant/integration/webhooks)。
- 商家後台完整支援 V3 個人檔案欄位,讓入駐操作人員可以審核並編輯透過 v3 API 收集的每個 KYC 欄位。請參閱[客戶入駐](/zh-Hant/integration/onboarding/customers)。
- 發布 v3 開發者遷移指南。請參閱[遷移至 v3](/zh-Hant/api-reference/versioning/migrate-to-v3)。

### 變更
- 客戶與帳戶的國家代碼在寫入時現在會驗證為已指派的 ISO 3166-1 alpha-2 值。讀取時容許舊有儲存值,讓現有紀錄仍可繼續解析。請參閱[帳戶與錢包](/zh-Hant/integration/accounts)。
- USDC 的可用性現在依目的地網路限定,因此報價與轉帳只會在目的地實際支援的網路上提供 USDC。
- `Capability.ready` 表示權限已獲核准，並不表示帳戶已核發。請使用 `accountProvisioning` 追蹤帳戶核發狀態：`not_applicable`、`not_started`、`in_progress`、`issued` 或 `failed`。
- 現在接受來自 iPhone 的 HEIC 上傳作為身分與地址文件。

### 修正
- 重新執行已消耗的報價現在會回傳 `409 quote_execution_consumed`,而非通用錯誤。請參閱[報價與轉帳](/zh-Hant/integration/quotes-and-transfers)。
- 轉帳清單讀取與報價金額讀取在大量歷史結果上不再回傳 `500`。
- 個人客戶的關聯方讀取不再回傳 `404`。
- 商家後台中的驗證連結列現在每一列都會顯示 **Open** 動作,且每個錢包基礎設施任務連結都會在需求視圖中呈現。
