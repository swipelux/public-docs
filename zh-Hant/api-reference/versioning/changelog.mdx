## 2026-08-17

**版本:** v3

### 新增
- 在 OpenAPI 規範中發布 v3 Problem Details 目錄,讓整合方可以直接從 schema 對應錯誤回應。
- 為 v3 帳戶 webhook 事件新增 `customerId`,讓您無需後續讀取即可將帳戶活動關聯至擁有的客戶。請參閱 [Webhook](/zh-Hant/integration/webhooks)。
- 商家後台完整支援 V3 個人檔案欄位,讓入駐操作人員可以審核並編輯透過 v3 API 收集的每個 KYC 欄位。請參閱[客戶入駐](/zh-Hant/integration/onboarding/customers)。
- 發布 v1/v2 → v3 開發者遷移指南。請參閱[遷移至 v3](/zh-Hant/api-reference/versioning/migrate-to-v3)。

### 變更
- 客戶與帳戶的國家代碼在寫入時現在會驗證為已指派的 ISO 3166-1 alpha-2 值。讀取時容許舊有儲存值,讓現有紀錄仍可繼續解析。請參閱[帳戶與錢包](/zh-Hant/integration/accounts)。
- BlindPay USDC 的可用性現在依目的地網路限定,因此報價與轉帳只會在目的地實際支援的網路上提供 USDC。
- 每個 rail intake 現在都需要接受 Swipelux Terms of Service,而 ACH intake 從第一步起就包含其 ToS。在供應商審核期間,現有的工作階段仍可繼續。請參閱[客戶入駐](/zh-Hant/integration/onboarding/customers)。
- `Capability.ready` 不再意味著帳戶已核發。請在假設帳戶存在之前等候帳戶事件(或讀取帳戶)。請參閱[能力與任務](/zh-Hant/integration/onboarding/capabilities-and-requirements)。
- 現在接受來自 iPhone 的 HEIC 上傳作為身分與地址文件。

### 修正
- 重新執行已消耗的報價現在會回傳 `409 quote_execution_consumed`,而非通用錯誤。請參閱[報價與轉帳](/zh-Hant/integration/quotes-and-transfers)。
- 轉帳清單讀取與報價金額讀取在大量歷史結果上不再回傳 500。
- 發生競爭的 KYC 重新導向現在會回傳 conflict 而非 404,讓重試可以乾淨地解決。託管的 Align 重新導向不再在中途回滾,而 process-KYC 連結在供應商審核期間仍可繼續使用。
- 個人客戶的關聯方讀取不再回傳 404。
- 外部 ACH 帳戶匯入在遭到拒絕時,現在會呈現供應商回報的原因,讓操作人員可以依實際原因處理。請參閱[帳戶與錢包](/zh-Hant/integration/accounts)。
- 標準核准掃描不再卡在其自身佇列頭部,因此入駐決策可以無需操作人員介入即通過審核。
- Sandbox 中的 Align 客戶現在會端對端完整佈建,且自建轉帳在 sandbox 中不再被回報為 conflict。
- 具有錢包無效欄位的 KYB 送出會在提交前被拒絕,而失敗的供應商同步在商家後台不再被回報為成功。
- 商家後台中的 RFI(資訊請求)任務:已送出的回應現在會顯示為完成,條款動作與其他步驟分開追蹤,重複的文件文案已移除,已開始的 KYC 工作階段在申請人完成前仍保持 pending,且過時的 RFI 任務不再破壞需求視圖。
- 商家後台中的驗證連結列現在每一列都會顯示 **Open** 動作,且每個錢包基礎設施任務連結都會在需求視圖中呈現。
