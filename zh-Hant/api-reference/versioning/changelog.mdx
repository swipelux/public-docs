## 2026-08-24

**版本：** v3

### 新增
- 客戶範圍內託管的驗證與服務條款工作階段現在包含具權威性的 `action` 物件。請依照其 `available` 或 `unavailable` 類型處理；對於可用動作，頂層的 `url` 與 `expiresAt` 欄位仍保留為相容性鏡像。請參閱[功能與要求](/zh-Hant/integration/onboarding/capabilities-and-requirements)。
- 沙盒錢包加值現在會傳回可透過 `GET /v3/transfers/{transferId}` 讀取或透過 `GET /v3/transfers` 列出的轉帳 ID。它們會顯示為已完成的傳入穩定幣存款。請參閱[在沙盒中測試](/zh-Hant/integration/sandbox)。

### 變更
- 商家面板中用於卡片與 Apple Pay 的 **First pay-in** 引導現在要求客戶擁有 Polygon 錢包。請先建立該錢包，再開始引導。請參閱[帳戶](/zh-Hant/integration/accounts)。
- 新要求與公開回應使用 `sepa` 作為方法與功能的標準名稱。`sepa_instant` 輸入別名及先前儲存的資源仍相容，但公開回應會使用 `sepa`。請參閱[帳戶](/zh-Hant/integration/accounts)。
- 新的 Faster Payments 功能、已發行帳戶與報價要求已不可用。現有帳戶、報價與轉帳仍可讀取。請參閱[帳戶](/zh-Hant/integration/accounts)。
- KYB 第一頁不再收集代表人的出生日期。股東出生日期仍是獨立要求。請參閱[KYB 工作流程](/zh-Hant/knowledge-base/business-onboarding/kyb-workflow)。
- RFI 文件參照現在除了 `image/jpeg` 外，也接受 MIME 別名 `image/jpg`。請參閱[文件要求](/zh-Hant/knowledge-base/business-onboarding/document-requirements)。
- 商家面板中的任務歷程現在會顯示不含修訂計數器、易於閱讀的稽核軌跡。請參閱[功能與要求](/zh-Hant/integration/onboarding/capabilities-and-requirements)。

### 移除
- 商家面板不再提供新的 UAEFTS 帳戶設定。現有 UAEFTS 帳戶仍可讀取。請參閱[帳戶](/zh-Hant/integration/accounts)。

### 修正
- 審查人員新增文件提交欄位時，RFI 表單會保留現有輸入，因此重新提交時不會遺失先前的回答。
- 商家面板可從可用動作繼續託管的合規工作階段，而不會捨棄有效連結。
- 託管的服務條款連結現在適用於 API 傳回的所有任務範圍。
- 在商家面板中要求 Payment Access 後，面板會開啟該要求傳回的受理任務，而不是較早要求中的任務。
- 商家面板的 KYB 示範現在會要求目前的必填欄位。
- 報價若將來源錢包重複用作 `destinationId`，現在會在開始任何供應商工作前傳回可採取行動的 `422 quote_direction_invalid` 詳細資料。請參閱[報價與轉帳](/zh-Hant/integration/quotes-and-transfers)。
- API 現在會以 `400` 錯誤拒絕格式錯誤的查詢字串編碼，而不是在未提示的情況下正規化要求。請參閱[錯誤與重試](/zh-Hant/integration/errors)。
- `POST /v3/customers/{customerId}/documents` 現在會以 `400` 錯誤拒絕空白、非 multipart 或格式錯誤的要求本文。

## 2026-08-17

**版本:** v3

### 新增
- 在 OpenAPI 規範中發布 v3 Problem Details 目錄,讓整合方可以直接從 schema 對應錯誤回應。請參閱[錯誤](/zh-Hant/integration/errors)。
- 為 v3 帳戶 webhook 事件新增 `customerId`,讓您無需後續讀取即可將帳戶活動關聯至擁有的客戶。請參閱 [Webhook](/zh-Hant/integration/webhooks)。
- 商家後台完整支援 V3 個人檔案欄位,讓入駐操作人員可以審核並編輯透過 v3 API 收集的每個 KYC 欄位。請參閱[客戶入駐](/zh-Hant/integration/onboarding/customers)。
- 發布 v3 開發者遷移指南。請參閱[遷移至 v3](/zh-Hant/api-reference/versioning/migrate-to-v3)。

### 變更
- 客戶與帳戶的國家代碼在寫入時現在會驗證為已指派的 ISO 3166-1 alpha-2 值。讀取時容許舊有儲存值,讓現有紀錄仍可繼續解析。請參閱[帳戶與錢包](/zh-Hant/integration/accounts)。
- USDC 的可用性現在依目的地網路限定,因此報價與轉帳只會在目的地實際支援的網路上提供 USDC。
- 所有入駐流程現在都需要 Swipelux 服務條款。既有的工作階段仍可恢復。請參閱[客戶入駐](/zh-Hant/integration/onboarding/customers)。
- `Capability.ready` 仍持續回報權限已獲核准。請使用 `accountProvisioning` 追蹤帳戶核發狀態：`not_applicable`、`not_started`、`in_progress`、`issued` 或 `failed`。請參閱[能力與任務](/zh-Hant/integration/onboarding/capabilities-and-requirements)。
- 現在接受來自 iPhone 的 HEIC 上傳作為身分與地址文件。

### 修正
- 重新執行已消耗的報價現在會回傳 `409 quote_execution_consumed`,而非通用錯誤。請參閱[報價與轉帳](/zh-Hant/integration/quotes-and-transfers)。
- 轉帳清單讀取與報價金額讀取在大量歷史結果上不再回傳 `500`。
- 並行的 KYC 重新導向現在會回傳衝突而非 `404`,因此重試能順利解決。託管的重新導向不再中途回滾,且 KYC 連結仍可恢復。
- 個人客戶的關聯方讀取不再回傳 `404`。
- 含無效錢包欄位的 KYB 提交會在送出前被拒絕,且同步失敗不再於商家後台中回報為成功。
- 商家後台中的需求任務現在會將已提交的答覆顯示為完成、獨立追蹤服務條款動作、移除重複的文件文字、讓已開始的 KYC 工作階段在完成前保持待處理,並在不破壞需求視圖的情況下處理過期任務。
- 商家後台中的驗證連結列現在每一列都會顯示 **Open** 動作,且每個任務連結都會在需求視圖中呈現。
