在建構入金、出金或發行銀行帳戶之前,請先建立客戶。能力、帳戶與轉帳的範圍都限定於該客戶。請以 `externalId` 作為與您系統中對應紀錄的穩定映射。

```bash Environment variables
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## 個人客戶 {#individual-customers}

個人客戶僅需 `type`。請一併提供您已知的個人資料欄位,並僅在當前能力或任務需要時再新增其他欄位。

使用 [`POST /v3/customers`](/api-reference/customers/post-v3-customers) 建立客戶:

```bash Create individual customer
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

將回傳的 `data.id` 儲存為 `CUSTOMER_ID`。政策背景請參閱[個人入駐](/zh-Hant/knowledge-base/individual-onboarding/overview)。

## 企業客戶 {#business-customers}

企業客戶需要提供 `business.legalName`。使用相同的操作建立企業:

```bash Create business customer
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

將回傳的 `data.id` 儲存為 `CUSTOMER_ID`。政策與文件相關內容請參閱[企業入駐](/zh-Hant/knowledge-base/business-onboarding/overview)。

## 新增企業關係人 {#add-business-related-parties}

當董事、股東等其他企業參與者已知或被要求時,請將其新增。此範例使用 [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) 建立一位董事:

```bash Add related party
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

將回傳的 `data.id` 儲存為 `RELATED_PARTY_ID`。

如需匯出客戶資料，請使用 [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) 並遵循其請求 schema。`json_basic_data` 格式會以 JSON 附件回傳當前的公開 v3 客戶資源;每次呼叫都會重新計算當前資料,且不包含文件與文件中繼資料。

若需可攜性權杖格式,請在 `forClientId` 中傳送接收方 KYC 專案的 client ID,而非 Swipelux 的 `customerId`。請在 `data.expiresAt` 之前使用回傳的 `data.token`。重複使用相同的 `Idempotency-Key` 與請求主體會重播該權杖結果;若要核發另一組權杖,請使用新的金鑰。

## 檢查更新時被忽略的欄位 {#check-ignored-fields-on-updates}

[`PATCH /v3/customers/{customerId}`](/api-reference/customers/patch-v3-customers-by-customer-id) 與 `PATCH /v3/customers/{customerId}/related-parties/{relatedPartyId}` 會忽略無法辨識的請求本文欄位。當它們忽略某個欄位時,成功的回應會包含 `Swipelux-Ignored-Fields` 標頭。該標頭以逗號分隔並排序列出被忽略欄位的 JSON Pointer。建立請求不會傳回此標頭。

請在每次更新後檢查此標頭。否則,名稱錯誤或位置錯誤的欄位會在沒有錯誤的情況下被捨棄。例如,傳送 `individual.dateOfBirth` 而非 `individual.birthDate` 會讓出生日期維持未設定。

```http Ignored fields response header
Swipelux-Ignored-Fields: /individual/dateOfBirth,/nickname
```

- 該標頭最多列出 20 個指標與 4096 個字元,當 Swipelux 截斷清單時以 `...` 結尾。指標區段採用百分比編碼。
- `metadata` 內的欄位為自由格式,一律不回報。
- 冪等重送會省略此標頭,因此請從第一次回應中讀取。
- 未來版本可能會以 `400` 拒絕未知欄位。

## 從能力讀取就緒狀態

客戶在 API 中並不具備驗證或就緒狀態。請使用 [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) 讀取當前的個人資料,然後利用能力及其 `openTaskIds` 來判斷該客戶接下來可以做什麼。

```bash Get customer
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

### 依能力就緒狀態篩選客戶 {#filter-customers-by-capability-readiness}

若要找出處於特定開戶階段的客戶,請使用下列查詢參數篩選 [`GET /v3/customers`](/api-reference/customers/get-v3-customers):

- `pooledCapabilityStatus`:客戶擁有處於此狀態的共用能力。
- `namedCapabilityStatus`:客戶擁有處於此狀態的具名能力。
- `hasReadyNamedAccount`:`true` 傳回擁有 `ready` 具名帳戶的客戶。`false` 傳回沒有此類帳戶的客戶。

狀態篩選條件接受 `pending`、`ready`、`restricted`、`rejected` 或 `canceled`。Swipelux 讀取狀態的方式與 `include=capabilities` 相同。請參閱[共用型與專屬型帳戶類型](/zh-Hant/integration/onboarding/capabilities-and-requirements#pooled-vs-named-account-types)。

若要排除僅在等待中的能力,請加入 `namedCapabilityExcludeWait=true` 或 `pooledCapabilityExcludeWait=true`;這會移除 `statusReason.resolution` 為 `wait` 的符合項目。`namedCapabilityIncludeWait=true` 或 `pooledCapabilityIncludeWait=true` 也會納入具有該處理方式的 `restricted` 能力。每個旗標只搭配其對應的狀態篩選條件使用,兩者同時設定時以 `ExcludeWait` 為準。

這些篩選條件可彼此組合,也可與其他清單篩選條件組合。Swipelux 會在分頁之前套用,因此每一頁只包含符合的客戶。API 金鑰需要 `accounts:read` 或 `rails:read` 才能使用。無效的值會傳回 `400 validation_error`。

例如,找出已獲銀行核准具名能力但尚無就緒具名帳戶的客戶:

```bash Filter customers awaiting a named account
curl --request GET \
  --get "${API_BASE}/v3/customers" \
  --data-urlencode "namedCapabilityStatus=ready" \
  --data-urlencode "hasReadyNamedAccount=false" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

### 找出有待提交文件的客戶

若要找出某一頁中哪些客戶仍需提交必要文件,請將 `include=documentRequirements` 傳給 [`GET /v3/customers`](/api-reference/customers/get-v3-customers)。你可以將其與能力摘要組合使用,寫作 `include=capabilities,documentRequirements`。API 金鑰需要 `accounts:read` 權限才能使用 `documentRequirements` 擴充。

此時,每個客戶摘要都會包含一個 `documentRequirements` 物件:

```json Document requirement summary
{
  "documentRequirements": {
    "required": true,
    "count": 2
  }
}
```

- `count` 是處於 `action_required` 狀態、且所屬任務也處於 `action_required` 狀態的必要文件要求數量。它涵蓋所有任務範圍,包括帳戶層級的任務,且不取決於能力的就緒狀態。
- 當 `count` 大於 `0` 時,`required` 為 `true`。
- 一組替代方案只計算一次,且僅在每個替代方案都需要文件時才計入。

此摘要採取保守做法。它不包含選用文件、有條件必要的文件,以及混合文件與非文件途徑的替代方案。它也不包含客戶可透過託管驗證完成的要求。因此,`required: false` 並不能證明沒有適用的文件任務。請用它來排定客戶的優先順序,然後讀取其任務,以取得需要收集內容的權威清單。若未使用此擴充,回應會省略 `documentRequirements`。

## 讀取客戶轉帳金額 {#read-customer-transfer-volume}

若要顯示客戶轉移了多少資金，請呼叫 `GET /v3/customers/{customerId}/transfer-totals`。API 金鑰需要 `customers:read`。未知客戶會傳回 `404 customer_not_found`。

```json Transfer totals
{
  "data": {
    "customerId": "cus_...",
    "received": { "amount": "1000.00", "currency": "USD" },
    "sent": { "amount": "25.00", "currency": "USD" }
  }
}
```

- 僅計入已完成的轉帳。待處理與失敗的轉帳不計入。
- `received` 加總入金以及來自其他客戶的入站錢包轉帳。`sent` 加總出金與出站錢包轉帳。
- USD、USDC 和 USDT 按 1:1 計為 USD。其他幣別的金額不計入。
- 客戶自有錢包之間的轉帳不計入。
- 每個 `amount` 都是保留兩位小數的十進位字串，沒有符合條件的轉帳時為 `"0.00"`。

這些總額是資金流動金額，而非目前餘額。
