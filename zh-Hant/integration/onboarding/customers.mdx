---
title: "客戶"
description: "建立擁有能力、帳戶與轉帳的個人或企業。"
---

在建構入金、出金或發行銀行帳戶之前,請先建立客戶。能力、帳戶與轉帳的範圍都限定於該客戶。請以 `externalId` 作為與您系統中對應紀錄的穩定映射。

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## 個人客戶 {#individual-customers}

個人客戶僅需 `type`。請一併提供您已知的個人資料欄位,並僅在當前能力或任務需要時再新增其他欄位。

使用 [`POST /v3/customers`](/api-reference/customers/post-v3-customers) 建立客戶:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

將回傳的 `data.id` 儲存為 `CUSTOMER_ID`。政策背景請參閱[個人入駐](/zh-Hant/knowledge-base/individual-onboarding/overview)。

## 企業客戶 {#business-customers}

企業客戶需要提供 `business.legalName`。使用相同的操作建立企業:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

將回傳的 `data.id` 儲存為 `CUSTOMER_ID`。政策與文件相關內容請參閱[企業入駐](/zh-Hant/knowledge-base/business-onboarding/overview)。

## 新增企業關係人

當董事、股東等其他企業參與者已知或被要求時,請將其新增。此範例使用 [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) 建立一位董事:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

將回傳的 `data.id` 儲存為 `RELATED_PARTY_ID`。

## 匯出客戶資料 {#export-customer-data}

使用 [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) 下載客戶資料,或將已通過的 KYC 交付至您自己的 Sumsub 專案。每次匯出都需要 `Idempotency-Key`;重放相同的金鑰與主體會取得相同的結果。

請在請求主體中選擇格式。

<Tabs>
  <Tab title="基本個人資料 JSON">

以 JSON 附件形式回傳公開的 v3 客戶資源,包含個人資料、地址、稅務、metadata 與關係人資料。不包含文件與文件 metadata。

```json
{
  "format": "json_basic_data"
}
```

  </Tab>
  <Tab title="Sumsub 分享權杖">

為已通過的個人客戶建立一次性的 Sumsub 分享權杖,讓接收方的 Sumsub 專案能匯入 KYC 資料。企業客戶會回傳 `422 invalid_field_for_type`。

```json
{
  "format": "sumsub_share_token",
  "forClientId": "partner-sumsub-client-id"
}
```

`forClientId` 是您的 Sumsub `clientId`,而非 Swipelux 的 `customerId`。它用來識別將接收申請人資料的 Sumsub 專案,因此值由您自行選擇。

回應會回傳 `provider`、`token` 與 `expiresAt`(Unix 秒):

```json
{
  "data": {
    "provider": "sumsub",
    "token": "_shr-...",
    "expiresAt": 1800000000
  }
}
```

請在 `expiresAt` 之前,將 `token` 傳遞給 Sumsub 的分享權杖匯入 API,對象為 `forClientId` 所識別的專案。僅使用一次。若需重新簽發,請以新的 `Idempotency-Key` 再次呼叫匯出。

  </Tab>
</Tabs>

## 從能力讀取就緒狀態

客戶在 API 中並不具備驗證或就緒狀態。請使用 [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) 讀取當前的個人資料,然後利用能力及其 `openTaskIds` 來判斷該客戶接下來可以做什麼。

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

接下來,請繼續前往[能力與任務](/zh-Hant/integration/onboarding/capabilities-and-requirements),以探索並啟用您需要的產品結果。
