## 驗證狀態與工作流程

面向政策的 KYC 旅程從資訊收集到審查,最終到達核准或拒絕決定。當前 API 資源則暴露獨立的能力、申請、任務與提交生命週期。

<Warning>
  政策審查標籤與時程估算並不定義 API 行為。切勿以下列標籤實作
  狀態機。
</Warning>

## 面向政策的審查概念

以下面向政策的審查概念用於描述入駐旅程。它們並非當前的 API 枚舉、webhook 值或保證的轉換。

| 政策標籤 | 意義 |
| --- | --- |
| `not_started` | 客戶已存在,但 KYC 工作尚未開始 |
| `incomplete` | KYC 已開始,但仍缺少所需資訊 |
| `pending_verification` | 審查等待客戶完成 |
| `under_review` | 提交的資訊或文件正在審查中 |
| `approved` | 政策審查核准客戶可使用適用流程 |
| `rejected` | 政策審查拒絕該客戶 |

僅在討論政策旅程時使用這些標籤。除非當前生成的結構在其自身脈絡中明確要求相同的值,否則切勿將它們作為當前狀態值傳送。

## Standard KYC 審查流程

1. 建立個人客戶。
2. 探索並申請符合資格的能力。
3. 讀取當前任務細節。
4. 將客戶引導至第一方託管的驗證 session,或提交任務所要求的完整答覆。
5. 讓審查繼續進行,同時當前資源會回報自身的審查狀態。
6. 重新讀取當前資源,以判斷是否需要進一步動作,或該能力已為 ready、restricted、rejected 或 canceled。

政策旅程可能將其描述為 not started、pending verification、under review,然後為 approved 或 rejected。這些用語並不定義 API 的轉換順序。

## Enhanced KYC 審查流程

1. 完成當前所要求的標準身分與活體工作。
2. 當加強審查要求額外資訊時,讀取最新任務。
3. 透過當前的託管 session 或任務提交,提供所要求的地址證明、資金證明或其他佐證。
4. 僅在當前任務要求時才上傳文件。
5. 於人工審查期間,持續監控當前資源。
6. 依當前的能力、申請、任務與提交狀態,判斷停止或繼續。

法遵團隊也可能透過客戶登記的電子郵件協調加強審查。

## 常見拒絕原因

| 原因 | 解決方式 |
| --- | --- |
| 文件無法辨識 | 提供清晰、高解析度的影像 |
| 文件已到期 | 提供有效且未到期的身分證件 |
| 臉部不符 | 確保 selfie 與身分證件照片明顯相符 |
| 資訊不完整 | 提供當前任務所要求的每一項 |
| 可疑活動 | 聯繫支援以進行人工審查 |

## 驗證時程

| 階段 | 一般時程 |
| --- | --- |
| 文件上傳 | 立即 |
| 自動化檢查 | 1-3 分鐘 |
| 標準審查 | 1-24 小時 |
| 加強審查 | 1-3 個工作日 |

上述時程為一般政策估算,並非保證的 API 行為。

## 當前的 API 狀態用語

當前資源使用獨立的封閉式用語:

- **能力狀態:** `pending`、`ready`、`restricted`、`rejected`、`canceled`
- **申請狀態:** `requested`、`in_review`、`action_required`、`ready`、`rejected`、`disabled`、`canceled`
- **任務狀態:** `action_required`、`in_review`、`satisfied`、`rejected`、`canceled`
- **提交結果:** `in_review`、`accepted`、`changes_requested`、`rejected`

請勿將這些用語收合為單一的驗證狀態。

## 事件與當前狀態

請將當前有文件記載的 [Webhook](/zh-Hant/integration/webhooks) 視為變更通知,然後重新讀取當前的客戶、能力、申請與任務資源。事件不會取代權威的資源讀取,且沒有任何面向政策的標籤暗示特定事件。

當前的動作迴圈請參閱[能力與任務](/zh-Hant/integration/onboarding/capabilities-and-requirements#complete-current-tasks)。
