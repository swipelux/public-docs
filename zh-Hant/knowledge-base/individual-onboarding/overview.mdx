## 個人入駐(KYC)

個人客戶必須完成 KYC 後才能進行交易。驗證等級取決於司法管轄區、交易量、風險評估與監理要求。

<Warning>
  要求會依客戶、司法管轄區、能力與審查而異。當前的任務與所產生的
  結構決定您必須提交的內容。
</Warning>

## KYC 涵蓋的內容

KYC 確認客戶身分,並可能隨著風險與監理要求提高,增加地址、活體、財務畫像或資金來源審查。要求可能依司法管轄區、交易量與用途而異。

## KYC 驗證等級

| 等級 | 要求 | 一般用途 |
| --- | --- | --- |
| Simplified | 姓、名與出生日期 | 已核准的小額流程 |
| Standard | 政府核發身分證件與 selfie/活體檢查 | 標準限額內的一般交易 |
| Enhanced | ID、selfie/活體、地址證明與資金證明 | 大額交易或高風險畫像 |

Simplified、Standard 與 Enhanced 為政策層級,並非當前 API 狀態值。

## 收集的資訊

依當前審查而定,Swipelux 可能要求:

- 法定姓名與出生日期
- 聯絡資訊
- 於必要時提供居住地址
- 政府核發的身分佐證與活體佐證
- 於必要時提供財務畫像資訊,包含預期活動與資金來源

請勿將此清單視為通用的請求主體。當前的客戶結構與任務細節決定特定能力所需的資訊。

## 當前實作

建立個人客戶、探索並申請符合資格的能力,然後依照當前任務執行。任務可能提供第一方託管的驗證 session,或要求提交任務答覆。僅在該任務要求時才上傳文件。

請依照[個人入駐指南](/zh-Hant/integration/onboarding/customers#individual-customers)、[能力與任務](/zh-Hant/integration/onboarding/capabilities-and-requirements#complete-current-tasks) 與[個人 API 工作流程對照](/zh-Hant/knowledge-base/individual-onboarding/api-workflow) 執行。
