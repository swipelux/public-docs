## KYC 驗證等級

Swipelux 使用三個政策層級的身分驗證。適用層級取決於客戶風險、司法管轄區、預期交易量與監理要求。

<Warning>
  這些層級為政策分類,而非當前的 API 枚舉值。當前任務決定特定客戶的
  實際要求。
</Warning>

## Simplified KYC

Simplified KYC 適用於已核准的低風險、小額流程。

### 必要資訊

- 名(First name)
- 姓(Last name)
- 出生日期

### 使用情境

- 交易金額低於適用的 simplified 門檻
- 客戶位於低風險司法管轄區

## Standard KYC

Standard KYC 透過政府核發的文件與 selfie 或活體檢查驗證身分。

### 必要文件

- 政府核發身分證件
- Selfie 或活體檢查

### 接受的身分文件

- 護照
- 駕照
- 國民身分證

## Enhanced KYC(加強盡職調查)

Enhanced KYC 針對較高風險情境增加地址與資金佐證。

### 必要文件

- Standard KYC 所需的所有項目
- 地址證明
- 資金證明

### Enhanced KYC 觸發條件

- 交易量超過標準門檻
- 高風險司法管轄區
- 法遵團隊根據風險評估的標記
- 監理要求

### 地址證明要求

| 文件類型 | 要求 |
| --- | --- |
| 銀行對帳單 | 過去 90 天內核發 |
| 水電費帳單 | 電、瓦斯、水或網路;過去 90 天內核發 |
| 政府信函 | 過去 90 天內核發的稅務通知或官方信件 |

### 資金證明要求

| 文件類型 | 說明 |
| --- | --- |
| 銀行對帳單 | 顯示足夠餘額或收入的近期對帳單 |
| 薪資單 | 就業收入驗證 |
| 報稅文件 | 年度稅務文件 |
| 投資對帳單 | 券商或退休帳戶對帳單 |

## 政策層級與當前任務

當前任務細節仍是下一步 API 動作的權威來源。它可能提供第一方託管的 session、透過提交要求答覆,或要求文件佐證。

在部分加強審查中,法遵團隊也可能透過客戶登記的電子郵件聯繫。請將該聯繫視為政策審查協調,而非取代讀取當前 API 資源。
