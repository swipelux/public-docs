description: "Gérez chaque code de problème public de l'API Swipelux, décidez quand réessayer et résolvez les échecs de validation, d'état, d'idempotence et de plateforme."

Les erreurs de l'API Swipelux utilisent le type de média `application/problem+json`. Faites dépendre le comportement de votre application de la valeur stable `code`, puis utilisez l'opération et les conseils ci-dessous pour résoudre l'échec.

| Champ | Comment l'utiliser |
| --- | --- |
| `type` | URI de documentation stable pour le code de problème. |
| `title` | Titre court et lisible du problème. |
| `status` | Statut HTTP associé à cette réponse. |
| `code` | Valeur stable lisible par machine pour la logique applicative. |
| `detail` | Texte contextuel lisible par l'humain pour cette occurrence. Ne l'analysez pas et ne le comparez pas. |
| `correlationId` | Identifiant de requête à stocker dans les logs et à inclure lorsque vous contactez le support. |
| `retryable` | Lorsque `true`, la même requête peut réussir plus tard. Lorsque `false`, modifiez la requête ou satisfaites un prérequis avant de réessayer. |
| `errors[]` | Détails de validation au niveau des champs, incluant un pointeur JSON lorsqu'il est disponible. |

Réessayez les écritures idempotentes avec l'`Idempotency-Key` d'origine et la méthode, le chemin et le corps inchangés. Ne réutilisez jamais cette clé pour une autre opération prévue.

```json
{
  "type": "https://docs.swipelux.com/errors/validation-error",
  "title": "Validation Error",
  "status": 400,
  "code": "validation_error",
  "detail": "The request contains invalid fields.",
  "correlationId": "01JERRORVALIDATION",
  "retryable": false,
  "errors": [
    {
      "pointer": "/externalId",
      "code": "invalid_format",
      "message": "Use a valid external identifier."
    }
  ]
}
```

### `forbidden`

**Statut HTTP :** `403`<br />
**Réessayable :** Non<br />
**Type de problème :** `https://docs.swipelux.com/errors/forbidden`

**Signification :** La clé API est valide mais n'est pas autorisée à effectuer cette opération.

**Quand elle se produit :** L'identifiant ne dispose pas d'une permission requise, ou un identifiant de production appelle un endpoint réservé au sandbox.

**Que faire :** Utilisez un identifiant pour le bon environnement avec les permissions requises. N'exposez pas et ne remplacez pas de clés dans du code côté client.

**Conseils de nouvelle tentative :** Ne réessayez pas la requête inchangée. Appliquez l'action ci-dessus avant d'envoyer une nouvelle requête.

**Opérations API concernées :** Toutes les opérations API authentifiées.

### `invalid_field_for_type`

**Statut HTTP :** `400`, `422`<br />
**Réessayable :** Non renvoyé<br />
**Type de problème :** `https://docs.swipelux.com/errors/invalid-field-for-type`

**Signification :** La requête inclut des champs qui ne sont pas valides pour le type de ressource sélectionné.

**Quand elle se produit :** Une requête discriminée, comme un profil particulier versus entreprise, contient des champs d'une autre variante ou omet des champs requis par le type sélectionné.

**Que faire :** Utilisez le schéma du type sélectionné, supprimez les champs appartenant aux autres variantes, fournissez ses champs requis et envoyez une requête corrigée.

**Conseils de nouvelle tentative :** Ce problème ne renvoie pas `retryable`. Ne supposez pas qu'une nouvelle tentative inchangée est sûre ; suivez l'action ci-dessus et les exigences d'idempotence de l'opération.

### `request_body_too_large`

**Statut HTTP :** `413`<br />
**Réessayable :** Non<br />
**Type de problème :** `https://docs.swipelux.com/errors/request-body-too-large`

**Signification :** Le corps de la requête dépasse la taille acceptée par l'opération.

**Quand elle se produit :** Une soumission de tâche envoie plus de données de requête que l'API ne peut en traiter dans un seul corps.

**Que faire :** Supprimez les données inutiles, utilisez des références de document au lieu d'intégrer le contenu des fichiers et envoyez une soumission plus petite qui répond toujours aux exigences actuelles.

**Conseils de nouvelle tentative :** Ne réessayez pas la requête inchangée. Appliquez l'action ci-dessus avant d'envoyer une nouvelle requête.

**Opérations API concernées :**

- [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) (`createCustomerTaskSubmission`, statut `413`)

### `unauthorized`

**Statut HTTP :** `401`<br />
**Réessayable :** Non<br />
**Type de problème :** `https://docs.swipelux.com/errors/unauthorized`

**Signification :** La requête ne contient pas de clé API valide.

**Quand elle se produit :** L'en-tête `X-API-Key` est absent, invalide, expiré ou non reconnu par l'API.

**Que faire :** Envoyez la clé correcte propre à l'environnement depuis un backend protégé. Effectuez une rotation de la clé si elle a pu être exposée.

**Conseils de nouvelle tentative :** Ne réessayez pas la requête inchangée. Appliquez l'action ci-dessus avant d'envoyer une nouvelle requête.

**Opérations API concernées :** Toutes les opérations API authentifiées.

**Type de problème :** `https://docs.swipelux.com/errors/unknown-parameter`

### `request_failed`

**Statut HTTP :** `502`, `503`<br />
**Réessayable :** Contextuel<br />
**Type de problème :** `https://docs.swipelux.com/errors/request-failed`

**Signification :** Un service nécessaire pour compléter l'opération n'a pas traité la requête avec succès.

**Quand elle se produit :** L'export de client, la gestion des webhooks ou la vérification sandbox rencontre une défaillance de service externe ou une configuration indisponible.

**Que faire :** Inspectez `retryable`. Réessayez plus tard lorsqu'il vaut `true` ; sinon, conservez `correlationId`, vérifiez les prérequis de la requête et contactez le support si l'échec persiste.

**Conseils de nouvelle tentative :** Lisez `retryable` dans cette réponse. Réessayez plus tard uniquement lorsqu'il vaut `true`. Pour une écriture idempotente, réutilisez la clé d'idempotence d'origine et la requête inchangée.
