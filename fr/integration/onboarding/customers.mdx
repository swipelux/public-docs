title: "Clients"

---

Créez le client avant de construire un encaissement, un paiement ou un compte bancaire émis. Les capacités, les comptes et les transferts sont liés à ce client. Utilisez `externalId` comme mappage stable vers l'enregistrement correspondant dans votre système.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Clients individuels {#individual-customers}

Un individu ne requiert que `type`. Incluez les champs de profil que vous connaissez déjà, et ajoutez-en davantage uniquement lorsque la capacité ou la tâche actuelle en a besoin.

Créez le client avec [`POST /v3/customers`](/api-reference/customers/post-v3-customers) :

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Stockez le `data.id` renvoyé en tant que `CUSTOMER_ID`. Consultez [Onboarding individuel](/fr/knowledge-base/individual-onboarding/overview) pour le contexte politique.

## Clients professionnels {#business-customers}

Une entreprise requiert `business.legalName`. Créez l'entreprise avec la même opération :

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Stockez le `data.id` renvoyé en tant que `CUSTOMER_ID`. Consultez [Onboarding professionnel](/fr/knowledge-base/business-onboarding/overview) pour le contexte politique et documentaire.

## Ajouter des parties liées professionnelles

Ajoutez des directeurs, des propriétaires et d'autres participants de l'entreprise lorsqu'ils sont connus ou requis. Cet exemple crée un directeur avec [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties) :

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Stockez le `data.id` renvoyé en tant que `RELATED_PARTY_ID`.

Si vous devez exporter un client, utilisez [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) et suivez son schéma de requête. Le format `json_basic_data` renvoie la ressource client v3 publique actuelle sous forme de pièce jointe JSON ; chaque appel recalcule les données actuelles et exclut les documents et leurs métadonnées.

Pour un format de jeton de portabilité, envoyez l'ID client du projet KYC destinataire en tant que `forClientId`, et non le `customerId` Swipelux. Utilisez le `data.token` renvoyé avant `data.expiresAt`. Réutiliser la même `Idempotency-Key` et le même corps rejoue ce résultat de jeton ; utilisez une nouvelle clé pour émettre un autre jeton.

## Lire la disponibilité à partir des capacités

Un client n'a pas de statut de vérification ou de disponibilité dans l'API. Lisez le client avec [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) pour les données de profil actuelles, puis utilisez les capacités et leurs `openTaskIds` pour décider de ce que le client peut faire ensuite.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Ensuite, continuez vers [Capacités et tâches](/fr/integration/onboarding/capabilities-and-requirements) pour découvrir et activer le résultat produit dont vous avez besoin.
