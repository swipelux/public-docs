## Jurisdiksjonsrammeverk

### Oversikt over sluttbrukerkvalifikasjon

Swipelux bruker et flerlags jurisdiksjonelt rammeverk i tråd med EU AMLD, FATF-veiledning og internt risikoappetitt. Sluttbrukere faller i tre brede kategorier:

#### A. Fullt støttet (EØS + CH)

Sluttbrukere kan onboardes med pass, nasjonalt ID eller EU-oppholdstillatelse.
Førerkort og papir-ID-er kan aksepteres med økt manuell gjennomgang.

**Jurisdiksjoner:**

EØS-land (EU + EFTA): Østerrike, Belgia, Bulgaria, Kroatia, Kypros, Tsjekkia, Danmark, Estland, Finland, Frankrike, Tyskland, Hellas, Ungarn, Irland, Italia, Latvia, Litauen, Luxembourg, Malta, Nederland, Polen, Portugal, Romania, Slovakia, Slovenia, Spania, Sverige, Island, Liechtenstein, Norge.

**Ytterligere akseptert:** Sveits (tilstrekkelig AML/CTF-regulatorisk miljø).

#### B. Global dekning - akseptert med Enhanced Due Diligence

Sluttbrukere fra disse jurisdiksjonene kan aksepteres med ytterligere KYC-trinn, strengere dokumentregler og potensiell videoverifisering basert på transaksjonsterskler.

**APAC (Asia-Stillehavet)**

**Akseptert:** Taiwan, India, Sri Lanka, Bhutan, Maldivene, Indonesia, Malaysia, Brunei, Kambodsja, Filippinene*, Singapore, Thailand, Vietnam*, m.fl.

**Dokumentkrav (APAC):**

- Pass ELLER nasjonalt ID (papir-ID krever pass)
- Bostedsbevis: strømregning, kontoutskrift, internettregning

**LATAM (Latin-Amerika og Karibia)**

**Akseptert:** Argentina, Bolivia, Brasil, Chile, Colombia, Costa Rica, Den dominikanske republikk, El Salvador, Guatemala, Honduras, Belize, Mexico, Panama*, Paraguay, Peru, Uruguay.

**Dokumentkrav (LATAM):**

- Pass ELLER nasjonalt ID (papir-ID krever pass)
- Bostedsbevis kreves

**EMEA (Europa unntatt EØS + Midtøsten + Afrika)**

**Akseptert:** Albania*, Algerie, Andorra, Angola, Bahrain, Israel, Gibraltar*, Georgia, Kenya, Kuwait, Oman, Qatar*, Saudi-Arabia, Sør-Afrika*, Tyrkia*, De forente arabiske emirater*, m.fl.

**Dokumentkrav (EMEA):**

- Pass ELLER nasjonalt ID (papir-ID krever pass)
- Bostedsbevis kreves
- Høyrisiko-jurisdiksjoner markert med (*) krever EDD ved onboarding

#### C. No-Go-jurisdiksjoner (forbudt)

Swipelux onboarder ikke sluttbrukere fra jurisdiksjoner klassifisert som:

- FATF-svarteliste
- EU AMLD Artikkel 9(2) høyrisiko-tredjeland med utilstrekkelige AML/CTF-tiltak
- OFAC-sanksjonerte land
- Interne høyrisiko-jurisdiksjoner (Ecuador, Haiti, Nicaragua, visse oversjøiske territorier)

**Listen inkluderer:** Afghanistan, DPRK, Iran, Syria, Jemen, Uganda, Vanuatu, Guyana, Russland, Hviterussland, Cuba, Venezuela, Nicaragua, Somalia, Sudan, Zimbabwe, Burma, CAR, DRC, Etiopia, Libya, Mali, Libanon, m.fl.

**Årsak:** Regulatoriske restriksjoner under EU AMLD, OFAC-sanksjoner og Swipelux' risikoappetitt.

### Viktig

- Jurisdiksjonsregler gjelder for sluttbrukere, ikke bare for merchant-registrering
- Lokale verifiseringsregler, som bostedsbevis, videointervju og dokumenttype, avhenger av brukerens nasjonalitet og bostedsland
- Swipelux screener alle brukere med sanksjoner, PEP-lister og risikobaserte AML-kontroller
- Brukere fra forbudte jurisdiksjoner kan ikke få tilgang til Swipelux-tjenester, selv via VPN eller offshore-enheter

For implementeringsveiledning, se [individ-onboarding](/no/integration/onboarding/customers#individual-customers), [motta midler](/no/integration/receive-funds) og [send midler](/no/integration/send-funds).

### Ansvarsfraskrivelse

Denne jurisdiksjonsmatrisen er en overordnet oversikt over Swipelux' globale støtterammeverk og er ikke uttømmende.

Bruk den for å forstå hvor Swipelux' betalings-rails kan være tilgjengelige for onboarding og betjening av sluttbrukere.

Swipelux' evne til å levere tjenester i en bestemt jurisdiksjon avhenger av:

1. Lokale reguleringer som styrer kryptotransaksjoner og fiat pay-in- eller payout-aktivitet
2. Kortsystemet og innløser-bankens restriksjoner
3. Sanksjoner og AML/CTF-forpliktelser
4. Swipelux' interne risikoappetitt

Krypto-rails refererer til pay-in- og payout-aktivitet utført av Swipelux som en regulert VASP, inkludert depotforvaltning, konvertering og blokkjede-overføringer initiert eller utført av Swipelux.

Fordi regulatoriske krav og systemregler utvikler seg, kan landene og reglene oppført i dette dokumentet endres når som helst.

Swipelux kan akseptere eller avvise enhver merchant eller sluttbruker, eller begrense bestemte betalings-rails, basert på regulatoriske, tekniske eller risikobaserte hensyn, uavhengig av om jurisdiksjonen fremgår av denne matrisen.

- For sensitive eller uklare jurisdiksjoner kan Swipelux kreve:
  - Geoblokkering av visse sluttbrukere
  - Rail-spesifikke restriksjoner (f.eks. kort deaktivert, krypto deaktivert)
  - Enhanced due diligence
  - Juridiske uttalelser eller regulatoriske bekreftelser

Endelige onboarding-beslutninger tas etter Swipelux' eget skjønn i tråd med vår EU VASP-lisens og interne risikorammeverk.
