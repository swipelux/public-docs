## API-workflow for individ-onboarding

Bruk dette kartet for å koble individ-KYC-policy til den gjeldende genererte API-referansen. Følg gjeldende ressurs i hvert trinn i stedet for å implementere policyvendte merkelapper som en API-tilstandsmaskin.

## Workflow-kart

### 1. Opprett individkunden

Opprett kunden med [`POST /v3/customers`](/api-reference/customers/post-v3-customers). Lagre den returnerte kunde-ID-en og les den gjeldende ressursen med [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id).

### 2. Oppdag og be om en kvalifisert capability

Les [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported). Velg en variant kun når dens gjeldende availability og eligibility tillater forespørselen, og bruk deretter [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id).

### 3. Les gjeldende capability og applications

Les [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id) og [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications). Følg gjeldende åpne oppgave-ID-er i stedet for å anta klarhet fra en tidligere respons.

### 4. Hent gjeldende oppgavedetalj

List kundeoppgaver med [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks). Hent den autoriserte handlingsflaten med [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task).

Oppgavedetaljer kan eksponere URL-er for førsteparts hosted sesjoner og de gjeldende handlingsklare kravene. Bruk gjeldende revisjon og status.

### 5. Fullfør hosted sesjoner eller send inn oppgavesvar

Når oppgavedetalj gir en hosted sesjon, returner kun nødvendige sesjonsdata til klienten din og hold API-nøkkelen i backend.

Når oppgaven krever svar, opprett ett komplett uforanderlig forsøk med [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission). Les én gjeldende innsending og dens offentlige utfall med [`GET /v3/customers/{customerId}/tasks/{taskId}/submissions/{submissionId}`](/api-reference/task-submissions/get-customer-task-submission).

### 6. Last opp dokumenter kun når det er forespurt

Last opp dokumenter kun når den gjeldende oppgaven ber om dem. Bruk [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents), og plasser så den returnerte dokument-ID-en i det aktuelle dokumentsvaret.

### 7. Hent gjeldende ressurser på nytt

Hent gjeldende kunde, capability, applications og oppgave på nytt etter hver hendelse eller handling. Bruk deres siste tilstander, årsaker, krav og åpne oppgave-ID-er for å velge neste trinn.

## Kart over genererte operasjoner

| Ressurs | Generert operasjon | Bruk |
| --- | --- | --- |
| Customers | [`POST /v3/customers`](/api-reference/customers/post-v3-customers) | Opprett individkunden |
| Customers | [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) | Les gjeldende kundedata |
| Capabilities | [`GET /v3/customers/{customerId}/capabilities/supported`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-supported) | Oppdag gjeldende availability og eligibility |
| Capabilities | [`POST /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/post-v3-customers-by-customer-id-capabilities-by-capability-id) | Be om den valgte capability-en |
| Capabilities | [`GET /v3/customers/{customerId}/capabilities/{capabilityId}`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id) | Les gjeldende capability-tilstand og åpne oppgaver |
| Capabilities | [`GET /v3/customers/{customerId}/capabilities/{capabilityId}/applications`](/api-reference/capabilities/get-v3-customers-by-customer-id-capabilities-by-capability-id-applications) | Les institusjons-applications og deres åpne oppgaver |
| Tasks | [`GET /v3/customers/{customerId}/tasks`](/api-reference/tasks/list-customer-tasks) | List kundeeide oppgaver |
| Tasks | [`GET /v3/customers/{customerId}/tasks/{taskId}`](/api-reference/tasks/get-customer-task) | Les gjeldende krav og hosted sesjoner |
| Task Submissions | [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) | Send inn et komplett svarsett |
| Task Submissions | [`GET /v3/customers/{customerId}/tasks/{taskId}/submissions/{submissionId}`](/api-reference/task-submissions/get-customer-task-submission) | Les det autoriserte svar-øyeblikksbildet og utfallet |
| Documents | [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents) | Last opp en fil forespurt av den gjeldende oppgaven |

## Policy- og implementeringsveiledning

Simplified, Standard og Enhanced KYC er policy-nivåer. De erstatter ikke gjeldende tilstander for capability, application, oppgave, innsending, krav eller hosted sesjon.

For implementeringsdetaljer, følg [individ-onboarding-guiden](/no/integration/onboarding/customers#individual-customers), [Capabilities og oppgaver](/no/integration/onboarding/capabilities-and-requirements#complete-current-tasks) og [Integrasjonsdokumenter-veiledningen](/no/integration/onboarding/capabilities-and-requirements#upload-documents).
