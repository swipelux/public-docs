---
title: "Kunder"
description: "Opprett individet eller virksomheten som eier capabilities, kontoer og overføringer."
---

Opprett kunden før du bygger en pay-in, payout eller utstedt bankkonto. Capabilities, kontoer og overføringer er avgrenset til denne kunden. Bruk `externalId` som stabil kobling til den tilhørende oppføringen i ditt system.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_API_KEY='replace-with-your-api-key'
```

## Individkunder {#individual-customers}

En individkunde krever kun `type`. Inkluder profilfelter du allerede kjenner, og legg til flere kun når gjeldende capability eller oppgave trenger dem.

Opprett kunden med [`POST /v3/customers`](/api-reference/customers/post-v3-customers):

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-user-123" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "individual",
  "externalId": "user_123",
  "individual": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Lagre den returnerte `data.id` som `CUSTOMER_ID`. Se [Individonboarding](/no/knowledge-base/individual-onboarding/overview) for policykontekst.

## Virksomhetskunder {#business-customers}

En virksomhet krever `business.legalName`. Opprett virksomheten med samme operasjon:

```bash
curl --request POST \
  "${API_BASE}/v3/customers" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: customer-company-456" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "type": "business",
  "externalId": "company_456",
  "business": {
    "legalName": "Acme Payments SAS"
  }
}
JSON
```

Lagre den returnerte `data.id` som `CUSTOMER_ID`. Se [Virksomhetsonboarding](/no/knowledge-base/business-onboarding/overview) for policy- og dokumentkontekst.

## Legg til nærstående parter for virksomheten

Legg til styremedlemmer, eiere og andre deltakere i virksomheten når de er kjent eller etterspurt. Dette eksempelet oppretter et styremedlem med [`POST /v3/customers/{customerId}/related-parties`](/api-reference/customers/post-v3-customers-by-customer-id-related-parties):

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/related-parties" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}" \
  --header "Idempotency-Key: related-party-director-001" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "partyType": "person",
  "roles": ["director"],
  "title": "Chief executive officer",
  "person": {
    "firstName": "Amina",
    "lastName": "Diallo",
    "residenceCountry": "FR"
  }
}
JSON
```

Lagre den returnerte `data.id` som `RELATED_PARTY_ID`.

## Eksporter kundedata {#export-customer-data}

Bruk [`POST /v3/customers/{customerId}/export`](/api-reference/customers/post-v3-customers-by-customer-id-export) for å laste ned en kunde eller overlevere godkjent KYC til ditt eget Sumsub-prosjekt. Hver eksport krever en `Idempotency-Key`; gjenta samme nøkkel og body for å få samme resultat.

Velg formatet i request-body-en.

<Tabs>
  <Tab title="Grunnleggende profil-JSON">

Returnerer den offentlige v3-kunderessursen som et JSON-vedlegg med profil-, adresse-, skatte-, metadata- og nærstående-parter-data. Dokumenter og dokumentmetadata er ikke inkludert.

```json
{
  "format": "json_basic_data"
}
```

  </Tab>
  <Tab title="Sumsub share token">

Oppretter et engangs Sumsub share token for en godkjent individkunde slik at mottakende Sumsub-prosjekt kan importere KYC-dataene. Virksomhetskunder returnerer `422 invalid_field_for_type`.

```json
{
  "format": "sumsub_share_token",
  "forClientId": "partner-sumsub-client-id"
}
```

`forClientId` er din Sumsub-`clientId`, ikke Swipelux-`customerId`. Den identifiserer Sumsub-prosjektet som skal motta søkerdataene, så verdien velger du selv.

Responsen returnerer `provider`, `token` og `expiresAt` (Unix-sekunder):

```json
{
  "data": {
    "provider": "sumsub",
    "token": "_shr-...",
    "expiresAt": 1800000000
  }
}
```

Gi `token` videre til Sumsubs share-token-import-API for prosjektet identifisert av `forClientId` før `expiresAt`. Bruk det én gang. For å utstede på nytt, kall eksporten på nytt med en ny `Idempotency-Key`.

  </Tab>
</Tabs>

## Les klarhet fra capabilities

En kunde har ikke en verifiserings- eller klarhetsstatus i API-et. Les kunden med [`GET /v3/customers/{customerId}`](/api-reference/customers/get-v3-customers-by-customer-id) for gjeldende profildata, og bruk deretter capabilities og deres `openTaskIds` for å avgjøre hva kunden kan gjøre videre.

```bash
curl --request GET \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}" \
  --header "X-API-Key: ${SWIPELUX_API_KEY}"
```

Deretter, fortsett til [Capabilities og oppgaver](/no/integration/onboarding/capabilities-and-requirements) for å oppdage og aktivere produktutfallet du trenger.
