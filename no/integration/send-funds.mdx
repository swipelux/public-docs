---
title: "Send midler"
description: "Send en Swipelux-payout fra en kundelommebok til en egen bankkonto, en annen lommebok eller en tredjeparts mottakerdestinasjon i fiat eller stablecoin."
---

Hver payout starter fra en klar, finansiert utstedt lommebok. Destinasjonsmodellen avhenger av hvem som eier endepunktet.

```mermaid
flowchart TD
  A["Funded issued wallet"] --> B{"Who owns the endpoint?"}
  B -->|"Customer"| C["Customer account acc_..."]
  B -->|"Another person or business"| D["Recipient destination dst_..."]
  C --> E["Create quote"]
  D --> E
  E --> F["Execute and track transfer"]
```

## Før du starter

Hent kildelommeboken på nytt. Bekreft at gjeldende status tillater payout-en og at tilgjengelig saldo dekker det tiltenkte kildebeløpet. Lagre dens responsavledede ID som `SOURCE_WALLET_ID`.

Du trenger også en klar payout-capability for gjeldende kunde og valgt destinasjon.

Eksisterende Tron-lommebøker kan sende USDT til en annen Tron-lommebok med et `stablecoin_transfers`-tilbud. Inn og ut må bruke samme nettverk og stablecoin. Du kan ikke opprette nye utstedte lommebøker på Tron.

## 2. Opprett payout-tilbudet

Bruk [`POST /v3/quotes`](/api-reference/money-movement/post-v3-quotes) med disse headerne:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-quote-001
Content-Type: application/json
```

```json
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "in": {
    "amount": "150.00",
    "currency": "USDC",
    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${PAYOUT_DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }
}
```

Lagre `data.id` som `QUOTE_ID` og presenter den returnerte prisen og gebyrene.

### Velg en bankrute {#choose-a-bank-route}

For en payout fra krypto til fiat kan du angi den valgfrie `institutionId` for å kreve en godkjent bankrute for kunden. Utelat den for å bruke automatisk ruting.

```json
{
  "customerId": "${CUSTOMER_ID}",
  "capabilityId": "${CAPABILITY_ID}",
  "institutionId": "${INSTITUTION_ID}",
  "in": {
    "amount": "150.00",
    "currency": "USDC",
    "accountId": "${SOURCE_WALLET_ID}"
  },
  "destinationId": "${PAYOUT_DESTINATION_ID}",
  "out": {
    "currency": "USD"
  }
}
```

- En eksplisitt `institutionId` faller aldri tilbake til en annen bank. Når den valgte banken ikke har noen klar rute for denne kunden, capability-en og destinasjonen, returnerer `POST /v3/quotes` `422` [`bank_not_supported_for_customer`](/integration/errors#bank-not-supported-for-customer) med pekeren `/institutionId`.
- `institutionId` er bare gyldig på payout-tilbud fra krypto til fiat. Å sende den på et pay-in-, kort- eller stablecoin-overføringstilbud returnerer `400` [`validation_error`](/integration/errors#validation-error).
- Lesing av tilbud og overføringer gjengir `institutionId` for den valgte ruten, også en automatisk valgt rute, når banken kan identifiseres.

### SWIFT-payouts {#swift-payouts}

I produksjon krever USD SWIFT-payouts en klar SWIFT-capability som støtter payouts (`swift_pooled` eller `swift_named`), og de finansieres med USDC på Ethereum, Base eller Polygon, eller med USDT på Ethereum eller Polygon. Mottakerbeløpet etter gebyrer må være minst 100.00 USD.

En SWIFT-destinasjon trenger bankens gateadresse i `bankAddress`, `bankCity`, `bankState` og `bankPostalCode`. BIC-landet må samsvare med bankens land. Swipelux henter mottakerens adresse fra kunde- eller mottakerprofilen.

## 3. Utfør payout-en

Opprett overføringen med [`POST /v3/transfers`](/api-reference/money-movement/post-v3-transfers). Bruk én ny nøkkel for denne tiltenkte utførelsen:

```http
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: payout-transfer-001
Content-Type: application/json
```

```json
{
  "quoteId": "${QUOTE_ID}"
}
```

Lagre overføringens `data.id` som `TRANSFER_ID`. En vellykket opprettelse starter payout-en; den beviser ikke levering.

## 4. Følg opp levering

Les [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) etter opprettelse og etter hver hendelse. Bruk siste `data.state`, `data.stateDetail` og `data.openTaskIds` for å avgjøre om du skal vente, handle eller vise et terminalt utfall.

Deretter, gå gjennom [Tilbud og overføringer](/no/integration/quotes-and-transfers) for nøyaktige beløp, trygg utførelsesgjenoppretting og overføringsoppgaver.
