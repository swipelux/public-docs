title: "Errors और retries"
description: "प्रत्येक public Swipelux API problem code को संभालें, तय करें कि कब retry करना है, और validation, state, idempotency, और platform विफलताओं को हल करें।"
---

Swipelux API त्रुटियाँ `application/problem+json` media type का उपयोग करती हैं। अपने application के behavior को stable `code` value पर branch करें, फिर failure को हल करने के लिए नीचे दिए गए operation और मार्गदर्शन का उपयोग करें।

| Field | इसका उपयोग कैसे करें |
| --- | --- |
| `type` | Problem code के लिए stable documentation URI। |
| `title` | संक्षिप्त human-readable problem title। |
| `status` | इस response से संबद्ध HTTP status। |
| `code` | Application logic के लिए stable machine-readable value। |
| `detail` | इस occurrence के लिए contextual human-readable text। इसे parse या compare न करें। |
| `correlationId` | Logs में संग्रहीत करने और support से संपर्क करते समय शामिल करने के लिए request identifier। |
| `retryable` | जब `true` हो, तो वही request बाद में सफल हो सकता है। जब `false` हो, तो पुनः प्रयास करने से पहले request बदलें या एक prerequisite पूरी करें। |
| `errors[]` | Field-level validation विवरण, उपलब्ध होने पर JSON Pointer सहित। |

Idempotent writes को मूल `Idempotency-Key` और अपरिवर्तित method, path, और body के साथ retry करें। उस key का पुन: उपयोग किसी भिन्न इच्छित operation के लिए कभी न करें।

```json
{
  "type": "https://docs.swipelux.com/errors/validation-error",
  "title": "Validation Error",
  "status": 400,
  "code": "validation_error",
  "detail": "The request contains invalid fields.",
  "correlationId": "01JERRORVALIDATION",
  "retryable": false,
  "errors": [
    {
      "pointer": "/externalId",
      "code": "invalid_format",
      "message": "Use a valid external identifier."
    }
  ]
}
```
