---
title: "Fehler und Wiederholungen"
description: "Behandeln Sie jeden öffentlichen Swipelux-API-Problemcode, entscheiden Sie über Wiederholungen und beheben Sie Validierungs-, Zustands-, Idempotenz- und Plattformfehler."
---

Swipelux-API-Fehler verwenden den Medientyp `application/problem+json`. Verzweigen Sie Ihr Anwendungsverhalten anhand des stabilen `code`-Werts und nutzen Sie dann die Operation und die Hinweise unten, um den Fehler zu beheben.

| Feld | Verwendung |
| --- | --- |
| `type` | Stabile Dokumentations-URI für den Problemcode. |
| `title` | Kurzer menschenlesbarer Problemtitel. |
| `status` | Der dieser Antwort zugeordnete HTTP-Status. |
| `code` | Stabiler maschinenlesbarer Wert für die Anwendungslogik. |
| `detail` | Kontextbezogener menschenlesbarer Text für dieses Auftreten. Parsen oder vergleichen Sie ihn nicht. |
| `correlationId` | Anfrage-ID zum Speichern in Logs und zur Angabe bei Kontakt mit dem Support. |
| `retryable` | Bei `true` kann dieselbe Anfrage später erfolgreich sein. Bei `false` ändern Sie die Anfrage oder erfüllen Sie eine Voraussetzung, bevor Sie es erneut versuchen. |
| `errors[]` | Validierungsdetails auf Feldebene, einschließlich eines JSON Pointers, sofern verfügbar. |

Wiederholen Sie idempotente Schreibvorgänge mit dem ursprünglichen `Idempotency-Key` sowie unveränderter Methode, unverändertem Pfad und Body. Verwenden Sie diesen Schlüssel niemals für eine andere beabsichtigte Operation wieder.

```json
{
  "type": "https://docs.swipelux.com/errors/validation-error",
  "title": "Validation Error",
  "status": 400,
  "code": "validation_error",
  "detail": "The request contains invalid fields.",
  "correlationId": "01JERRORVALIDATION",
  "retryable": false,
  "errors": [
    {
      "pointer": "/externalId",
      "code": "invalid_format",
      "message": "Use a valid external identifier."
    }
  ]
}
```

### `forbidden`

**HTTP-Status:** `403`<br />
**Wiederholbar:** Nein<br />
**Problemtyp:** `https://docs.swipelux.com/errors/forbidden`

**Bedeutung:** Der API-Schlüssel ist gültig, darf diese Operation jedoch nicht ausführen.

**Wann er auftritt:** Dem Zugangsschlüssel fehlt eine erforderliche Berechtigung, oder ein Produktionsschlüssel ruft einen Nur-Sandbox-Endpunkt auf.

**Was zu tun ist:** Verwenden Sie einen Zugangsschlüssel für die richtige Umgebung mit den erforderlichen Berechtigungen. Legen Sie Schlüssel nicht in clientseitigem Code offen und ersetzen Sie sie dort nicht.

**Hinweise zur Wiederholung:** Wiederholen Sie die unveränderte Anfrage nicht. Wenden Sie die obige Maßnahme an, bevor Sie eine weitere Anfrage senden.

**Relevante API-Operationen:** Alle authentifizierten API-Operationen.

### `invalid_field_for_type`

**HTTP-Status:** `400`, `422`<br />
**Wiederholbar:** Wird nicht zurückgegeben<br />
**Problemtyp:** `https://docs.swipelux.com/errors/invalid-field-for-type`

**Bedeutung:** Die Anfrage enthält Felder, die für den ausgewählten Ressourcentyp nicht gültig sind.

**Wann er auftritt:** Eine diskriminierte Anfrage, etwa ein Privatkunden- gegenüber einem Geschäftskundenprofil, enthält Felder einer anderen Variante oder lässt Felder weg, die der ausgewählte Typ erfordert.

**Was zu tun ist:** Verwenden Sie das Schema des ausgewählten Typs, entfernen Sie Felder anderer Varianten, liefern Sie dessen Pflichtfelder und senden Sie eine korrigierte Anfrage.

**Hinweise zur Wiederholung:** Dieses Problem gibt `retryable` nicht zurück. Gehen Sie nicht davon aus, dass eine unveränderte Wiederholung sicher ist; folgen Sie der obigen Maßnahme und den Idempotenz-Anforderungen der Operation.

### `request_body_too_large`

**HTTP-Status:** `413`<br />
**Wiederholbar:** Nein<br />
**Problemtyp:** `https://docs.swipelux.com/errors/request-body-too-large`

**Bedeutung:** Der Request-Body überschreitet die von der Operation akzeptierte Größe.

**Wann er auftritt:** Eine Aufgabeneinreichung sendet mehr Anfragedaten, als die API in einem Body verarbeiten kann.

**Was zu tun ist:** Entfernen Sie unnötige Daten, verwenden Sie Dokumentreferenzen statt eingebetteter Dateiinhalte und senden Sie eine kleinere Einreichung, die weiterhin die aktuellen Anforderungen beantwortet.

**Hinweise zur Wiederholung:** Wiederholen Sie die unveränderte Anfrage nicht. Wenden Sie die obige Maßnahme an, bevor Sie eine weitere Anfrage senden.

**Relevante API-Operationen:**

- [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) (`createCustomerTaskSubmission`, status `413`)

### `unauthorized`

**HTTP-Status:** `401`<br />
**Wiederholbar:** Nein<br />
**Problemtyp:** `https://docs.swipelux.com/errors/unauthorized`

**Bedeutung:** Der Anfrage fehlt ein gültiger API-Schlüssel.

**Wann er auftritt:** Der `X-API-Key`-Header fehlt, ist ungültig, abgelaufen oder wird von der API nicht erkannt.

**Was zu tun ist:** Senden Sie den richtigen umgebungsspezifischen Schlüssel von einem geschützten Backend. Rotieren Sie den Schlüssel, falls er offengelegt worden sein könnte.

**Hinweise zur Wiederholung:** Wiederholen Sie die unveränderte Anfrage nicht. Wenden Sie die obige Maßnahme an, bevor Sie eine weitere Anfrage senden.
