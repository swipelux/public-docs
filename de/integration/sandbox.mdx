Die Sandbox verwendet denselben API-Host wie die Produktion. Ein Sandbox-API-Schlüssel wählt die Testumgebung aus, in der Hilfsfunktionen Ergebnisse simulieren, ohne echte Gelder zu bewegen.

Bewahren Sie den Schlüssel auf Ihrem Backend auf. Sandbox-Hilfsfunktionen ersetzen nicht die produktive Compliance oder das Onboarding.

Verwenden Sie [Fehler und Wiederholungen](/de/integration/errors), um zu testen, wie Ihre Integration Validierungs-, Zustands- und wiederholbare Plattformfehler behandelt, die von Sandbox-Operationen zurückgegeben werden.

```bash
export API_BASE='https://platform.swipelux.com'
export SWIPELUX_SANDBOX_API_KEY='replace-with-your-sandbox-key'
```

## Fähigkeitsbereitschaft testen

Setzen Sie nach der Anforderung einer Fähigkeit deren Sandbox-Status mit [`POST /v3/sandbox/customers/{customerId}/capabilities/{capabilityId}/status`](/api-reference/sandbox/post-v3-sandbox-customers-by-customer-id-capabilities-by-capability-id-status):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/customers/${CUSTOMER_ID}/capabilities/${CAPABILITY_ID}/status" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"status":"ready"}'
```

Rufen Sie die Fähigkeit nach dem Einsatz der Hilfsfunktion erneut ab. Behandeln Sie deren aktuellen `status` und `openTaskIds` als das Ergebnis, das Ihr Produkt verarbeiten muss.

## Eine offene Aufgabe testen

Erstellen Sie eine Sandbox-Aufgabe mit [`POST /v3/sandbox/tasks`](/api-reference/sandbox/post-v3-sandbox-tasks). Ordnen Sie sie der Ressource zu, deren Workflow Sie testen, und beschreiben Sie mit `items`, was der Kunde einreichen muss. Dieser Leitfaden zeigt Capability- und Transfer-Workflows; die API-Referenz definiert den Kunden-Scope und das vollständige Request-Schema.

Verwenden Sie ein `explanation`-Element für eine Textantwort und ein `document`-Element für einen Upload. Neue `profile`-Elemente erfordern außerdem `profilePointer`, einen JSON Pointer auf das Kundenfeld. Weitere Elementtypen und Felder finden Sie unter [Sandbox-Aufgabe erstellen](/api-reference/sandbox/post-v3-sandbox-tasks).

Erstellen Sie für das Transfer-Beispiel zunächst einen Sandbox-Transfer über einen [Pay-in](/de/integration/receive-funds)- oder [Payout](/de/integration/send-funds)-Ablauf und exportieren Sie anschließend die zurückgegebene `data.id`:

```bash
export TRANSFER_ID='tr_replace_with_your_transfer_id'
```

<Tabs>
  <Tab title="Fähigkeit + Erklärung">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "capability",
    "customerId": "${CUSTOMER_ID}",
    "capabilityId": "${CAPABILITY_ID}"
  },
  "items": [
    {
      "type": "explanation",
      "request": "Explain the source of funds."
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="Transfer-RFI + Dokument">

Ordnen Sie die Aufgabe dem zu prüfenden Transfer zu und fordern Sie ein Dokument mit `constraints` an, die die akzeptierten Typen, Formate und das Alter einschränken.

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "scope": {
    "type": "transfer",
    "customerId": "${CUSTOMER_ID}",
    "transferId": "${TRANSFER_ID}"
  },
  "category": "transaction_rfi",
  "items": [
    {
      "type": "document",
      "request": "Upload a bank statement showing the source of funds for this transfer.",
      "constraints": {
        "acceptedDocumentTypes": ["bank_statement"],
        "acceptedFormats": ["pdf", "jpeg"],
        "maxAgeDays": 90
      }
    }
  ]
}
JSON
```

Das Beispiel begrenzt den akzeptierten Dokumenttyp, das Format und das Alter. Alle unterstützten Dokumenteinschränkungen finden Sie unter [Sandbox-Aufgabe erstellen](/api-reference/sandbox/post-v3-sandbox-tasks).

  </Tab>
</Tabs>

Speichern Sie `data.id` als `TASK_ID`, `data.revision` als `TASK_REVISION` und die aktuelle `data.requirements[0].id` als `REQUIREMENT_ID`. Stimmen Sie beim Aufruf von [`POST /v3/customers/{customerId}/tasks/{taskId}/submissions`](/api-reference/task-submissions/create-customer-task-submission) die Antwort auf das erstellte Element ab:

<Tabs>
  <Tab title="Erklärungsantwort">

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "text",
        "value": "Sandbox requirement completed."
      }
    }
  ]
}
JSON
```

  </Tab>
  <Tab title="Dokumentantwort">

Laden Sie mit [`POST /v3/customers/{customerId}/documents`](/api-reference/documents/post-v3-customers-by-customer-id-documents) eine passende Datei hoch, speichern Sie die zurückgegebene `data.id` als `DOCUMENT_ID` und senden Sie sie als Dokumentantwort:

```bash
curl --request POST \
  "${API_BASE}/v3/customers/${CUSTOMER_ID}/tasks/${TASK_ID}/submissions" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Idempotency-Key: sandbox-task-document-submission-001" \
  --header "Content-Type: application/json" \
  --data @- <<JSON
{
  "taskRevision": ${TASK_REVISION},
  "answers": [
    {
      "requirementId": "${REQUIREMENT_ID}",
      "answer": {
        "type": "document",
        "documentIds": ["${DOCUMENT_ID}"]
      }
    }
  ]
}
JSON
```

  </Tab>
</Tabs>

Akzeptieren oder lehnen Sie die aktuelle Einreichung dann mit [`POST /v3/sandbox/tasks/{taskId}/review`](/api-reference/sandbox/post-v3-sandbox-tasks-by-task-id-review) ab:

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/tasks/${TASK_ID}/review" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"outcome":"accepted"}'
```

Verwenden Sie [Fähigkeiten und Aufgaben](/de/integration/onboarding/capabilities-and-requirements) für das produktive Muster zur Aufgabenerfüllung.

## Eine Sandbox-Wallet finanzieren

Belasten Sie eine ausgegebene Wallet mit [`POST /v3/sandbox/accounts/{accountId}/topup`](/api-reference/sandbox/post-v3-sandbox-accounts-by-account-id-topup):

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/accounts/${ACCOUNT_ID}/topup" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"amount":"250.00","currency":"USDC"}'
```

Speichern Sie das zurückgegebene `data.id` als `TRANSFER_ID`, wenn Sie den simulierten Finanzierungstransfer prüfen möchten.

Die Topup-ID ist eine Transfer-ID. Rufen Sie sie über [`GET /v3/transfers/{transferId}`](/api-reference/money-movement/get-v3-transfers-by-transfer-id) ab oder listen Sie sie über [`GET /v3/transfers`](/api-reference/money-movement/get-v3-transfers) auf, um Ihren Code-Pfad für eingehende Einzahlungen gegen Sandbox-Topups zu testen. Die Transferprojektion ist eine abgeschlossene eingehende Stablecoin-Einzahlung mit `origin: "inbound_deposit"`, `method: "stablecoin_transfers"` und `direction: "stablecoin_move"` und wird von den passenden Listenfiltern `accountId`, `origin`, `method` und `direction` zurückgegeben.

## Einen Transfer abschließen oder fehlschlagen lassen

Setzen Sie das Ergebnis mit [`POST /v3/sandbox/transfers/{transferId}/state`](/api-reference/sandbox/post-v3-sandbox-transfers-by-transfer-id-state):

<Tabs>
  <Tab title="Abschließen">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data '{"state":"completed"}'
```

  </Tab>
  <Tab title="Fehlschlagen">

```bash
curl --request POST \
  "${API_BASE}/v3/sandbox/transfers/${TRANSFER_ID}/state" \
  --header "X-API-Key: ${SWIPELUX_SANDBOX_API_KEY}" \
  --header "Content-Type: application/json" \
  --data @- <<'JSON'
{
  "state": "failed",
  "stateDetail": {
    "code": "sandbox_review",
    "message": "Sandbox transfer failed."
  }
}
JSON
```

  </Tab>
</Tabs>

Führen Sie als Nächstes einen [Pay-in](/de/integration/receive-funds)-, [Payout](/de/integration/send-funds)- oder [Ausgegebenes-Bankkonto](/de/integration/issue-bank-account)-Flow in der Sandbox aus.
