---
title: "Empfänger und Ziele"
description: "Erstellen Sie einen Drittparteien-Empfänger bei Swipelux samt Bankkonto- oder Krypto-Wallet-Ziel für Payouts und nutzen Sie beide für spätere Transfers."
---

Verwenden Sie ein Kundenkonto, wenn dem Kunden der Endpunkt gehört. Verwenden Sie einen Empfänger und ein Ziel, wenn eine andere Person oder ein anderes Unternehmen die Gelder empfängt.

Der Empfänger dokumentiert, wer Gelder empfängt. Das Ziel dokumentiert, wo sie sie empfangen.

## 1. Empfänger anlegen

Legen Sie eine Einzelperson oder ein Unternehmen mit [`POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients) an. Senden Sie diese Header:

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-create-001
Content-Type: application/json
```

```json Request body
{
  "type": "individual",
  "relationship": "contractor",
  "firstName": "Jason",
  "lastName": "Swipelux",
  "email": "jason@swipelux.com",
  "phone": "+14155551234",
  "address": {
    "streetLine1": "1 Market Street",
    "city": "San Francisco",
    "state": "CA",
    "postalCode": "94105",
    "country": "US"
  },
  "label": "Jason contractor"
}
```

`relationship` beschreibt die Beziehung des Empfängers zu Ihrem Kunden. Wählen Sie einen Wert aus dem [Request-Schema für `POST /v3/customers/{customerId}/recipients`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients). Senden Sie bei `other` kein zusätzliches Freitextfeld; das Schema lehnt unbekannte Felder ab.

Fügen Sie die Adresse hinzu, bevor Sie ein Fiat-Ziel anlegen. Speichern Sie die zurückgegebene Empfänger-`data.id` als `RECIPIENT_ID` und behalten Sie ihren aktuellen Status.

## 2. Ein Ziel hinzufügen

Legen Sie den Endpunkt mit [`POST /v3/customers/{customerId}/recipients/{recipientId}/destinations`](/api-reference/recipients/post-v3-customers-by-customer-id-recipients-by-recipient-id-destinations) an. Verwenden Sie einen neuen Schlüssel für dieses beabsichtigte Ziel:

```http Request headers
X-API-Key: ${SWIPELUX_API_KEY}
Idempotency-Key: recipient-destination-create-001
Content-Type: application/json
```

Pix- und Pix Safe-Ziele empfangen BRL und benötigen die bereite Pix-Fähigkeit des Kunden (`pix_pooled`). Ein Pix-Ziel zahlt an einen Pix-Schlüssel: eine CPF oder CNPJ nur aus Ziffern, eine Telefonnummer als `+55` gefolgt von 10 oder 11 Ziffern, eine E-Mail-Adresse oder einen zufälligen Schlüssel. Ein Pix Safe-Ziel zahlt an ein brasilianisches Bankkonto, das über die CPF oder CNPJ des Inhabers in `taxId`, den 8-stelligen ISPB-Code der Bank in `bankCode`, die Filiale und die Kontonummer mit ihrer Prüfziffer identifiziert wird. Antworten und Webhooks geben `taxId` bis auf die letzten vier Ziffern maskiert zurück.

Swipelux validiert Bankkennungen wie IBANs, BICs, ABA-Routing-Nummern sowie CPF- oder CNPJ-Nummern einschließlich Prüfsummen, wenn Sie ein Bankziel anlegen. Fehlerhafte Werte geben `400 validation_error` zurück. Diese Prüfungen bestätigen nur das Format, nicht, dass das Konto existiert oder wem es gehört.

Verwenden Sie `self_custodied` nur, wenn der Empfänger die Wallet kontrolliert. Folgen Sie der aktuellen API-Referenz-Variante, wenn die Wallet von einem anderen Verwahrer gehalten wird.

Speichern Sie die zurückgegebene Ziel-`data.id` als `DESTINATION_ID` und behalten Sie ihren aktuellen Status.

## 3. Auf Zielbereitschaft warten

Lesen Sie [`GET /v3/customers/{customerId}/recipients/{recipientId}/destinations/{destinationId}`](/api-reference/recipients/get-v3-customers-by-customer-id-recipients-by-recipient-id-destinations-by-destination-id), bevor Sie ein Quote erstellen.

Fahren Sie nur fort, wenn der aktuelle Zielstatus den Payout erlaubt und seine Währung, Methode und Netzwerk mit der beabsichtigten Bewegung übereinstimmen. Empfänger- und Zielstatus sind unabhängig voneinander.

Verwenden Sie die `dst_`-Ziel-ID im Payout-Quote. Die `rcp_`-Empfänger-ID identifiziert den Eigentümer-Datensatz und ist keine Quote-Ziel.

Nehmen Sie als Nächstes das bereite Ziel zu [Gelder senden](/de/integration/send-funds).
